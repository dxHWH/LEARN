## 面试官提问

> `new int()` 和 `new int` 的区别？

## 我的回答（原文）

> 对于基本类型 int、char、double 等，new X 代表对着这些基本类型执行默认构造初始化，这意味 new it 没有指定初始化值，此时 int* p = new int 是一个未确定值，其内存中存放的可能是随机的垃圾值。而对于 new X()，则意味初始化为 0，本质是传入初始化值但是类似“缺省”了，等价于 new X{}。而对于复杂的类型，则主要看默认构造函数（无参构造）的实现，在大多数情况下 new Complexclass 和 new Complexclass() 逻辑等价，只有语义上的区别，前者是“通过默认构造函数初始化”，后者时“调用无参构造函数初始化”。

## 1. 答案点评

### 1.1 总体评价

**评分：约 55 / 100**。

`int` 这部分基本答对了：`new int` 的值不确定，`new int()` 是 0，和 `new int{}` 一样。  
但这道题真正考的是**类类型**，你的结论「大多数情况下 `new C` 和 `new C()` 逻辑等价，只有语义区别」**恰好答反了**。对于**没有用户提供的默认构造函数**的类（POD 结构体、聚合体、`= default` 的类、只有隐式构造函数的类，游戏代码里大量都是这种），两者的结果**不一样**：`new C()` 会先把整个对象**清零**，`new C` 不会。这是这道题的核心考点。

另外，回答里没有出现标准术语：**默认初始化（default-initialization）、值初始化（value-initialization）、零初始化（zero-initialization）**。面试官很可能就是想听这三个词。

## 2. 推荐的满分版口述答案（约 2 分钟）

> 这两种写法对应 C++ 里两种不同的初始化方式：`new T` 是**默认初始化**，`new T()` 是**值初始化**。
>
> **对 `int` 这种标量**：默认初始化就是**什么都不做**，所以 `new int` 的值是**不确定的**，读取它是未定义行为；值初始化等于**零初始化**，所以 `new int()` 是 0。`new int{}` 也是值初始化，结果同样是 0。数组也一样：`new int[n]` 不初始化，`new int[n]()` 全部为 0。
>
> **对类类型**，关键看默认构造函数是不是**用户提供的**：
>
> - 如果是用户自己写了函数体的构造函数，两种写法**完全一样**，都只调用这个构造函数，构造函数没初始化的成员仍然是垃圾值；
> - 如果**没有用户提供的默认构造函数**，比如 POD 结构体、只有隐式构造函数的类、在类内写了 `= default` 的类，那么 `new T()` 会**先把整个对象零初始化**，再调用（非平凡的）构造函数；而 `new T` 只调用构造函数，**内置类型的成员不会被清零**。
>
> 有一个坑：`= default` 写在类里不算用户提供，写在类外（`T::T() = default;`）就算用户提供，后者 `new T()` 就**不会清零**了。
>
> 实际开发中有两个影响：一是**正确性**，Debug 堆会把未初始化的内存填成 `0xCD`，Release 下是上次留下的旧数据，很容易出现只在 Release 下偶现的 bug；帧同步游戏里，一个没初始化的字段就可能让各个客户端不同步，所以我习惯给成员**都写默认成员初始化器**，比如 `int hp = 0;`。二是**性能**，清零是有代价的，大块的缓冲区如果马上要整体覆盖，可以故意不初始化，C++20 的 `make_unique_for_overwrite` 就是为这个加的；UE 的 `FVector` 默认构造函数也故意不初始化，需要零向量时要写 `FVector::ZeroVector` 或 `FVector(ForceInit)`。

## 3. 先把三个术语搞清楚

| 术语                                | 触发写法                                              | 做什么                                               |
| --------------------------------- | ------------------------------------------------- | ------------------------------------------------- |
| **默认初始化**（default-initialization） | `new T`、`T t;`（局部变量）                              | 类类型：调用默认构造函数  
数组：每个元素默认初始化  
**标量：什么都不做 → 不确定值** |
| **值初始化**（value-initialization）    | `new T()`、`new T{}`、`T()`、`T{}`、`T t{};`          | 见下面的规则                                            |
| **零初始化**（zero-initialization）     | 值初始化的一部分；**静态存储期变量**（全局、`static`）在其他初始化之前一定会先零初始化 | 把对象的每个标量成员设为 0，**包括填充字节（padding）**                |

**值初始化的完整规则**（C++20 [dcl.init]）：

```text
T 是类类型：
  ├─ 没有默认构造函数，或默认构造函数是「用户提供的」或「已删除的」
  │     → 只做默认初始化（调用构造函数，不清零）
  └─ 默认构造函数不是用户提供的（隐式生成 / 首次声明处 = default）
        → 先零初始化整个对象；
          如果构造函数是非平凡的，再调用它
T 是数组 → 每个元素做值初始化
其他（标量）→ 零初始化
```

> **一句话**：`()` 不是「传入一个缺省值」，而是「如果你没有自己接管构造函数，我就先帮你清零」。

### 「用户提供的」到底指什么

| 写法                       | 是否用户提供 | `new T()` 会清零吗 |
| ------------------------ | ------ | -------------- |
| 什么都不写（隐式生成）              | 否      | ✅ 清零           |
| 类内 `T() = default;`      | 否      | ✅ 清零           |
| 类外 `T::T() = default;`   | **是**  | ❌ 不清零          |
| `T() {}`、`T() : a(1) {}` | 是      | ❌ 不清零          |
| `T() = delete;`          | （已删除）  | 编译失败           |

## 4. 实测：把内存刷成 `0xAB`，看哪些字节被初始化过

```cpp
struct Pod          { int a; int b; };                         // 没有构造函数
struct UserCtor     { int a; int b; UserCtor() : a(1) {} };   // 用户提供，只初始化了 a
struct DefaultedIn  { int a; int b; DefaultedIn() = default; };
struct DefaultedOut { int a; int b; DefaultedOut(); };
DefaultedOut::DefaultedOut() = default;                        // 类外 = default
struct WithString   { int a; int b; std::string s; };         // 隐式构造函数，非平凡
struct WithNsdmi    { int a = 5; int b; };                     // 默认成员初始化器
struct Vec3         { float x, y, z; Vec3() {} };             // 模仿 UE 的 FVector
struct Base { int hp; };  struct Derived : Base { int mp; Derived() {} };
```

Release 实测（Debug 下第 1、2 节结果完全相同）：

```text
==== 1. 标量 ====
  new int                     [0]=未初始化
  new int ()                  [0]=0x00000000
  new int {}                  [0]=0x00000000
  new double                  [0]=未初始化  [1]=未初始化
  new double ()               [0]=0x00000000  [1]=0x00000000

==== 2. 类类型：关键看默认构造函数是不是“用户提供的” ====
  new Pod                     [0]=未初始化  [1]=未初始化
  new Pod ()                  [0]=0x00000000  [1]=0x00000000      ← 区别在这里
  new Pod {}                  [0]=0x00000000  [1]=0x00000000
  new UserCtor                [0]=0x00000001  [1]=未初始化
  new UserCtor ()             [0]=0x00000001  [1]=未初始化         ← 用户提供：() 也不清零
  new DefaultedIn             [0]=未初始化  [1]=未初始化
  new DefaultedIn ()          [0]=0x00000000  [1]=0x00000000      ← 类内 = default：清零
  new DefaultedOut            [0]=未初始化  [1]=未初始化
  new DefaultedOut ()         [0]=未初始化  [1]=未初始化           ← 类外 = default：不清零！
  new WithString              [0]=未初始化  [1]=未初始化
  new WithString ()           [0]=0x00000000  [1]=0x00000000      ← 先清零，再调用隐式构造函数构造 string
  new WithNsdmi               [0]=0x00000005  [1]=未初始化
  new WithNsdmi ()            [0]=0x00000005  [1]=0x00000000      ← b 被清零，a 再被赋值为 5
  new Vec3                    [0]=未初始化  [1]=未初始化  [2]=未初始化
  new Vec3 ()                 [0]=未初始化  [1]=未初始化  [2]=未初始化
  new Vec3 {}                 [0]=未初始化  [1]=未初始化  [2]=未初始化   ← 空构造函数体，{} 也救不了
  new Derived                 [0]=未初始化  [1]=未初始化
  new Derived ()              [0]=未初始化  [1]=未初始化           ← 派生类有用户构造函数，基类成员也不清零
```

逐个看最容易出错的几行：

1. **`Pod`**：最常见的情况。游戏里的数据结构、网络包、配置项大多长这样，`new Pod` 和 `new Pod()` 结果不同。
2. **`WithString`**：有隐式构造函数，而且是**非平凡**的（要构造 `std::string`），但构造函数**不会**管 `int` 成员。`()` 先清零，再调用构造函数。所以「有构造函数 = 两者等价」也是错的，要看是不是**用户提供的**。
3. **`WithNsdmi`**：`int a = 5;` 让构造函数变成非平凡的，但它不是用户提供的，所以 `()` 仍会先清零 `b`。
4. **`Vec3` / `Derived`**：哪怕构造函数是空的 `{}`，只要是用户写的，`()` 和 `{}` 都不清零，连基类的成员也不管。

## 5. 「垃圾值」到底是什么：Debug 和 Release 不一样

Demo 第 3 节：先 `new int[4]` 写入 `0x11111111 ~ 0x44444444`，`delete[]` 之后再 `new int[4]`：

```text
Release： new int[4]    地址复用： 0x11111111 0x22222222 0x33333333 0x44444444   ← 上一个对象留下的旧数据
Debug  ： new int[4]    地址未复用： 0xCDCDCDCD 0xCDCDCDCD 0xCDCDCDCD 0xCDCDCDCD ← 调试 CRT 的填充值
两者都是：new int[4]()  ： 0x00000000 ×4
          new int[4]{9} ： 0x00000009 0x00000000 0x00000000 0x00000000   ← 剩余元素做值初始化
```

这就&#x662F;**「Debug 下稳定，Release 下偶现」**&#x7684;根源：

- **Debug**：未初始化的值总是 `0xCDCDCDCD`。如果当成指针，一访问就崩，地址很好认；当成 `int` 是一个很大的负数（-842150451），当成 `float` 约等于 -4.3 亿，bug 稳定复现。
- **Release**：值是**上一个对象留下的旧数据**，很多时候「刚好是合理的值」，bug 偶尔出现，而且和之前的操作有关，极难复现。

MSVC 调试 CRT 的填充值，排查问题时一眼就能认出来：

| 值      | 含义                       |
| ------ | ------------------------ |
| `0xCD` | 已在堆上分配、还没初始化（Clean）      |
| `0xDD` | 已释放的堆内存（Dead）            |
| `0xFD` | 堆块前后的保护字节（No man's land） |
| `0xCC` | 未初始化的栈内存（`/RTC` 开启时）     |

**更严重的问题：读取不确定值是未定义行为**。编译器可以假设它不会发生，并据此优化。例如 `bool alive;` 未初始化时，`if (alive)` 和 `if (!alive)` 有可能**同时为真**，因为 `bool` 的那个字节可能是 0 和 1 以外的值。

> C++26 把**局部自动变量**的未初始化读取改成了「错误行为（erroneous behavior）」，不再是 UB，但**堆上 `new` 出来的对象不在此列**，仍然是不确定值。

## 6. `()` 和 `{}` 的区别

对标量和大部分类来说，`new T()` 和 `new T{}` 结果一样，但 `{}`（列表初始化）有自己的规则：

| 方面                      | `new T(...)`                 | `new T{...}`    | 实测                                                                                                                               |
| ----------------------- | ---------------------------- | --------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| 窄化转换                    | 允许（有警告）                      | **禁止**          | `new int(3.5)` 只报警告 C4244；`new int{3.5}` 报 **C2397 需要收缩转换**                                                                      |
| `initializer_list` 构造函数 | 不优先                          | **优先**          | `new vector<int>(3)` 是 3 个 0；`new vector<int>{3}` 是一个元素 3                                                                        |
| 聚合体                     | 空括号做值初始化；C++20 起也能 `T(1, 2)` | 聚合初始化           | `new Pod{1}` → `a=1, b=0`                                                                                                        |
| 删除了默认构造函数的「聚合体」         | 编译失败                         | **C++17 能编译通过** | `struct NoDefault { NoDefault() = delete; int a; };`：C++17 下 `new NoDefault{}` 编译通过（被当成聚合体，绕过了 `= delete`）；C++20 修复了，报 **C2280** |

### 局部变量的 most vexing parse

`new T()` 不会有歧义，但局部变量写成 `T t();` 是**声明了一个返回 `T` 的函数**，不是值初始化：

```cpp
Pod p();     // 函数声明！
p.a = 1;     // C2228: “.a”的左边必须有类/结构/联合
Pod q{};     // ✅ 值初始化，全部为 0
Pod r = Pod();  // ✅ 也可以
```

### `const` 对象必须初始化

```cpp
new const int;   // C2737: 必须初始化 const 对象（默认初始化什么都不做）
new const Pod;   // C2737：Pod 没有用户提供的构造函数，同样不行
new const int(); // ✅
```

## 7. 性能：清零是有代价的

Demo 第 4 节，256 MB 的 `char` 数组（Release）：

```text
  new char[256MB]            :    0.010 ms   首字节=0x00（新页由系统清零，“看起来是 0”不代表初始化了）
  new char[256MB]()          :   18.529 ms
  new char[N]   + 覆盖写一遍 :   22.974 ms
  new char[N]() + 覆盖写一遍 :   26.400 ms
  make_unique<char[]>(N)     :   17.707 ms
  make_unique_for_overwrite  :    0.011 ms
  std::vector<char>(N)       :   17.807 ms
```

怎么理解这组数字：

1. **`new char[N]` 只要 0.01 ms**：大块内存是直接向系统申请的，物理页要等**第一次访问时**才真正分配（缺页中断）。系统给的新页一定是全 0，所以首字节读出来是 `0x00`，**但这是操作系统的行为，不是 C++ 保证的初始化**，换成复用的小块内存就是旧数据（第 5 节）。
2. **`()` 的 18.5 ms**：主要花在 `memset` 触碰每一页引发的缺页中断上。
3. **如果之后马上要整体覆盖写**：不清零 22.97 ms，先清零再写 26.40 ms，**多写了一遍，额外花了约 3.4 ms**（这时页已经提交，纯粹是多一次内存带宽）。
4. **标准库容器默认都是值初始化**：`vector<char>(N)`、`resize(N)`、`make_unique<T[]>(N)` 都会清零。C++20 的 `make_unique_for_overwrite`（以及 `make_shared_for_overwrite`）专门用来**跳过清零**。
5. **Debug 版本**下 `new char[N]` 也要 23.8 ms，因为调试 CRT 会把整块填成 `0xCD`，所以 Debug 下测的性能没有参考价值。

游戏中的典型取舍：

- **要清零**：逻辑对象、网络包、存档结构，正确性优先；
- **可以不清零**：顶点/索引缓冲、纹理上传用的 staging buffer、音频解码缓冲、每帧重写的临时数组等，**马上会被整体覆盖**的大块内存，用默认初始化或 `make_unique_for_overwrite`，避免每帧白白多写一遍。

## 8. 游戏客户端中的实际影响

### 8.1 UE 的 `FVector` 默认不初始化

UE 的数学类型（`FVector`、`FRotator`、`FQuat`、`FMatrix`）的默认构造函数是**用户提供的空函数**，为了性能**故意不初始化**，行为就像 Demo 里的 `Vec3`：

```cpp
FVector A;            // 垃圾值
FVector B = FVector();// 仍然是垃圾值！用户提供的构造函数，() 不清零
FVector C = FVector::ZeroVector;     // ✅
FVector D(ForceInit);                // ✅ EForceInit 版本的构造函数会清零
FVector E(0.f);                      // ✅
```

很多从 Unity 或其他引擎转过来的同学会以为 `FVector()` 就是零向量，这是很常见的 bug 来源。

> 对比：`UObject` 由 `NewObject` 创建时，引擎会**先把整块内存清零**再调用构造函数，所以 `UObject` 的成员即使没写初始化器，通常也是 0。但 `USTRUCT` 和普通 C++ 结构体没有这个保证。

### 8.2 帧同步：一个未初始化的字段就能导致不同步

MOBA 类游戏常用**帧同步（lockstep）**：所有客户端用相同的输入跑相同的逻辑，依赖每一步结果都完全一致。如果某个逻辑结构里有一个字段没初始化：

- 不同客户端的内存布局、之前的分配历史都不同，**读到的旧数据也不同**；
- 逻辑结果开始出现差异，经过若干帧放大之后，**状态哈希校验不一致**，判定为不同步；
- 而且 Debug 下（全是 `0xCD`）各端碰巧一致，**只在 Release 下出现**。

还有一个更隐蔽的问题：**结构体的填充字节**。如果对整个结构体 `memcmp`、算哈希，或者直接按字节序列化，填充字节没初始化也会导致结果不一致。值初始化（`T{}`、`T()`，在没有用户提供构造函数时）会把**填充字节也清零**，但逐个成员赋值不会。

### 8.3 团队规范建议

1. **所有成员都写默认成员初始化器**：`int hp = 0; float speed = 0.f; Actor* target = nullptr;`，这是最简单可靠的办法，不依赖调用方写不写 `()`；
2. 局部变量和临时对象习惯写 `T t{};`；
3. 如果为了性能故意不初始化，要在注释里写明，并提供显式初始化的方法（参考 UE 的 `ForceInit`）；
4. 用工具兜底：

| 工具                                                                          | 能发现什么                        |
| --------------------------------------------------------------------------- | ---------------------------- |
| MSVC `/W4`（C4700）、`/analyze`（C6001）                                         | 局部变量使用前未初始化                  |
| MSVC Debug `/RTCu`                                                          | 运行时检查局部变量使用前未初始化             |
| Clang `-Wuninitialized`、clang-tidy `cppcoreguidelines-pro-type-member-init` | 成员没有初始化                      |
| MemorySanitizer（Clang，Linux）、Valgrind Memcheck                              | 运行时读取未初始化内存。**ASan 查不出这类问题** |
| `-ftrivial-auto-var-init=pattern/zero`（Clang/GCC）                           | 自动把局部变量填成固定值，让 bug 稳定复现或消失   |

## 9. 面试官可能的追问

**Q1：全局变量 `int g;` 和堆上的 `new int` 有什么不同？**  
全局变量、`static` 变量是**静态存储期**，程序启动时一定会先零初始化，所以 `g` 是 0。堆上和栈上的对象没有这个保证。

**Q2：`std::vector<int> v(100);` 里面是什么值？**  
全是 0。`vector` 的大小构造函数和 `resize` 都做值初始化。`reserve(100)` 不创建元素，只分配容量。想要不清零的「大小」，C++ 标准容器做不到，需要自定义分配器，或者用 `make_unique_for_overwrite<int[]>(100)`。

**Q3：`new T()` 和 `new T` 对有虚函数的类有区别吗？**  
虚函数让构造函数变成非平凡的（要设置虚表指针），但只要构造函数不是用户提供的，`new T()` 仍然会先清零普通成员，再调用构造函数设置虚表指针；`new T` 只设置虚表指针。

**Q4：`T() = default;` 写在类里和类外有什么区别？**  
写在类里，构造函数不是用户提供的，可能是平凡的，`T()` 会清零，类型也可能是聚合体（C++20 之前）。写在类外，它是用户提供的，`T()` 不清零，类型也不是平凡可默认构造的。第 4 节 Demo 有实测。

**Q5：为什么 C++ 不默认把所有东西都清零？**  
零开销原则：不需要的东西不付出代价。大数组、马上要覆盖的缓冲区，清零是纯浪费（第 7 节实测，256 MB 清零约 18 ms，相当于 60 帧游戏一整帧的时间）。所以 C++ 把选择权交给程序员，代价是要自己保证不读未初始化的数据。

**Q6：`new int` 读出来是 0，是不是就说明初始化了？**  
不是。大块内存可能来自系统新分配的页（总是全 0）（第 7 节首字节 `0x00`），小块内存可能恰好复用了一块原来是 0 的内存。这是巧合，标准不保证，换个场景就是旧数据（第 5 节 Release 输出）。

## 10. 速记卡

```text
new T    → 默认初始化：标量什么都不做（不确定值，读取是 UB）；类调用默认构造函数
new T()  → 值初始化：标量清零；类看默认构造函数是不是「用户提供的」
new T{}  → 一般同 ()；但禁止窄化、优先 initializer_list、聚合体走聚合初始化

类类型的值初始化：
  用户提供的构造函数（含 T(){}、类外 =default）→ 只调用它，不清零
  非用户提供（隐式 / 类内 =default）       → 先整体清零（含 padding），再调用非平凡构造函数
「两者等价」只在默认构造函数是用户提供的时候成立

数组：new int[n] 不初始化；new int[n]() 全 0；new int[n]{9} 剩余补 0
const：new const int 编译失败；局部变量 T t(); 是函数声明 → 写 T t{};
MSVC Debug：0xCD 未初始化堆，0xDD 已释放，0xFD 保护字节，0xCC 未初始化栈
性能：清零有代价（256MB 约 18ms）；马上整体覆盖的缓冲区用 make_unique_for_overwrite
游戏：UE FVector() 不清零 → 用 ZeroVector / ForceInit；帧同步中未初始化字段 → 不同步
规范：成员一律写默认成员初始化器 int hp = 0;
```
