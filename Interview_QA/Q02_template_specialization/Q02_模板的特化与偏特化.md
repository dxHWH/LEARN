## 面试官提问

> 介绍一下模板的特化和偏特化。

## 我的回答（原文）

> 模板的特化有全特化和偏特化。全特化是指针对某一类型，并不适配当前模板函数或者或模板类中逻辑，或者程序员想要实现针对某一类型的参数特殊化的逻辑，就可使用全特化，全特化中，必须先写 `template<>`，并显示声明模板特化匹配的类型，这表示模板参数已经全部固定，没有剩余参数，例如：
>
> ```cpp
> template<>
> class Printer<bool>
> {
> public:
>     void Print(bool value)
>     {
>         std::cout << (value ? "true" : "false");
>     }
> };
> ```
>
> 而偏特化，则是针对一类具有统一性质的类型，例如所有指针类型，实现另一套实现。则可以在类模板使用偏特化，例如：
>
> ```cpp
> template<typename T>
> class Traits<T*>
> {
> };
> ```
>
> 针对所有的指针类型 T* 都实例化上诉模板。  
> 另外，模板函数不能偏特化，与之对应的是模板函数的重载可以实现类似的效果。在隐式的模板参数推到中，虽然 T 和 T* 都能正常匹配，但编译器会优先使用匹配更特殊的模板。

| 1 | **没讲函数模板全特化不参与重载决议** | 🔴 重要遗漏 | 这是这道题最大的区分点。函数模板的全特化不是一个新的重载，编译器先在**主模板**之间做重载决议，选中之后才看它有没有对应的全特化。结果是**声明顺序会改变调用结果**（见第 5.2 节，Demo 实测）。这也是《C++ Coding Standards》第 66 条、Herb Sutter《Why Not Specialize Function Templates?》建议**不要特化函数模板**的原因 |
| 2 | **偏特化的例子少了主模板声明**    | 🔴 代码错误 | `template<typename T> class Traits<T*> {};` 单独写**编译不过**，前面必须先有 `template<typename T> class Traits;`（主模板至少要声明）。Demo `cf4_no_primary.cpp` 实测报 `C3856: “Traits”: 符号不是 模板 类`                                    |

| 4 | **偏特化的理解太窄**         | 🟠 遗漏   | 偏特化不只是“一类具有统一性质的类型”，它有两个维度：① **固定一部分参数**，例如 `Pair<K, int>`；② **限制参数的形状**，例如 `T*`、`const T`、`T&`、`T[N]`、`std::vector<T>`、`R(*)(Args...)`、`T C::*`。偏特化的参数个数还可以和主模板**不一样**（`T[N]` 有两个参数，`R(Args...)` 是可变参数）    |

| 6 | **没有讲用途**            | 🟠 遗漏   | 特化真正的价值在于：**type_traits（编译期拆解类型）、编译期递归的终止条件、给自定义类型接入框架（`std::hash`）、标准库里的优化版本（`vector<bool>`、`unique_ptr<T[]>`）**。游戏客户端可以联系 UE 的 `TStructOpsTypeTraits`、Lua 绑定的类型转换器                                        |
| 7 | **没讲规则与限制**          | 🟡 遗漏   | 特化必须在**第一次使用之前**声明；全特化的函数是普通函数，放在头文件里必须加 `inline`；偏特化不能有默认模板实参；可以只特化类模板的某一个成员函数；不能往 `std` 里特化函数模板（C++20 起）                                                                                                  |
| 8 | **没有提到现代替代方案**       | 🟡 加分项  | C++17 `if constexpr`、C++20 concepts（带约束的偏特化），以及变量模板也可以特化                                                                                                                                                    |
| 9 | 表述细节                 | 🟢 小问题  | “全特化是指针对某一类型”：多个参数时，是针对**一组确定的模板实参**；`Printer<bool>` 里的成员可以和主模板**完全不同**（它和主模板是两个无关的类），这一点也值得说出来。另外有几个错别字：推到 → **推导**，上诉 → **上述**，显示声明 → **显式**声明                                                            |

## 2. 推荐的满分版口述答案（约 2 分钟）

> **特化**是：在通用模板（主模板）之外，为特定的模板实参提供一份**专门的实现**。分两种：
>
> **全特化**用 `template<>`，把所有模板参数都固定下来，比如 `template<> class Printer<bool>`。**全特化之后它就不再是模板了，而是一个普通的类或函数，它的成员可以和主模板完全不同。**
>
> **偏特化**只用于**类模板和变量模板**，它要么固定一部分参数，比如 `Pair<K, int>`；要么限制参数的形状，比如 `T*`、`const T`、`T[N]`、`std::vector<T>`、函数指针 `R(*)(Args...)`。偏特化本身仍然是模板，前提是主模板必须先声明。
>
> **使用时，编译器拿实参去和每一个偏特化做推导，只匹配到一个就用它；匹配到多个，就按偏序规则选最特殊的那个；如果几个一样特殊，就报歧义错误。全特化优先级最高，什么都匹配不上就用主模板。**
>
> **函数模板只能全特化，不能偏特化**，因为重载已经可以表达同样的意思。而且有个坑：**函数模板的全特化不参与重载决议**。编译器先在主模板之间选，选中之后才去看它有没有全特化，所以特化挂在哪个主模板下面，取决于**声明顺序**，结果可能和预期不一样。因此一般建议**函数用重载，不要特化**；真的需要偏特化效果时，就把实现转发给一个**类模板的静态成员函数**，再去偏特化这个类模板；C++17 之后也可以用 `if constexpr`，C++20 可以用 concepts。
>
> 典型用途：`std::is_pointer`、`std::remove_pointer` 这类 type traits 就是用偏特化在编译期“拆解”类型；`Factorial<0>` 这种全特化用来终止编译期递归；`std::hash<MyType>` 让自定义类型可以作为 `unordered_map` 的 key；标准库的 `vector<bool>`、`unique_ptr<T[]>` 也是特化。在 UE 里，给结构体特化 `TStructOpsTypeTraits` 来开启 `NetSerializer`，也是同一个机制。
>
> 需要注意的规则：特化必须在第一次使用之前声明，否则会报错，或者更糟，不同编译单元用了不同版本；全特化的函数放在头文件里要加 `inline`；偏特化不能有默认模板参数。

## 3. 全特化（Explicit / Full Specialization）

### 3.1 全特化之后就是一个“普通的类”

```cpp
template <typename T>
class Printer {
public:
    void Print(const T& v);
};

template <>
class Printer<bool> {              // 和主模板是两个无关的类
public:
    void Print(bool v);            // 签名可以不同
    void PrintUpper(bool v) {...}  // 可以多出主模板没有的成员
};

// 全特化类的成员在类外定义时，不再写 template<>
void Printer<bool>::Print(bool v) { ... }
```

要点：

- 全特化的类**不会继承**主模板的任何成员，主模板里有的，这里不写就没有。`std::vector<bool>` 就是一个“接口长得像、实现完全不同”的全特化（按位存储，`operator[]` 返回代理对象而不是 `bool&`，所以它常被吐槽“不是一个真正的容器”）。
- 全特化类的成员在**类外定义时不加 `template<>`**，因为它已经不是模板了。很多人在这里会多写一个 `template<>`，导致编译错误。

### 3.2 只特化类模板的一个成员函数

不需要把整个类都重写一遍：

```cpp
template <typename T>
class Logger {
public:
    void Log();
    void Other();
};

template <>
void Logger<std::string>::Log() { ... }   // 只特化 Log，Other 仍然用通用版本
```

Demo 实测：

```text
  Logger<T>::Log      通用版本
  Logger<string>::Log 成员函数全特化
  Logger<T>::Other    通用版本（特化 Log 不影响它）
```

但要注意：**成员函数不能单独偏特化**。想对 `Logger<T*>` 的 `Log` 做特殊处理，只能偏特化整个类。

### 3.3 全特化函数在头文件中要加 `inline`

函数模板（以及类模板的成员函数）定义在头文件中，多个 `.cpp` 包含时不会重复定义，因为模板有特殊的 ODR 规则。但**全特化之后就是一个普通函数**，如果定义在头文件里又没有加 `inline`，多个 `.cpp` 包含之后，链接时会报 `LNK2005: 已经在 xxx.obj 中定义`。

```cpp
// MyHeader.h
template <typename T> void Foo(T) {}
template <> inline void Foo<int>(int) {}     // 必须 inline，或者只在头文件中声明、在某个 .cpp 中定义
```

### 3.4 编译期递归的终止条件

```cpp
template <unsigned N> struct Factorial    { static constexpr auto value = N * Factorial<N - 1>::value; };
template <>           struct Factorial<0> { static constexpr auto value = 1ull; };
// Factorial<20>::value = 2432902008176640000，编译期就算好了
```

## 4. 偏特化（Partial Specialization）


### 4.1 偏特化有哪些“形状”

只有**类模板**和**变量模板**（C++14）可以偏特化。偏特化有两个维度：

**维度一：固定部分参数**

```cpp
template <typename K, typename V> struct Pair {};          // 主模板
template <typename K>             struct Pair<K, int> {};  // 第二个参数固定为 int
template <typename T>             struct Pair<T, T> {};    // 两个参数相同
template <typename T>             struct Buffer<T, 0> {};  // 非类型参数也可以固定
```

**维度二：限制参数的形状**

| 偏特化                                  | 匹配          | 标准库中的例子                              |
| ------------------------------------ | ----------- | ------------------------------------ |
| `X<T*>`                              | 所有指针        | `std::iterator_traits<T*>`           |
| `X<const T>`                         | 顶层 const    | `std::remove_const`                  |
| `X<T&>` / `X<T&&>`                   | 引用          | `std::remove_reference`              |
| `X<T[N]>` / `X<T[]>`                 | 数组          | `std::extent`、`std::unique_ptr<T[]>` |
| `X<std::vector<T>>`                  | 某个模板的任意实例   | 自定义的容器 traits                        |
| `X<R(*)(Args...)>` / `X<R(Args...)>` | 函数指针 / 函数类型 | `std::function<R(Args...)>`          |
| `X<T C::*>`                          | 成员指针        | `std::is_member_pointer`             |

Demo 实测（注意两个 const 的区别）：

```text
  Traits<double*>           -> 偏特化 T*
  Traits<int*>              -> 全特化 int*
  Traits<const double>      -> 偏特化 const T
  Traits<const double*>     -> 偏特化 T*        （指向 const 的指针，顶层不是 const）
  Traits<double* const>     -> 偏特化 const T   （顶层 const）
  Traits<char[16]>          -> 偏特化 T[N]
  Traits<vector<Hero>>      -> 偏特化 vector<T>
  Traits<decltype(&Add)>    -> 偏特化 函数指针 R(*)(A...)
  Traits<decltype(&Hero::hp)> -> 偏特化 成员指针 T C::*
```

> `const double*` 匹配的是 `T*`（`T = const double`），而不是 `const T`，因为它的**顶层**不是 const。这是一个很好的追问点，能说清楚说明你真的理解了模式匹配。

### 4.2 偏特化的匹配过程

当代码中用到 `X<A1, A2, ...>` 时：

1. 如果有完全一致的**全特化**，直接使用；
2. 否则，拿实参依次和**每一个偏特化**做模板实参推导（这里是**精确的模式匹配，不做任何隐式转换**）；
3. 没有一个匹配 → 用**主模板**；
4. 只有一个匹配 → 用它；
5. 有多个匹配 → 按**偏序规则**选“最特殊”的那个；没有最特殊的 → **歧义，编译错误**。

**偏序规则**怎么判断“谁更特殊”：给模板 A 的参数代入一个虚构的独有类型，看能不能用这个结果去推导模板 B。如果 A 的任何实例都能匹配 B，反过来不行，那么 A 比 B 更特殊。例如 `T*` 和 `T`：`U*` 能匹配 `T`（`T = U*`），但 `U` 不能匹配 `T*`，所以 `T*` 更特殊。

### 4.3 歧义的例子

```cpp
template <typename K> struct Pair<K, int> {};
template <typename T> struct Pair<T, T> {};
Pair<int, int> p;   // 两个都能匹配，谁也不比谁更特殊
```

MSVC 实测（`cf2_ambiguous_partial.cpp`）：

```text
error C2752: “Pair<int,int>”: 多个部分专用化与模板参数列表匹配
```

解决方法：再加一个更特殊的全特化 `template<> struct Pair<int, int>`，Demo 里就是这样消除歧义的。

### 4.4 偏特化的规则与限制

| 规则                 | 反例 / 实测                                                        |
| ------------------ | -------------------------------------------------------------- |
| 主模板必须先声明           | `cf4_no_primary.cpp` → `C3856: “Traits”: 符号不是 模板 类`            |
| 偏特化不能有默认模板实参       | `cf5_partial_default_arg.cpp` → `C2756: 部分专用化中不允许有默认模板参数`      |
| 偏特化必须比主模板更特殊       | 否则编译报错                                                         |
| 非类型实参不能是依赖参数的复杂表达式 | 例如 `template<int N> struct A<N * 2>` 不合法                       |
| 只有类模板和变量模板可以偏特化    | 函数模板偏特化 `cf1_func_partial_spec.cpp` → `C2768: “h”: 非法使用显式模板参数` |

### 4.5 用途：编译期“拆解”类型

偏特化最大的价值在于：**它能把一个类型拆开，取出其中的组成部分**。这就是整个 `<type_traits>` 的实现基础：

```cpp
template <typename T> struct MyRemovePtr     { using type = T; };
template <typename T> struct MyRemovePtr<T*> { using type = T; };   // 从 Hero* 中“取出” Hero

template <typename T> struct MyIsPointer     : std::false_type {};
template <typename T> struct MyIsPointer<T*> : std::true_type  {};

template <typename T> struct ElemOf;                                  // 只声明不定义：不支持的类型直接编译报错
template <typename T> struct ElemOf<std::vector<T>> { using type = T; };
template <typename T, size_t N> struct ElemOf<T[N]> { using type = T; };
```

“只声明主模板、不定义”是一个很实用的技巧：**只允许特化过的类型使用，其他类型直接在编译期报错**。

## 5. 函数模板：只能全特化，不能偏特化（重点）

### 5.1 为什么函数模板不能偏特化

1. **重载已经能表达同样的意思**：`template<class T> void f(T*)` 就是“对所有指针的特殊版本”。
2. 如果再允许偏特化，“重载决议”和“特化选择”两套规则交织在一起，会非常复杂，标准委员会选择不支持。

### 5.2 全特化不参与重载决议：Dimov/Abrahams 例子

这是这道题**最能拉开差距**的点。函数调用的流程是：

```text
① 在所有【主模板】和非模板函数之间做重载决议 → 选出一个主模板
② 看这个主模板有没有对应实参的【全特化】→ 有就用全特化，没有就实例化主模板
```

所以，**一个全特化属于哪个主模板，决定了它会不会被调用**。而它属于哪个主模板，取决于**它声明时**能看到哪些主模板：

```cpp
// 顺序一：a, b, c
template <typename T> const char* f(T);      // (a)
template <typename T> const char* f(T*);     // (b)
template <> const char* f<>(int*);           // (c) 此时 (b) 更特殊 → c 是 (b) 的特化

// 顺序二：a, c, b
template <typename T> const char* f(T);      // (a)
template <> const char* f<>(int*);           // (c) 此时只能看到 (a) → c 是 (a) 的特化（T = int*）
template <typename T> const char* f(T*);     // (b)

int x; f(&x);
```

Demo 实测：

```text
  顺序 a,b,c：f(&x) -> (c) f<int*> 全特化
  顺序 a,c,b：f(&x) -> (b) f(T*)   <-- 同样的代码换个顺序，特化被“绕过”了
```

第二种顺序下：重载决议在 (a) 和 (b) 之间选了更特殊的 (b)，而 (c) 是挂在 (a) 下面的，所以**根本不会被考虑**。代码一模一样，只是换了声明顺序，调用结果就变了。这也是业界建议**函数模板用重载，不要用全特化**的原因：如果想要 `int*` 的特殊版本，直接写一个非模板重载 `const char* f(int*)`，它一定会参与重载决议。

### 5.3 重载决议的完整优先级

```cpp
template <typename T> const char* g(T);
template <typename T> const char* g(T*);
const char* g(int);                       // 非模板
template <> const char* g<double>(double);
```

Demo 实测：

```text
  g(1)      -> 非模板 g(int)
  g<>(1)    -> 模板 g(T)   （显式写 <> 排除非模板函数）
  g(1L)     -> 模板 g(T)                  ← 注意这一条
  g(&x)     -> 模板重载 g(T*)（相当于偏特化）
  g(3.14)   -> 全特化 g<double>
```

规则顺序：

1. **先比转换序列**：`g(1L)` 中，模板 `g(T)` 推导出 `T = long`，是**精确匹配**；非模板 `g(int)` 需要 `long → int` 转换。所以**模板胜出**。“非模板优先”只在匹配程度相同时才生效；
2. 转换序列一样好时，**非模板函数优先于模板**（`g(1)`）；
3. 都是模板时，按**偏序规则**选更特殊的（`g(&x)` 选 `g(T*)`）；
4. 选中主模板之后，再看有没有全特化（`g(3.14)` 选中 `g(T)`，再找到 `g<double>`）。

### 5.4 真的需要“函数偏特化”时怎么办

**方案一：转发给类模板**（最通用）

```cpp
template <typename T> struct SerializeImpl                 { static std::string Do(const T&); };
template <typename T> struct SerializeImpl<std::vector<T>> { static std::string Do(const std::vector<T>&); };

template <typename T>
std::string Serialize(const T& v) { return SerializeImpl<T>::Do(v); }   // 函数只做转发
```

**方案二：`if constexpr`（C++17）**，分支少的时候最直观

```cpp
template <typename T> std::string Describe(const T&) {
    if constexpr (std::is_pointer_v<T>)       return "指针";
    else if constexpr (std::is_integral_v<T>) return "整数";
    else                                      return "其他";
}
```

**方案三：tag dispatch 或 concepts 约束的重载（C++20）**

## 6. 特化的声明位置：一个隐蔽的坑

**规则：特化必须在第一次会引起隐式实例化的使用之前声明。**

同一个文件里违反时，编译器能发现（`cf3_spec_after_use.cpp`）：

```text
error C2908: 显式专用化；已实例化“Box<int>”
```

**真正危险的是跨编译单元的情况**：

```cpp
// Serializer.h
template <typename T> struct Serializer { static void Write(...) { /* 通用版本 */ } };

// HeroData.cpp
template <> struct Serializer<HeroData> { static void Write(...) { /* 专用版本 */ } };

// Network.cpp —— 只包含了 Serializer.h，看不到这个特化
Serializer<HeroData>::Write(...);   // 用的是通用版本！
```

标准规定这种情况属于 **ill-formed, no diagnostic required**（程序非法，但编译器不需要报错）。实际表现是：**不同的 `.cpp` 用了不同的版本，一个模块序列化、另一个模块反序列化，数据就对不上了**，而且编译、链接都不会报错。正确做法：**特化的声明必须和主模板放在同一个头文件里，或者放在类型自己的头文件里**，确保所有使用者都能看到。

## 7. 现代 C++ 中的补充

### 7.1 C++20 concepts：带约束的偏特化

```cpp
template <typename T> struct Codec {};                                       // 主模板
template <std::integral T> struct Codec<T> {};                               // 所有整数
template <typename T> requires std::integral<T> && (sizeof(T) == 1)
struct Codec<T> {};                                                          // 1 字节整数
```

Demo 实测：

```text
  Codec<double> -> Codec 主模板
  Codec<int>    -> Codec<integral>
  Codec<char>   -> Codec<integral && 1字节>（约束更强，胜出）
```

约束之间也有“更特殊”的比较（叫**约束包含 subsumption**）：`A && B` 包含 `A`，所以更特殊。以前要用 `enable_if` 加 SFINAE 才能实现的条件偏特化，现在可以直接写出来。

### 7.2 变量模板也可以特化（C++14）

```cpp
template <typename T> constexpr const char* kTypeName     = "unknown";
template <typename T> constexpr const char* kTypeName<T*> = "pointer";  // 偏特化
template <>           constexpr const char* kTypeName<int> = "int";     // 全特化
```

`std::is_pointer_v` 这类 `_v` 后缀的变量模板，就是基于这个特性实现的。小坑：`kTypeName<int>= "int"` 会编译失败，因为 `>=` 被当成一个记号，Demo 编译时真的踩到了（`C2947`），中间必须加空格。

### 7.3 特化 `std` 中的模板

- ✅ 允许：为**自己定义的类型**特化 `std` 中的**类模板**，例如 `std::hash<GridPos>`、`std::formatter<T>`；
- ❌ 不允许：特化 `std` 中的**函数模板**（C++20 起明确禁止），以及往 `std` 里添加重载或新的声明。`swap` 这类函数应该在自己的命名空间里写重载，依靠 ADL 找到。

```cpp
struct GridPos { int x, y; bool operator==(const GridPos&) const = default; };
template <> struct std::hash<GridPos> {
    size_t operator()(const GridPos& p) const noexcept { ... }
};
std::unordered_map<GridPos, const char*> grid;   // 自定义类型可以直接作为 key
```

## 9. 面试官可能的追问

**Q1：特化和实例化有什么区别？**  
特化是**程序员提供**的一个专门版本；实例化是**编译器**用具体实参把模板生成为真正的代码。显式实例化 `template class Vec<int>;` 是要求编译器在这里生成代码（常用来减少编译时间、把模板实现放在 `.cpp` 中），而显式特化 `template<> class Vec<int> {...}` 是自己写一个版本，两者语法只差一个 `<>`。

**Q2：函数模板全特化和重载，选哪个？**  
选重载。全特化不参与重载决议，结果依赖声明顺序（第 5.2 节）。非模板重载一定参与重载决议，行为可预期。

**Q3：类模板的偏特化匹配时，会考虑隐式转换吗？**  
不会。偏特化匹配是**精确的模式匹配**（模板实参推导），`Traits<const double*>` 只能匹配 `T*`，不会因为“可以转换”而匹配其他版本。

**Q4：`vector<bool>` 有什么问题？**  
它是全特化，按位存储，`operator[]` 返回的是代理对象，不是 `bool&`。所以 `bool& r = v[0];` 编译不过，`auto x = v[0];` 得到的是代理而不是 `bool`，也不能安全地多线程写不同的元素（相邻的位在同一个字节里）。需要真正的 bool 数组时，用 `std::vector<char>` 或 `std::deque<bool>`。

**Q5：怎么只让某些类型可以使用某个模板？**  
① 只声明主模板、不定义，只为允许的类型提供特化（第 4.5 节 `ElemOf`）；② 在主模板中 `static_assert(sizeof(T) == 0, "unsupported type")`（注意要依赖 `T`，否则会被立即触发）；③ C++20 用 concepts 约束。

**Q6：特化可以放在 `.cpp` 中吗？**  
可以，但**声明**必须放在头文件中，让所有使用者都能看到（第 6 节），否则不同编译单元可能用了不同的版本。

**Q7：偏特化的参数个数必须和主模板一样吗？**  
不需要。`template<class T, size_t N> struct X<T[N]>` 有两个参数，主模板只有一个；`template<class R, class... A> struct X<R(A...)>` 是可变参数。偏特化参数列表中的参数，只需要都能从实参中推导出来就行。

## 10. 速记卡

```text
全特化：template<>，所有参数固定 → 不再是模板，是普通类/函数（头文件中的函数要 inline）
偏特化：只用于类模板 / 变量模板；固定部分参数 或 限制形状（T* const T T& T[N] vector<T> R(Args...) T C::*）
         前提：主模板先声明；不能有默认参数；匹配不做隐式转换
选择顺序：全特化 > 最特殊的偏特化（偏序；同样特殊 → 歧义报错）> 主模板
函数模板：不能偏特化 → 用重载 / 转发类模板 / if constexpr / concepts
         全特化不参与重载决议：先选主模板，再看特化 → 结果依赖声明顺序 → 建议不要特化函数模板
重载优先级：转换序列更好 > 非模板 > 更特殊的模板 > 通用模板
特化必须在首次使用之前声明，跨编译单元看不到 = 静默 ODR 违规
用途：type_traits、递归终止、std::hash、vector<bool>/unique_ptr<T[]>、UE TStructOpsTypeTraits、Lua 绑定
```
