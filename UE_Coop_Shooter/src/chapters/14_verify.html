CHAPTER 14

验收：测试清单、调试工具与演示方式

“合格”最后要落在可复现的测试上。本章给出每次改网络代码都要跑的清单、按症状查问题的工具表，以及面试前怎么把这个 Demo 录成一段有说服力的演示。

1. 四种运行模式，各测什么

模式PIE 设置能暴露的问题
Listen ServerNumber of Players = 2，Net Mode = Play As Listen Server主机特殊性：主机玩家既 HasAuthority 又 IsLocallyControlled；SkipOwner 的 OnRep 不在服务器触发
Dedicated ServerNet Mode = Play As Client（后台启动专用服务器）依赖“主机玩家存在”的逻辑（原 Demo 的开局链路）；服务器不渲染：动画通知、骨骼命中盒
独立进程取消 Run Under One Process同进程共享的单例、静态变量掩盖的问题；更接近真实的加载时序
Standalone 双开 / 打包两个独立游戏进程，局域网会话会话（主持 / 查找 / 加入）、断线回菜单、ServerTravel 带人换图

3. 按症状查问题

症状先看工具 / 命令
客户端调用没反应RPC 是否被丢弃（Actor 不属于这个客户端）日志 No owning connection for actor；检查 Owner 链
某个变量客户端不更新Actor / 组件是否 Replicates；变量是否标了复制；条件是否把这个客户端排除了Networking Insights 的属性 / RPC 视图；在 OnRep 里打 Print 确认是否到达
主机正常、客户端不正常是否用了 GetPlayerController(0)、HasAuthority 代替 IsLocallyControlled全局搜索；在节点前打 Print（会带 Server / Client 前缀）
角色被拉回 / 抖动两端移动参数是否一致p.NetShowCorrections 1、p.NetCorrectionLifetime 4、LogNetPlayerMovement
AI 不动 / 卡住行为树当前分支、黑板值Gameplay Debugger（按 '）、Behavior Tree 调试视图、Visual Logger
延迟高、带宽高哪个 Actor / 属性 / RPC 占了带宽stat net、启动参数 -NetTrace=1 -trace=net 录 Networking Insights
帧卡（不是网络）游戏线程 / 渲染线程耗时stat unit、stat game、Unreal Insights（CPU）
一个省时间的小习惯：给 Print String 加上“我是谁”

PIE 多人时 Print String 自带 Server: / Client 1: 前缀，但自定义日志没有。写一个函数库函数 NetTag(Actor)，返回 “NetMode + LocalRole + 是否本地控制”，所有调试输出都带上它，排查“这段代码到底在哪一端跑”会快很多。
