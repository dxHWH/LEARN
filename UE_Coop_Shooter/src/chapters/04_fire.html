CHAPTER 04

问 ①：从开火到击中僵尸，发生了什么

原 Demo 的做法是“服务器生成复制子弹、表现等组播”，没有射线检测；理想方案把一发子弹拆成“本机表现、服务器裁决、各端表现”三段：本机不等服务器，结果只认服务器，别人看到的是服务器复制的结果。

本章目标
  • 按时间顺序讲清一发子弹在三台“视角”（本机 / 服务器 / 另一端）上各发生了什么。
  • 对比原 Demo 的时序：反馈延迟、空放、子弹突现从哪来（E1）。
  • 写出服务器校验、伤害、僵尸受击与死亡的正确实现。
  • 分清当前做法（复制子弹 Actor）与理想方案（命中扫描），以及保留抛射物时的正确做法。
当前做法
原 Demo 没有射线检测。本机按住开火时每 0.12 秒发一条 Reliable 的 Server_Fire；服务器先 Multicast_Fire 组播开火动画，再在 Server_SpawnBullet 里检查弹药、生成一颗复制的子弹 Actor（BP_Bullet，ProjectileMovement 200 m/s）；子弹在服务器和客户端各飞一份，碰撞事件里播弹孔、调用 Apply Damage（客户端那次被 Authority Only 拦下，伤害实际只在服务器）；僵尸在服务器扣血后，用组播播受击 / 死亡。完整时序见图 K0-2。
存在的问题
  1. P1自己开枪要等约 {{v:E1[s=0,rtt=200].own:.0f}} ms：本机不播任何表现，全部等服务器组播（A#9，E1）。
  2. P1组播排在弹药检查之前：打空也播开火动画，还会打断换弹蒙太奇（A#10）。
  3. P1每发一个复制子弹 Actor：远端看到子弹凭空出现在约 {{v:E1[s=0,rtt=200].pop:.1f}} m 外，消息量约 {{v:E7.0.4}} vs {{v:E7.1.4}} B/s（A#12，E1 / E7）。
  4. P1逐发 Reliable：RTT 200 ms、丢包 10% 时 P99 处理延迟 {{v:E2[rtt=200,loss=0.1].p99:.0f}} ms（A#11，E2）。
  5. P1后坐力在服务器上对控制器加输入，只对主机生效（A#13）。
  6. P2伤害写在每一端都会触发的碰撞里、没有权限判断、Instigator 为空：客户端没扣血只是被引擎的 Authority Only 拦下（A#2、A#19）。
  7. 没有延迟补偿：僵尸横移 4.8 m/s、RTT 200 ms 时命中率只有 {{v:E3[v=480,rtt=200].none:.1f}}%（E3）。
理想方案
本章正文的“三段式”：本机立刻播表现并做射线（命中扫描），把序号、起点、方向、命中目标发给服务器；服务器校验后扣弹、结算伤害；各端从复制状态播表现。章末对比命中扫描与抛射物。

原 Demo 的一次连射，在时间轴上长什么样

当前做法下面是 E1 的一次模拟：RTT 200 ms、按住开火 1.5 s、弹匣 10 发。按原蓝图的逻辑：本机计时器每 0.12 s 发一条 Server_Fire，服务器先多播开火动画，再检查弹药、生成复制子弹；弹药变量在下一个网络帧复制回来。

三个现象都能从这张图读出来：

  • 反馈延迟：本机看到自己开火的时间 = 上行半个 RTT + 等服务器网络帧 + 下行半个 RTT。RTT 200 ms 时平均 {{v:E1[s=0,rtt=200].own:.0f}} ms；就算 RTT 为 0，也有约 {{v:E1[s=0,rtt=0].own:.0f}} ms（等 30 Hz 网络帧）。
  • 空放：本机判断“还有子弹”用的是复制下来的旧值，最后一发之后还会再发一次请求；服务器的 Server_Fire 先调 Multicast_Fire 再检查弹药，于是两端都播了一次没有子弹的开火动画。这次多播还带着 bStopAllMontages = true，如果玩家此时在换弹，换弹动画会被打断。
  • 子弹突现：子弹是服务器生成的复制 Actor，到达本机时它已经飞了“一个网络帧 + 下行时间”，平均约 {{v:E1[s=0,rtt=200].pop:.1f}} m——玩家看到子弹凭空出现在枪口前几米处。

理想方案的流程：三段式

第一段：本机（只做表现和预测）

void ACoopWeapon::StartFire() { // 由本地输入调用，只在 IsLocallyControlled 的一端 if (bWantsToFire) return; bWantsToFire = true; FireShot(); GetWorldTimerManager().SetTimer(RefireTimer, this, &ACoopWeapon::FireShot, FireInterval, true); } void ACoopWeapon::FireShot() { if (!bWantsToFire || IsReloadingLocal()) return; if (GetDisplayedAmmo() <= 0) { StopFire(); PlayDryFireLocal(); TryAutoReload(); return; } const uint16 Seq = ++LocalShotSeq; // 预测：显示弹数 = 服务器弹数 - (LocalShotSeq - AckSeq) FVector Start, Dir; GetAim(Start, Dir, /*SpreadSeed*/ Seq); // 相机视点 + 散布；用 Seq 做种子，服务器能复现同样的散布 PlayFireCosmetics(/*bFirstPerson*/ true); // 1P 蒙太奇、枪口火焰、声音 ApplyRecoilLocal(); // 后坐力必须在本地控制者上做（原 Demo 在服务器上做，客户端无效） FHitResult Hit; const bool bHit = TraceShot(Start, Dir, Hit); // 本地射线：只用于命中特效 / 准星命中提示 if (bHit) PlayImpactCosmetics(Hit); FShotRequest R; R.Seq = Seq; R.Start = Start; R.Dir = Dir; R.ClientTime = GetWorld()->GetGameState()->GetServerWorldTimeSeconds(); R.HitActor = bHit ? Hit.GetActor() : nullptr; // PvE：把客户端命中结果一起发上去，服务器做容差校验 R.HitBone = bHit ? Hit.BoneName : NAME_None; if (HasAuthority()) ProcessShot(R); // 主机玩家：直接在服务器处理 else ServerFireShot(R); // Reliable：低频（8 发/秒）且会造成伤害，不能丢 }

第二段：服务器（校验、扣弹、判定、伤害）

void ACoopWeapon::ServerFireShot_Implementation(const FShotRequest& R) { ProcessShot(R); } void ACoopWeapon::ProcessShot(const FShotRequest& R) { check(HasAuthority()); Ammo.AckSeq = R.Seq; // 无论接不接受都推进 AckSeq，本机据此纠正预测 ACoopCharacter* Shooter = GetOwner(); const float Now = GetWorld()->GetTimeSeconds(); const bool bOk = Shooter && Shooter->IsAlive() && !bPendingReload && Ammo.InClip > 0 && FVector::Dist(R.Start, Shooter->GetPawnViewLocation()) < MaxOriginError // 起点：不能离眼睛太远 && FVector::DotProduct(R.Dir, Shooter->GetBaseAimRotation().Vector()) > 0.8f // 方向：与服务器视角接近 && ConsumeShotBudget(Now); // 射速：令牌桶，放最后（有副作用：只有其他条件都过了才扣令牌）；不能比较到达间隔，见第 11 章 if (!bOk) return; // 被拒：弹数不变、AckSeq 已推进，本机显示会 +1 纠正回来 --Ammo.InClip; ++BurstCounter; // COND_SkipOwner：另一端据此播开火表现 if (!Shooter->IsLocallyControlled() && GetNetMode() == NM_ListenServer) PlayFireCosmetics(/*bFirstPerson*/ false); // 主机看客户端开火：C++ 的 OnRep 不在服务器执行，这里手动播 FHitResult Hit; if (ResolveHit(R, Hit)) // PvE：校验 R.HitActor（包围盒 + 容差 + 视线）；PvP：回溯后重新射线（第 6 章） UGameplayStatics::ApplyPointDamage(Hit.GetActor(), BaseDamage, R.Dir, Hit, Shooter->GetController(), this, DamageTypeClass); // Instigator / Causer 都要填 }
为什么这里用 Reliable，而不是原 Demo 的“逐发 Reliable 有问题”？

原 Demo 的问题不在于 Server_Fire 是 Reliable，而在于本机的表现要等它往返一圈，并且多播排在弹药检查之前。改成本机预测后，Reliable 的排队（E2：RTT 200 / 丢包 10% 时 P99 处理延迟 {{v:E2[rtt=200,loss=0.1].p99:.0f}} ms）只会推迟伤害生效，不会影响手感；而换成 Unreliable 则会在同样条件下丢掉约 {{v:E2[rtt=200,loss=0.1].ulost:.0f}}% 的命中——“明明打中了没扣血”比“晚 0.3 秒扣血”更难接受。射速很高（如 20 发/秒以上）时，再把同一帧内的多发合并成一个数组发送。

第三段：僵尸受击与死亡（只在服务器改状态，各端从 OnRep 播表现）

UPROPERTY(ReplicatedUsing = OnRep_Health) float Health = 100.f; UPROPERTY(ReplicatedUsing = OnRep_LastHit) FZombieHitInfo LastHit; // {uint8 Counter; FVector_NetQuantize Point; bool bHeadshot; ...} UPROPERTY(ReplicatedUsing = OnRep_IsDead) bool bIsDead = false; float ACoopZombie::TakeDamage(float Damage, const FDamageEvent& Ev, AController* InstigatorPC, AActor* Causer) { if (!HasAuthority() || bIsDead) return 0.f; // 显式写出权限判断（原 Demo 依赖 Apply Damage 的 Authority Only 才没出错） bool bHead = false; if (Ev.IsOfType(FPointDamageEvent::ClassID)) { const auto& PE = static_cast(Ev); bHead = PE.HitInfo.BoneName == HeadBoneName; LastHit.Point = PE.HitInfo.ImpactPoint; } Damage = bHead ? 两个容易被追问的细节
  • 爆头判定用的是哪套骨骼？服务器用自己的骨骼姿势做射线。Listen Server 的主机会渲染，骨骼每帧更新；Dedicated Server 默认不刷新不可见网格的骨骼，需要把僵尸网格的 VisibilityBasedAnimTickOption 设为 AlwaysTickPoseAndRefreshBones，或者干脆用胶囊体 + 头部球体这类简化碰撞体判定。
  • 受击反馈用 Multicast 还是复制属性？两者都可以。用复制属性（如 LastHit 计数器）能和血量在同一次更新里到达，不会出现“血先掉、动画后播”；Unreliable Multicast 更简单，丢了也只是少播一次受击动作。绝对不要在客户端调用它。

改完之后的时间轴

命中扫描还是抛射物？

理想 A：命中扫描（Hitscan）理想 B：服务器抛射物 + 本机假子弹当前做法：复制抛射物
适合步枪、手枪（子弹飞行时间 < 一帧到几帧）火箭筒、榴弹、慢速弓箭—
本机手感立即立即（假子弹不复制，只在本机）晚一个 RTT 才看到子弹
别人看到BurstCounter + 本地曳光服务器抛射物复制下来（可按 RTT/2 向前外推）突然出现在几米外
网络开销每发几个字节每发一个 Actor 通道每发一个 Actor 通道（E7）
伤害在哪算服务器服务器抛射物的命中每一端都调用 Apply Damage，客户端那次被 Authority Only 拦下，实际只在服务器

当前做法原 Demo 用的是最右一列：子弹 20000 cm/s，打 20 m 外的僵尸只要 0.1 s，本质上就是命中扫描，却为每一发付出了一个复制 Actor，还要处理远端子弹突现、两份子弹各撞各的。

理想方案重构方案对步枪走路线 A：伤害由服务器校验后的射线结果决定，“看得见的子弹”由各端本地画不复制的曳光。以后加火箭筒这类慢速弹再走路线 B：服务器生成权威子弹，伤害只在它的碰撞里结算（先判断权限）；开火者本机立刻生成一颗不复制的假子弹；服务器子弹对开火者隐藏，其他端看到它时按延迟向前快进一段。为什么快进还不够、什么时候要目标回溯、高射速怎么办，见第 5B 章。

面试注意：这道题的高频坑
  • 说“客户端做射线，打中了就调 Server RPC 扣血”——要补上服务器校验，否则外挂可以随便上报命中。PvE 合作游戏可以放宽，但射速、弹药、起点、方向这些必须校验。
  • 说“服务器多播开火，所有人一起播动画”——开火者自己会晚一个 RTT。开火者本机预测播，别人用 SkipOwner 的计数器或多播。
  • 忘了 Listen Server 主机：C++ 的 OnRep 只在收到复制的客户端执行、服务器上永远不执行（与 SkipOwner 无关），所以主机要看到客户端开火，需要在 ProcessShot 里自己播远端表现；蓝图的 RepNotify 在服务器赋值时会执行一次，蓝图版反而要在 OnRep 里过滤掉主机自己的武器（第 11 章图 11-4）。
  • 伤害不填 Instigator：后续的击杀统计、友伤规则、仇恨（僵尸追击打它的人）都做不了。
本章速记
  • 本机：检查预测弹药 → 扣一发、Seq+1 → 立即播 1P 表现和后坐力 → 本地射线播命中特效 → ServerFireShot(Seq, 起点, 方向, 时间)。
  • 服务器：校验（存活 / 换弹 / 射速 / 弹药 / 起点 / 方向）→ 扣弹、AckSeq、BurstCounter → 判定命中 → ApplyPointDamage(Instigator, Causer)。
  • 僵尸：TakeDamage 仅服务器；Health / LastHit / bIsDead 复制，OnRep 播受击和布娃娃；死亡时停 AI、清计时器、加分、由 GameMode 补刷。
  • E1：原方案本机反馈 ≈ RTT + 网络帧；预测后本机为 0，另一端的延迟不变。
自测：为什么服务器拒绝一发之后，仍然要把 AckSeq 推进到这一发的序号？ 本机的显示值 = 服务器弹数 − (本地已发序号 − 服务器已处理序号)。服务器拒绝时弹数没减，如果 AckSeq 也不推进，本机会一直认为这发“还在路上”，显示值永远少 1；推进之后，未确认发数减 1 而服务器弹数不变，显示值自动 +1，被拒的那发就被纠正回来了。
自测：原 Demo 中客户端玩家为什么感觉不到后坐力？ 后坐力 Timeline 在服务器的 Server_SpawnBullet 里触发，调用的是 Pawn->AddControllerYawInput / AddControllerPitchInput。这两个函数只在 Controller 是本地玩家控制器时才生效；服务器上客户端玩家的 PC 不是本地的，调用直接被忽略。主机玩家的 PC 在服务器上是本地的，所以只有主机有后坐力。
