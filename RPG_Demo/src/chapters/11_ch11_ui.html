CHAPTER 11

UI 与表现层：血条、受击闪白与视差背景

表现层的面试题看起来“简单”，追问却很深：事件订阅放在哪个生命周期、renderer.material 为什么会悄悄复制材质、多个系统同时改颜色谁说了算、UI 刷新怎么不卡。项目里已经写好了一个没用上的 Shader，正好拿来讲“从改材质到改参数”的演进。

本章目标
  • 说清事件订阅的对称原则，以及 public Action 字段和 event 的区别
  • 理解 sr.material 的复制语义、颜色写者冲突，以及 MaterialPropertyBlock / Shader 参数方案
  • 能推导视差背景的公式，并说出 Canvas 重建、虚拟列表、飘字池这些 UI 性能要点

11.1 30 秒面试版 · 现状 vs 理想

30 秒回答

血条挂在角色下面的世界空间 Canvas 上，Start 里订阅 onHealthChanged 和 onFlipped（角色翻转时把血条反向旋转回来），OnDisable 里退订——订阅与退订不对称，禁用再启用后血条就不再刷新；两个回调都是 public 委托字段而不是 event，外部可以用 = 把别人的订阅冲掉。受击闪白是把 SpriteRenderer 的材质临时换成纯色材质 0.2 s，异常状态用 InvokeRepeating 每 0.3 s 切换颜色；问题是 sr.material 会为每个角色复制一份材质实例，闪白、异常色、眩晕取消三方都直接写颜色。项目里已经有一个支持闪白强度和闪烁参数的 SpriteStatusFX Shader，但没有材质用它——用 MaterialPropertyBlock 改它的参数就是正确的方向。

11.2 血条：订阅放在哪里

private void Start() { entity = GetComponentInParent(); myStats = GetComponentInParent(); UpdateHealthUI(); entity.onFlipped += FlipUI; // 订阅在 Start myStats.onHealthChanged += UpdateHealthUI; } private void FlipUI() => myTransform.Rotate(0, 180, 0); // 父物体转 180°，子 UI 再转回来，文字不镜像 private void OnDisable() { entity.onFlipped -= FlipUI; // 退订在 OnDisable myStats.onHealthChanged -= UpdateHealthUI; }
  • 问题 P2 如果对象在 Start 之前就被禁用（例如生成时立即 SetActive(false)），OnDisable 先于 Start 执行，entity 还是 null，退订时空引用。
  • public Action vs event：public System.Action onHealthChanged; 允许任何人写 stats.onHealthChanged = Foo;，一行代码就冲掉了所有已有订阅，也允许外部直接 onHealthChanged() 伪造通知。加上 event 关键字后，外部只能 += / −=。
  • 只刷新血量不刷新上限：装备改变最大生命时不触发事件，血条上限要等下一次受伤（第 7 章）。
  • 翻转的写法：Entity.Flip 用 transform.Rotate(0, 180, 0) 翻转整棵层级（攻击点、检测点、子 UI 一起翻），所以 UI 需要“反向转回来”。另一种写法是只翻 SpriteRenderer.flipX 或 scale.x = −1，各有对子物体的影响，选定一种后要在整个项目里一致。

11.3 受击闪白与异常色：谁在写颜色

private void Start() { sr = GetComponentInChildren(); originMat = sr.material; } // ← 读取 .material 会复制一份实例 private IEnumerator FlashFX() { isFlashing = true; sr.material = hitMat; // FlashFXMaterial：内置纯色 Shader，整张图变白 Color currentColor = sr.color; // 记下“此刻”的颜色（可能是异常色） sr.color = Color.white; yield return new WaitForSeconds(0.2f); sr.color = currentColor; // 0.2 s 后恢复成记下的颜色 sr.material = originMat; isFlashing = false; } private void CancelColorChange() { CancelInvoke(); sr.color = Color.white; } // 取消该组件上所有 Invoke
问题说明
sr.material 复制材质 扩展Renderer.material 的 getter 在材质被共享时会克隆一份并让该渲染器从此使用克隆体。每个角色一份 Sprites-Default 的副本：破坏动态合批（材质不同不能合批），而且克隆体不会随对象销毁自动释放，需要在 OnDestroy 里 Destroy(originMat)。只想读应使用 sr.sharedMaterial。
颜色的三个写者闪白协程（记下颜色、0.2 s 后恢复）、异常状态 InvokeRepeating（每 0.3 s 在两种颜色间切换，闪白期间靠 isFlashing 跳过）、CancelColorChange（取消全部 Invoke 并设白）。推断 如果异常状态恰好在闪白的 0.2 s 内结束，CancelColorChange 先把颜色设白，随后闪白协程把颜色恢复成“闪白开始时记下的异常色”——异常结束了，颜色却永久残留。
CancelInvoke() 误伤眩晕结束时调用 CancelColorChange，会把点燃 / 冰冻的变色一并取消（第 4 章）。
未使用的 ShaderAssets/Script/SpriteStatusFX.shader 已经支持 _FlashAmount（闪白强度）和 _BlinkColor / _BlinkIntensity / _BlinkSpeed（状态闪烁），但没有任何材质引用它。
static readonly int FlashId = Shader.PropertyToID("_FlashAmount"); static readonly int BlinkId = Shader.PropertyToID("_BlinkIntensity"); static readonly int BlinkColorId = Shader.PropertyToID("_BlinkColor"); MaterialPropertyBlock mpb; // 所有角色共用同一个 SpriteStatusFX 材质，参数各自写在 MPB 里 float flashUntil; void LateUpdate() // 每帧由“当前所有效果”推导一次，不再有写者冲突 { sr.GetPropertyBlock(mpb); mpb.SetFloat(FlashId, Time.time < flashUntil ? 1f : 0f); var top = buffs.TopVisualAilment(); // 优先级最高的异常（来自 Buff 系统） mpb.SetFloat(BlinkId, top != null ? 1f : 0f); if (top != null) mpb.SetColor(BlinkColorId, top.color); sr.SetPropertyBlock(mpb); } public void Flash(float sec) => flashUntil = Mathf.Max(flashUntil, Time.time + sec);

注意 MaterialPropertyBlock 与 SRP Batcher 不兼容（使用 MPB 的渲染器会退出 SRP Batcher 路径）；2D 内置管线下它能保持“同一材质”，对动态合批友好。若使用 URP 2D，也可以把闪白做成顶点色或改用 sr.color 的一个通道编码，避免打断合批——具体取舍要用 Frame Debugger 看批次。

11.4 视差背景：一行公式

void Start() { cam = GameObject.Find("Main Camera"); length = GetComponent().bounds.size.x; xPosition = transform.position.x; } void Update() { float distanceToMove = cam.transform.position.x * parallaxEffect; // 背景跟随相机的比例 float distanceMoved = cam.transform.position.x * (1 - parallaxEffect); // 相机相对背景走了多远 transform.position = new Vector3(xPosition + distanceToMove, transform.position.y); if (distanceMoved > xPosition + length) xPosition += length; // 无限循环：整段平移一个图宽 else if (distanceMoved < xPosition - length) xPosition -= length; }

parallaxEffect = 1 时背景完全跟随相机（看起来无限远），= 0 时静止（和前景同深度）。三个追问点：① 用 Update 读相机位置，而 Cinemachine 默认在 LateUpdate 更新相机——背景用的是上一帧的相机位置，相机移动时背景会滞后一帧抖动，应改成 LateUpdate 并保证在相机之后执行（或订阅 CinemachineBrain 的更新事件）推断；② GameObject.Find("Main Camera") 依赖对象名，Camera.main 或注入更稳；③ 世界坐标离原点很远时 float 精度下降，大地图需要“原点重置”（floating origin）。

11.5 UI 性能要点（扩展）

主题要点
Canvas 重建同一 Canvas 下任一元素变化会触发整张 Canvas 的网格重建（Rebuild）；动静分离：常驻 HUD、频繁变化的血条 / 飘字、背包面板各用独立 Canvas 或子 Canvas
布局LayoutGroup / ContentSizeFitter 在任一子元素变化时会重算整组，背包格子这类固定布局可以在编辑期算好
射线检测不需要交互的 Image / Text 关掉 Raycast Target，减少 GraphicRaycaster 的遍历
世界空间血条每个角色一个 Canvas 开销大；数量多时改为屏幕空间统一绘制（一个 Canvas、对象池、每帧把世界坐标转屏幕坐标）
飘字对象池 + TextMeshPro + 共享材质；数字图集化；同一帧同一目标的多次伤害合并显示
数据绑定UI 订阅数据变化（MVP / MVVM），而不是每帧轮询；项目的血条是事件驱动的，方向正确

11.6 面试追问

血条怎么刷新？（Q11-1） ├─ 订阅在哪里做？为什么要退订？（Q11-1 L2） ├─ event 和 Action 字段有什么区别？（Q11-2） ├─ 受击闪白怎么做？为什么不直接改 material？（Q11-3） │ └─ 闪白和中毒变色同时发生怎么办？（Q11-4 → 图 11-2） └─ 1000 个怪的血条怎么做？（场景 11-2）
Q11-1　血条怎么刷新？订阅放在哪？

L2　属性组件在血量变化时触发 onHealthChanged，血条订阅后刷新 Slider。订阅和退订必须成对：OnEnable / OnDisable 或 Start / OnDestroy。不退订的话，血条被销毁后属性组件还持有它的委托，下次触发会访问已销毁对象（MissingReferenceException），也阻止 GC 回收。

L3 · 项目　我写成了 Start 订阅、OnDisable 退订，禁用再启用后就不刷新了；如果对象在 Start 前被禁用，退订时还会空引用。改成 OnEnable / OnDisable，并在 OnEnable 里立即刷新一次。

Q11-2　event 和 public Action 字段有什么区别？

L2　event 对外只暴露 += 和 −=，只有声明它的类能调用和清空；public 字段可以被外部直接赋值（冲掉所有订阅）或直接调用（伪造事件）。我项目里两个回调都是 public 字段，应该加 event。

Q11-3 → Q11-4　受击闪白怎么做？和中毒变色冲突怎么办？

L2　我现在是临时换成一个纯色材质 0.2 s 再换回来。问题是 sr.material 读取时会克隆材质，每个角色一份，破坏合批也要手动销毁；而且闪白、中毒变色、眩晕取消三方都在直接写颜色，可能出现“中毒结束了颜色还残留”。

L3　改成一个支持闪白和闪烁参数的 Shader（项目里已经写好了 SpriteStatusFX），所有角色共享一个材质，用 MaterialPropertyBlock 写各自的参数；每帧由“当前生效的效果”推导参数（闪白截止时间、最高优先级异常），而不是由效果去改颜色——和第 7 章的速度修正器是同一个思想。

常见错误回答

错误：“改颜色用 GetComponent<SpriteRenderer>().material.color = Color.red 就行。”

问题：每个角色克隆一份材质，合批失效、内存泄漏；而且多个效果直接改同一个 color 会互相覆盖。

更好的回答：“只读用 sharedMaterial；按对象改参数用 MaterialPropertyBlock 或顶点色；颜色由效果集合推导，不由效果直接写。”

11.7 发散场景题

场景 11-1　设计一个伤害飘字系统，要求暴击放大、同目标短时间多次伤害合并、不卡帧。

为什么会问：客户端最常见的表现系统之一。

数据：伤害事件（目标、数值、类型、是否暴击）进入队列；合并：同一目标 0.1 s 内的同类伤害累加成一条；表现：对象池里的 TMP 文本，位置 = 目标头顶世界坐标转屏幕坐标 + 随机偏移，动画用曲线驱动（缩放 / 上浮 / 淡出，暴击用另一条曲线和颜色）；性能：单独 Canvas、共享材质、同屏上限（超出时丢弃最小的）。数据来自伤害管线的 HitResult（第 6 章），闪避显示 Miss。

场景 11-2　1000 个怪都要显示血条，怎么做？

为什么会问：世界空间 UI 的规模问题。

不要每个怪一个世界空间 Canvas。方案一：一个屏幕空间 Canvas + 对象池，只给“受过伤 / 在镜头内 / 距离近”的怪分配血条，每帧更新位置；方案二：血条做成 SpriteRenderer（一张 9-slice 图 + Shader 控制填充比例），和怪物一起合批，甚至 GPU Instancing；方案三：完全由一个 Mesh 批量绘制。还要做 LOD：远处只在受伤后显示 2 s。

场景 11-3　策划要求“UI 不能直接调用游戏逻辑”，你怎么组织背包界面？

为什么会问：UI 架构分层。

MVP：View（格子组件，只负责显示和把点击转成意图）、Presenter（把“点击格子 3”翻译成“请求装备容器 A 的第 3 格”，并订阅容器变化刷新 View）、Model（容器 + 事务，第 10 章）。项目里 UI_ItemSlot.OnPointerDown 直接调 Inventory.instance.EquipItem、还读 Input.GetKey(LeftControl)，View 与逻辑耦合；改完后 View 可以换皮、逻辑可以单测、联网时 Presenter 改成发请求即可。

本章速记
  • 订阅 OnEnable / OnDisable 成对；回调用 event 而不是 public 字段（#28）。
  • sr.material 克隆材质（合批失效 + 需手动销毁）；只读用 sharedMaterial（#29）。
  • 颜色有三个写者 → 可能残留异常色；改为 MPB 写 Shader 参数 + 每帧由效果集合推导（项目里的 SpriteStatusFX 已备好）。
  • 视差：x = 起点 + 相机 x × 系数；在 LateUpdate、相机之后读取；Find 换 Camera.main。
自测 1：为什么 UI 需要在角色翻转时“反向旋转”？Entity.Flip 用 transform.Rotate(0,180,0) 旋转整棵层级，子物体上的世界空间 Canvas 也被镜像，文字会反过来；FlipUI 再转 180° 抵消。
自测 2：FlashFXMaterial 用的是什么 Shader？内置 GUI/Text Shader（fileID 10101），它只输出顶点色 × 贴图 alpha，配合 sr.color = white 就是整张图纯白——经典的闪白技巧。
自测 3：MaterialPropertyBlock 有什么限制？使用 MPB 的渲染器不走 SRP Batcher；在内置管线 / 2D 下它保持共享材质，适合动态合批；需要用 Frame Debugger 确认批次。
