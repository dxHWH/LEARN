CHAPTER 09

敌人 AI：骷髅的 6 个状态与“自己切到自己”

骷髅 AI 只有 6 个状态，却集中暴露了“用继承复用转移逻辑”的副作用：战斗状态继承了地面状态的“发现玩家 → 进入战斗”，于是看见玩家的每一帧都在自己切换到自己，顺带执行一次 GameObject.Find；战斗计时器每帧被重置，永远不会超时。

本章目标
  • 画出骷髅状态图，说清感知（射线 + 2 m 圆）、追击、攻击冷却、眩晕、死亡的规则
  • 用 E7 讲清自转移的成因与代价：10 s 内自转移 [[E7.A.self]] 次、Find [[E7.A.finds]] 次
  • 理解“战斗永不超时 + 无边缘检测 + 射线不被墙挡”组合出的“平台下抽搐”
  • 能设计可扩展到百只怪物的 AI：行为树 / 感知系统 / AI LOD / 攻击令牌

9.1 30 秒面试版 · 现状 vs 理想

30 秒回答

骷髅在 Idle 和 Move 之间巡逻（撞墙或到边缘就转身），从前方 5 m 射线或 2 m 范围发现玩家后进入 Battle：追击、进入 1.75 m 攻击距离且冷却好了就攻击，攻击动画里开关弹反窗口，被弹反则眩晕，血量归零进入死亡。问题出在 Battle 继承了 GroundState：父类的“发现玩家就切到 Battle”在 Battle 自己身上也生效，于是每帧 Exit + Enter 一次（Enter 里还有 GameObject.Find），实测 10 s 自转移 [[E7.A.self]] 次；Battle 的超时计时器每帧被重置，玩家跳到高处后骷髅会在他脚下永远来回抽搐，10 s 转身 [[E7.C.flips]] 次。修法：Battle 不继承 GroundState、计时器只在看见玩家时续命；更进一步用行为树和感知组件。

9.3 E7：自转移与 Find

public class Enemy_SkeletonGroundState : EnemyState { public override void Enter() { base.Enter(); playerTransform = GameObject.Find("player").transform; } public override void Update() { base.Update(); if (enemy.IsPlayerDetected() || Vector2.Distance(enemy.transform.position, playerTransform.position) < 2) { stateMachine.ChangeState(enemy.battleState); return; } // ← 当前就是 battleState 时：自己切到自己 } } public class Enemy_SkeletonBattleState : Enemy_SkeletonGroundState // ← 继承了上面的转移 { public override void Enter() { base.Enter(); playerTransform = PlayerManager.Instance.player.transform; } // Find 先执行一次 public override void Update() { base.Update(); // 可能刚刚 Exit + Enter 了自己；return 只退出父类 stateTimer = enemy.battleTime; // ← 每帧重置，下面的 stateTimer < 0 永远不成立 if (enemy.IsPlayerDetected()) { if (enemy.IsPlayerDetected().distance <= enemy.attackRange) { ...; if (CanAttack()) ChangeState(attackState); return; } } else if (stateTimer < 0 || Vector2.Distance(playerTransform.position, enemy.transform.position) > enemy.battleDistance) { stateMachine.ChangeState(enemy.idleState); return; } // 追击：没有边缘检测 enemy.SetVelocity(enemy.moveSpeed * moveDir * 1.5f, rb.velocity.y); } }

用 C++ 逐行移植 4 个状态类，在 1D 平台上跑三个场景（60 fps，遭遇发生在开局 5 s 后）实测 E7 模型：

每秒 [[E7.A.fps|.0f]] 次 GameObject.Find 对一只骷髅不算什么，但它的成本与场景对象数成正比、与怪物数成正比：100 只骷髅同时进入战斗、场景里有几千个对象时，这就是每帧几百次全场景遍历。更关键的是它说明了一个结构性问题：“用继承复用转移规则”会让规则作用到你没想到的状态上，而且因为行为不变，任何功能测试都发现不了。

场景 C：前 3 s 玩家在骷髅前方地面上，骷髅进入战斗并出手；随后玩家跳上骷髅头顶 4 m 高的平台（水平偏移 0.5 m）。此时：射线是水平的，看不见玩家；直线距离约 4 m，不满足 < 2 m 的近身感知，也不满足 > 10 m 的脱战条件；超时条件永远为假。于是：

9.5 其余细节

  • 两种拿玩家的方式：GroundState 用 GameObject.Find("player")（依赖对象名，改名即空引用），BattleState 用 PlayerManager.Instance；BattleState 又声明了一个同名私有字段 playerTransform 隐藏了父类字段。同一个类层次里三份 enemy 字段（基类 enemyBase、Ground 的 enemy、Idle / Death / Stun 各自又声明一次）。
  • Idle / Move 同样有“切走后继续执行”：Idle.Update 在 base.Update 切到 Battle 之后仍会检查自己的计时器并可能切到 Move；Move 切走后仍 SetVelocity 并检查边缘（第 3 章同一个模式）。
  • 眩晕在对方的回调里发生：弹反成功时，骷髅的状态是在它自己的 AttackTrigger 动画事件执行过程中被切到 Stun 的；回调返回后，同一时刻的 CloseCounterAttackWindow 仍会执行。目前无害，但“在回调里改变调用者的状态”是重入问题的温床。
  • 死亡不回收：尸体关掉碰撞体后穿地坠落，GameObject、EnemyStats.Update、血条都还在；刷怪时就是线性增长的“幽灵”。

9.6 改进：从 FSM 到可扩展的 AI

9.7 面试追问

怪物 AI 怎么写的？（Q9-1） ├─ 状态之间怎么复用代码？有没有副作用？（Q9-2 → E7） ├─ 怪物怎么发现玩家？隔着墙能看见吗？（Q9-3） ├─ 追不到玩家时怎么办？（Q9-4 → 场景 C） ├─ 为什么用状态机不用行为树？（Q9-5） └─ 100 只怪同屏怎么保证性能？（场景 9-1）
Q9-1 → Q9-2　怪物 AI 怎么写？状态复用有没有副作用？

L2　和玩家一样是状态类：Idle / Move 巡逻，GroundState 父类负责“发现玩家进入战斗”，Battle 追击并在距离与冷却满足时攻击。

L3 · 项目　我把 Battle 也继承了 GroundState，结果父类的“发现玩家 → 切到 Battle”对 Battle 自己也生效，每帧 Exit + Enter 一次，Enter 里还有 GameObject.Find。行为完全正常，所以功能测试测不出来；我是用 C++ 移植逐帧计数才发现的：10 s 自转移 [[E7.A.self]] 次。修法是让状态机拒绝自转移（或 Battle 不继承），并把 Find 换成注入。

L4 · 攻击　“状态机拒绝自转移会不会影响需要重入的状态？”→ 需要“重新开始”的状态（比如连续两次受击硬直）应该显式调用 Restart，而不是靠 ChangeState(this)；把这两种语义分开，比依赖隐式行为安全。

Q9-3　怪物怎么发现玩家？隔着墙能看见吗？

L2　前方 5 m 的射线（只检测 Player 层）加 2 m 的全向距离。因为射线的 LayerMask 只有 Player，墙不会挡住射线；距离判断也无视墙，所以能隔墙发现。

L3　正确的视线检测是两步：先用 LayerMask = Player 找候选（或者距离 + 视野角），再从眼睛到目标打一条 LayerMask = 地形 的射线，命中地形就说明被遮挡。感知结果写进黑板并记录“最后看见的位置”，丢失目标后去那里搜索，而不是立刻放弃或永远追。

Q9-4　追不到玩家时怎么办？

L2　设计上 Battle 有两个出口：超时（battleTime 5 s 没看见）和距离（> 10 m）。源码每帧重置计时器，超时永不发生；玩家跳到头顶平台时，骷髅在他脚下来回转身，10 s [[E7.C.flips]] 次。

L3　修复后 5 s 脱战。更完整的做法：追击前判断可达性（2D 平台游戏常用“平台图”：哪些平台之间可以走 / 跳过去），不可达时切到“守望”或“远程攻击”；同时给追击加边缘检测，避免追下悬崖。

Q9-5　为什么用状态机不用行为树？

L2　6 个状态、规则简单时 FSM 最直接，调试也容易。当出现“优先级 + 条件组合”（低血量逃跑、有队友时包抄、玩家远程时找掩体）时，FSM 的转移数量会平方增长，行为树用 Selector / Sequence 的优先级结构表达更自然，也更容易让策划配置。

L3　行为树不是银弹：每帧从根节点重新评估有开销，需要“事件驱动 + 装饰器中断”优化；决策特别依赖打分时用 Utility AI，需要规划多步行动时用 GOAP。很多项目是“行为树做决策、FSM 做动作”（行为树叶子节点驱动一个小状态机）。

常见错误回答

错误：“怪物 AI 很简单，就是状态机，没有什么问题。”

问题：面试官会追问“状态之间怎么复用”“丢失目标怎么办”“隔墙能不能看见”，每个问题在这个项目里都有一个具体的 bug。

更好的回答：“状态机本身很简单，我复盘时发现了三类问题：继承复用导致的每帧自转移、计时器写错导致的永不脱战、感知不考虑遮挡。修法分别是……”

9.8 发散场景题

场景 9-1　同屏 100 只骷髅，帧率掉到 30，你怎么优化？

为什么会问：AI 性能是动作 / 割草游戏的必考题。

先用 Profiler 定位（Update 本身、Physics2D 查询、Animator、GC）。AI 侧：① 去掉每帧 Find 和重复射线（E7 每帧 3 次射线 + 1 次 Find）；② 感知降频（每 0.1~0.3 s，分帧错开）；③ AI LOD：屏幕外 / 远处的怪只跑简化逻辑或不跑；④ 统一由 AIManager 批量 Tick，替代 100 个 MonoBehaviour.Update（减少引擎回调开销）。动画侧：屏外 Animator 设为 Cull Update Transforms 或 Cull Completely（注意它会停止动画事件，第 4 章）；GPU 动画 / 合批。物理侧：查询加 LayerMask、NonAlloc；骷髅之间关闭碰撞。再往上是 DOTS / Job System 批量计算移动与感知。

场景 9-2　十只骷髅围住玩家时挤成一团、同时出手，怎么办？

为什么会问：群体 AI 的表现与公平性。

攻击令牌：全局（或以玩家为中心）只发 2 个令牌，拿到令牌的怪才能进入攻击，其他怪在攻击距离外“踱步”；站位：以玩家为中心分配环形槽位，避免重叠；节奏：出手后令牌回收并加个人冷却。这既是性能优化（大多数怪在做便宜的事），也是体验优化（玩家能读清攻击）。

场景 9-3　加一个远程弓箭手，用行为树怎么搭？

为什么会问：考察行为树的实际搭建能力。

Selector：① [Sequence] 低血量 → 逃离；② [Sequence] 目标可见 且 距离 < 3 m → 后撤步；③ [Sequence] 目标可见 且 距离在射程内 且 拿到攻击令牌 → 转向 → 拉弓（技能）；④ [Sequence] 有最后看见位置 → 移动过去搜索；⑤ 巡逻。感知组件负责“可见”，技能系统负责“拉弓”的时间轴与投射物，行为树只做选择。

场景 9-4　怪物需要“仇恨”：谁打它就追谁，但坦克可以嘲讽，怎么做？

为什么会问：多目标选择是联机 / 召唤物出现后的必然需求。

仇恨表：受击者在 Receive 里给攻击者加仇恨（伤害 × 系数），治疗者获得“治疗仇恨”，嘲讽直接把仇恨设为当前最高 + 一个余量并锁定 N 秒；仇恨随时间衰减、目标离开太远时移除。决策时取仇恨最高且可达的目标。这要求先完成第 6 章的 DamageInfo（知道“谁打的”），以及第 1 章说的“敌人不再只认 Player 组件”。

本章速记
  • Battle 继承 GroundState → 看见玩家就每帧自转移 + Find（E7：10 s [[E7.A.self]] 次自转移、[[E7.A.finds]] 次 Find；行为不变，测不出来）。
  • stateTimer 每帧重置 → 永不超时；叠加“射线只看水平、追击无边缘检测” → 平台下抽搐 10 s 转身 [[E7.C.flips]] 次。
  • 感知：射线 LayerMask 只有 Player → 穿墙可见；正确做法是候选 + 遮挡射线 + 最后看见位置。
  • 扩展：感知 → 黑板 → 行为树 → 动作（技能），加攻击令牌、AI LOD、对象池。
自测 1：为什么自转移在画面上看不出来？Exit 把 Move 置假、Enter 立刻置真，同一帧内 Animator 只看到最终值 true，不触发转移；追击和攻击逻辑在自转移之后照常执行。
自测 2：修正版为什么必须在 Enter 里初始化计时器？Battle.Enter 原本不设 stateTimer；去掉“每帧重置”后，若进入时计时器是上次留下的负数，第一帧没看见玩家就会立刻脱战，形成 Idle ↔ Battle 抖动。
自测 3：骷髅死亡后为什么还在消耗性能？Death 状态只关碰撞体、停动画，GameObject 不销毁也不回收，EnemyStats.Update、状态机 Update、血条都还在运行。
