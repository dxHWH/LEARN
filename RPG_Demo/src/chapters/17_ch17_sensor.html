CHAPTER 17

状态判定：着地、贴墙、顶头与边缘怎么检测

问题 ①：“平台跳跃游戏里不同状态怎么判定？当前挂一个 Transform 做射线检测的做法合适吗？能否进一步优化？”——答案是：原型阶段合适，但它把“感知”和“决策”混在一起，并且只用一个点、一条线去代表一个有体积的角色。这一章先拆清楚需要判定什么，再列出单射线方案的六个坑，最后给出“每个物理步一次的感知层”这一更好的结构。

本章目标
  • 列出平台动作游戏需要的“环境判定”：着地、坡度、贴墙、顶头、边缘、站在什么上面
  • 用场景里的真实尺寸算清单射线方案的边界：可识别坡度约 [[F1.a1|.1f]]°、墙检测高度 [[F1.wallH|.2f]] m
  • 比较射线、多射线、形状投射、接触法线、触发器五种检测手段的适用场景
  • 说清“感知层 → 状态机 → 表现”的分层，以及宽限、滞回这两个让判定“不抖”的机制

17.1 口径：30 秒怎么讲 · 现状 vs 理想

面试口播

现状我的做法：角色身上挂两个空子物体作为探测点，脚底那个向下发 0.15 m 的射线判断着地，腰部那个向朝向方向发 0.25 m 的射线判断贴墙，各个状态在每帧更新里自己调用这两个检测。

评价：原型阶段这样做是合适的——直观、成本低、编辑器里能用 Gizmos 画出来调。但它有两个结构性问题：一是用一个点代表有体积的角色（坡度超过约 [[F1.a1|.1f]]° 就判定离地、矮墙测不到、墙顶有死区）；二是感知散落在状态里、在渲染帧里做（同一帧多次查询、结果和物理不同步、没有宽限和滞回）。

理想更好的做法：每个物理步只做一次“感知”，用形状投射或接触法线把接触面分成地面 / 墙 / 天花板，结果写进一个“接触信息”结构，加上宽限时间和滞回；状态机只读这个结构做决策。

17.3 用场景尺寸算一算：单射线的边界

玩家胶囊体宽 0.77 m、高 2.07 m，脚底探测点在胶囊最低点上方 [[F1.s0|.3f]] m，射线长 0.15 m——真正伸出脚底的只有 [[F1.m|.3f]] m（约 4 cm）。站在斜坡上时，胶囊是用圆弧底部的切点接触坡面的，中心正下方的最低点会悬在坡面上方 $r(1/\cos\theta - 1)$。当这个间隙超过 4 cm，中心射线就够不着地面了：

当前关卡全是直角平台，所以这个坑没有暴露；但面试官问“如果加斜坡呢？”时，你能算出“约 [[F1.a1|.1f]]° 就会出问题、为什么、怎么改”，就比“我会加斜坡检测”有说服力得多。

17.4 单射线方案的六个坑

坑 ①　一个点代表一个有体积的角色

现状坡度超过约 [[F1.a1|.1f]]° 判定离地；站在平台边缘、身体中心已经悬空但胶囊圆弧还搭在边上时，射线打空 → 播下落动画、按跳无效，或者在“着地 / 离地”之间每帧抖动。

理想做法用覆盖脚底宽度的检测：两三条射线（左、中、右）取“任一命中”，或者用和脚底同宽的盒子 / 胶囊做向下的形状投射。

坑 ②　射线长度是一个两头为难的魔法数字

现状0.15 m 里有 0.108 m 在碰撞体内部，只伸出脚底 4 cm。太短：下台阶、过接缝、下坡时会短暂判定离地；太长：起跳后的前几厘米仍判定着地，可能重复起跳或落地动画提前播放。

理想做法长度只负责“即将着地”的预判，“是否着地”由实际接触决定；起跳后加一个很短的“着地判定屏蔽时间”（例如 0.05 s），避免起跳那一刻被判回地面。

坑 ③　墙检测只有一条腰部射线

现状墙检测高度在脚底上方 [[F1.wallH|.2f]] m，伸出碰撞体表面 [[F1.reach|.3f]] m。矮于 1.32 m 的墙测不到；接近墙顶时脚还贴着墙、射线已越过墙顶，形成“贴着墙却滑不了”的死区（第 18 章 F5 量化）；只看朝向一侧，背对墙时不算贴墙。

理想做法脚部 + 腰部（必要时 + 头部）两到三条射线，或侧向盒子投射；左右两侧都检测，结果里带上“哪一侧”和“覆盖了多少高度”。

坑 ④　感知散落在各个状态里，在渲染帧里做

现状地面状态、下落、冲刺、滑墙各自调用检测，同一帧最多查询三四次；检测在 Update 里做，而物理世界只在物理步更新，两者节奏不同。更隐蔽的一点：玩家刚体开了插值，Update 里的 Transform 位置是两个物理步之间的插值位置，比真实的物理位置落后最多一步——高速下落时（约 15 m/s）可能差出 0.3 m，射线从“落后的位置”打出去，落地判定会晚一个物理步 推断。

理想做法在每个物理步（FixedUpdate）里做一次感知，射线起点用刚体的物理位置而不是 Transform；结果缓存起来，本步所有状态都读这一份。

坑 ⑤　只靠 LayerMask，不看法线和对象类型

现状地面与墙在同一个 Ground 层（项目里定义了 Wall 层但没用），检测只知道“碰到了 Ground”，不知道是地面、墙还是墙顶；单向平台、移动平台、敌人头顶、箱子都无法区分。另外项目开启了 “Queries Start In Colliders”，脚底射线的起点在玩家自己的碰撞体内部——之所以没打到自己，只是因为 LayerMask 恰好不含 Player 层；哪天把掩码改成 Everything，第一个命中的就是自己。

理想做法按接触法线分类：法线与竖直向上的夹角 ≤ 最大可站坡度（如 45°）是地面，接近水平是墙，朝下是天花板；对象类型用组件或标签识别（单向平台、移动平台、可攀爬墙）；查询时显式排除自身碰撞体。

坑 ⑥　判定是每帧重算的布尔值，没有记忆

现状离开地面的那一帧就切到下落，按跳无效（没有土狼时间，第 20 章 F2）；判定结果没有滞回，在边界上会来回切换。

理想做法感知结果带时间信息——“上次着地是多少秒前”“上次贴墙是多少秒前”；状态机按时间做宽限（离地 0.1 s 内仍可起跳、离墙 0.1 s 内仍可蹬墙）；进入和退出用不同阈值（滞回），例如“连续 2 个物理步命中才算着地”。

17.5 五种检测手段怎么选

手段原理优点缺点适合
单 / 多射线从探测点沿方向打线最便宜、最直观、易调试覆盖不全（点状）；长度难调；不知道体积原型；辅助判断（边缘、前方是否有墙）
形状投射把与脚底同宽的盒子 / 胶囊沿方向“扫”一段距离覆盖整个脚底；返回命中点、法线、距离比射线贵一些；要处理“起点已重叠”地面 / 墙 / 天花板的主判定；“即将着地”预判
接触点法线读取刚体当前所有接触点及其法线（物理引擎已经算好）零额外查询；就是“真实的接触”只有真正碰上才有；动态刚体才有动态刚体角色的着地 / 贴墙判定
重叠查询 / 触发器脚底放一个小盒子，查询与谁重叠简单，适合“区域”判断没有法线；触发器回调时机在物理步后水、梯子、风区、伤害区
运动学控制器的移动结果自己做移动时逐轴投射，碰撞结果就是感知手感完全可控、可确定性斜坡、台阶、推挤都要自己写精品平台跳跃、格斗、需要回放 / 帧同步
推荐组合（动态刚体角色，就是这个 Demo 的情况）

① 主判定：每个物理步读接触点，按法线分类出地面 / 左墙 / 右墙 / 天花板；② 补充判定：向下做一次很短的形状投射，用于“即将着地”（提前切落地动画、下坡贴地吸附）和坑 ① 的平台边缘；③ 辅助射线：前方脚下一条射线做边缘检测（巡逻 AI、防冲刺掉落）。玩家碰撞体用零摩擦物理材质（项目里已经这样做了：forPlayer 材质摩擦为 0），避免贴墙按方向键时被摩擦力挂住——这是 Demo 里做对的一个细节。

17.6 更好的结构：感知层 → 状态机 → 表现

  • 接触信息里存什么：是否着地、地面法线与坡度、脚下对象（普通 / 单向 / 移动平台及其速度）、左右墙是否接触及覆盖高度、是否顶头、前方是否有地面、离地时长、离墙时长。
  • 宽限与滞回放在哪：感知层只报告“事实 + 时间”，宽限（土狼时间、墙宽限）由状态机按时间判断——这样调手感时只改状态机参数，不改检测。
  • 可测试：感知层的输出是纯数据，状态机可以喂一串伪造的接触信息做单元测试（本书第 3 章 E1 就是这样回放的）。

17.7 那么，“挂一个 Transform 做检测”到底合不合适？

场景结论理由
原型、Game Jam、只有直角平台合适Transform 作为探测点直观、可在编辑器里拖动调整、能画 Gizmos；成本最低
有斜坡、单向平台、移动平台需要升级单射线判不了坡、分不清对象类型；至少多射线 + 法线
角色尺寸可变（蹲下、变身）、多种角色复用不合适探测点位置要跟着碰撞体改；应由碰撞体尺寸推导检测形状
精品手感、回放、帧同步不合适需要每物理步一次、确定性的感知；常见做法是运动学控制器自己做碰撞

一句话口径：“Transform 探测点适合原型；要做正式产品，检测形状应该从碰撞体推导、在物理步里集中做一次、按法线分类，并把结果和宽限时间一起交给状态机。”

17.8 面试防守

你怎么判断角色着地？（Q17-1） ├─ 为什么不用 OnCollisionEnter / Exit 判断？（Q17-2） ├─ 斜坡怎么处理？上坡变慢、下坡飞出去怎么办？（Q17-3） ├─ 单向平台怎么做？怎么从上面跳下来？（Q17-4） ├─ 站在移动平台上为什么会滑走？（Q17-5） └─ 检测放在 Update 还是 FixedUpdate？（Q17-6 → 坑 ④）
Q17-1　你怎么判断角色着地？

L1　Demo 里是脚底探测点向下 0.15 m 的射线，只检测地面层。

L2　这个方案的边界我算过：射线只伸出脚底 4 cm，坡度超过约 [[F1.a1|.1f]]° 就会判定离地；站在边缘、中心悬空时也会误判。

L3　更好的做法是在物理步里统一做感知：动态刚体直接读接触点，按法线和竖直方向的夹角分出地面、墙、天花板，再补一个短距离的向下形状投射处理“即将着地”和边缘；结果带上“离地多久”，由状态机做土狼时间和滞回。

L4 · 攻击　“接触点法线在角落会同时出现地面和墙，怎么办？”→ 分别统计：只要有一个法线落在地面范围就算着地，同时记录墙接触；角落里“既着地又贴墙”是合法状态，由状态机按优先级处理（着地优先，墙滑只在空中生效）。

Q17-2　为什么不用碰撞进入 / 退出回调判断着地？

L2　进入 / 退出是“事件”，着地是“状态”。多个接触点、同一物理步里先进后出、穿过单向平台、碰撞体被禁用时不发退出事件，都会让“进入计数 − 退出计数”出错，常见结果是角色在空中被判定为着地。正确做法是每步根据当前接触重新计算（持续回调或主动读取接触点），事件只用来触发一次性表现（落地尘土）。

Q17-3　斜坡怎么处理？

L2　三件事：① 判定——法线角 ≤ 可站坡度算地面，超过的当成墙或滑坡；② 移动——把输入速度投影到坡面切线方向，否则上坡会“顶”着坡、下坡会每帧腾空；③ 下坡贴地——向下短投射，如果离地面很近就把角色吸附到地面并保持着地，避免下坡时“一路小跳”。另外站在坡上不按键时要防止下滑（静止时提高摩擦或关闭重力分量）。

Q17-4 → Q17-5　单向平台、移动平台？

单向平台　Unity 2D 有 PlatformEffector2D：只有从上方来的接触才生效。感知层要识别“脚下是单向平台”，下跳时临时忽略与这个平台的碰撞 0.2~0.3 s；着地判定还要求“竖直速度 ≤ 0”，否则从下往上穿过时会在中途被判着地。

移动平台　角色在平台上时，把平台本步的位移（或速度）叠加到角色上；用父子关系带动最简单，但会和刚体、缩放冲突，更稳的做法是感知层报告“脚下平台的速度”，角色移动时加上它。离开平台时是否继承平台速度（惯性）是设计决定。

常见错误回答

错误：“用 tag 判断碰到的是不是 Ground 就行。”

问题：标签只说明“碰到了什么”，不说明“从哪个方向碰到”——撞到地面块的侧面也会被当成着地，于是贴墙时可以无限起跳（“爬墙 bug”）。

更好的回答：“对象类型用标签 / 组件识别，接触方向用法线判断，两者都要。”

17.9 发散场景题

场景 17-1　角色可以蹲下（碰撞体变矮），蹲着的时候头顶有天花板就不能站起来。怎么做？

考点：检测形状与碰撞体尺寸的绑定。

蹲下时切换到矮碰撞体；想站起时，用“站立尺寸”的形状在当前位置做一次重叠查询（排除自身），有重叠就保持蹲姿。所有检测形状都从当前碰撞体尺寸推导，而不是挂固定位置的 Transform——这正是“挂探测点”方案在角色尺寸会变时不适用的原因。

场景 17-2　加入冰面（滑）和泥地（慢），怎么让判定和移动知道脚下是什么？

考点：表面属性的数据化。

两种来源：物理材质（摩擦）只影响物理，不够表达“加速度 / 最高速度 / 脚步声”；更好的是瓦片或地面对象携带“表面类型”数据（瓦片地图可以按格子查到瓦片资源，第 19 章），感知层把“脚下表面类型”写进接触信息，移动参数按表面类型查表。

场景 17-3　为什么角色偶尔会卡在两块地砖的接缝处？

考点：逐格碰撞体的内部接缝（ghost collision）。

逐格生成碰撞体时，相邻两格之间有一条内部竖边，角色快速滑过时可能被这条边的角“绊”一下。解决办法是把瓦片碰撞体合并成一个整体轮廓（项目里已经用了 CompositeCollider2D，79 格合并成 2 个多边形，第 19 章图 19-2），角色碰撞体用胶囊（圆角）而不是方盒也能大大缓解。

本章速记
  • 先拆判定：着地、坡度、左右墙、顶头、边缘、脚下对象、能否站起。
  • 单射线的边界（场景数值）：伸出脚底 4 cm、可识别坡度 ≈ [[F1.a1|.1f]]°、墙检测高度 [[F1.wallH|.2f]] m。
  • 六个坑：点代表体积、长度两难、墙单射线、散落在渲染帧（且读的是插值位置）、不看法线、没有记忆。
  • 正解：物理步里一次感知 → 法线分类 → 接触信息（含时间）→ 状态机做宽限与滞回。
  • 口径：“Transform 探测点适合原型，正式产品要从碰撞体推导检测形状并集中感知。”
自测 1：为什么射线“加长”也能识别更陡的坡，却不是好办法？加长后起跳后的前几厘米仍会命中地面，导致起跳那一刻被判回着地；“是否着地”应由实际接触决定，长度只用于“即将着地”的预判，并配合起跳后短暂屏蔽着地判定。
自测 2：开启刚体插值后，为什么检测起点不该用 Transform？插值让 Transform 显示的是两个物理步之间的位置，落后于真实物理位置最多一步；物理查询面对的是真实位置的世界，起点应该用刚体的物理位置。
自测 3：骷髅的地面探测点放在身体前方，有什么好处和问题？好处：同一个点兼作“前方是否有地面”的边缘检测，巡逻时到边缘会转身；问题：一个传感器承担了“我是否着地”和“前方有没有路”两个含义，追击状态里没有用它，所以会追下平台（第 9 章）。
