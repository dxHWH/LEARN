CHAPTER 08

技能系统：冷却、冲刺分身与四模式飞剑

“技能系统怎么设计”是 Gameplay 岗的高频系统题。项目里的技能是“每个技能一个 MonoBehaviour + 一个控制器”，能跑，但能看到三类典型问题：名字叫 Can 的函数在消耗冷却、分身的攻击回调拿不到玩家、飞剑用七个 bool 拼出四种模式。

本章目标
  • 说清 Skill 基类的冷却模型，以及 CanUseSkill 为什么违反“命令-查询分离”
  • 找到分身攻击的空引用（P0）和朝向判断写进循环的 bug，并用 E11 量化后者
  • 画出飞剑的生命周期，指出“bool 标志汤”的组合爆炸，给出策略模式的重构
  • 能在白板上画一个数据驱动的技能系统，并对照 UE GAS 的五个核心概念

8.1 30 秒面试版 · 现状 vs 理想

30 秒回答

SkillManager 上挂着三个继承 Skill 的组件（冲刺、分身、飞剑），Skill 只管冷却：CanUseSkill() 冷却好了就直接 UseSkill 并重置冷却。冲刺每次生成一个淡出的分身；飞剑由 SkillController_ThrowSword 控制，支持普通、弹跳、穿刺、旋转四种模式和召回。问题有三：CanUseSkill 名为查询实为命令；分身配置成可攻击，但它的攻击回调用 GetComponentInParent<Player>() 找玩家，分身不是玩家的子物体，范围内有敌人就空引用；飞剑用 7 个 bool 组合模式，任何新模式都要改控制器的每个分支。重构方向是“技能 = 配置 + 运行时实例 + 时间轴任务”，飞剑模式改成可组合的行为对象。

8.2 Skill 基类：冷却与“Can”的副作用

protected virtual void Start() { player = PlayerManager.Instance.player; } protected virtual void Update() { coolDownTimer -= Time.deltaTime; } // 一直往负数减，从不封底 public virtual bool CanUseSkill() { if (coolDownTimer < 0) { UseSkill(); // ← 名字是“能不能用”，实际“已经用了” coolDownTimer = coolDown; return true; } Debug.Log("Skill [" + skillName + "] is on CoolDown"); // 每次失败都拼字符串 + 打日志 return false; }
问题源码事实后果
命令-查询不分离CanUseSkill 调用即消耗冷却调用方无法“先问再决定”。加了状态守卫后（第 3 章），如果冲刺请求被拒绝，冷却已经白白消耗。正确的形状是 bool TryActivate()（名字说明会执行）或 CanActivate() + Commit() 两步
子类重写 Update 没调 baseSkill_ThrowSword.Update 完全重写（Skill_ThrowSword.cs:75-89）飞剑的 coolDownTimer 永不递减；目前掷剑不经过冷却检查所以没暴露，一旦接入就是“永远在冷却”
每帧改写序列化字段SetupGravity() 每帧把 bounce / pierce / spin 的重力写进 swordGravityScale；Regular 分支什么都不做运行中从 Pierce（重力 1）切回 Regular，重力停在 1 而不是原来的 4.5——原始值已被覆盖
冷却失败的日志字符串拼接 + Debug.Log每次按键都分配并写日志（打包后 Debug.Log 依然执行，见第 12 章）
未使用的代码FindClosestEnemy 没有调用方；分身和雷击各写了一份“找最近敌人”同一逻辑三份实现，修 bug 要修三处（其中一份就有 E11 的 bug）

8.3 冲刺分身：一个 P0 和一个循环里的 bug

public void SetupClone(Transform _newTranform, float _cloneDuration, float _colorLosingSpeed, bool canAttack) { transform.position = _newTranform.position; // 只拷了位置，没拷朝向 cloneTimer = _cloneDuration; if (canAttack) // 场景里 Skill_Clone.canAttack = 1 { FaceClosesttTarget(); animator.SetInteger("AttackNumber", Random.Range(1, 4)); // 随机播 1~3 段攻击 } } private Player player => GetComponentInParent(); // 分身是 Instantiate(clonePrefab) 生成的根物体 private void AttackTrigger() // 攻击片段 0.083~0.357 s 处的动画事件 { foreach (var c in Physics2D.OverlapCircleAll(attackCheck.position, attackCheckRadius)) if (c.GetComponent() is Enemy enemy) { player.stats.DoDamage(enemy.stats); // ← player 为 null：NullReferenceException enemy.DamageEffect(); } } private void FaceClosesttTarget() { float closestDistance = Mathf.Infinity; foreach (Collider2D collider in Physics2D.OverlapCircleAll(transform.position, 25)) { Enemy enemy = collider.GetComponent(); if (enemy != null && Vector2.Distance(transform.position, enemy.transform.position) < closestDistance) { closestDistance = ...; closetEnemy = enemy.transform; } if (closetEnemy != null && transform.position.x > closetEnemy.position.x) transform.Rotate(0, 180, 0); // ← 写在 foreach 里：之后每遍历一个碰撞体都可能再转一次 } }

问题 P0 分身由 Instantiate(clonePrefab) 生成，没有父物体，Clone.prefab 上也没有 Player 组件（已查 prefab：只有 SpriteRenderer、Animator、SkillController_Clone 和一个 AttackCheck 子物体）。GetComponentInParent<Player>() 必然返回 null。因为空引用发生在 if (enemy != null) 里面，只有分身攻击范围内有敌人时才会抛异常——也就是“分身攻击从来没打出过伤害，而且每次打到敌人都报错”。教程原版在 SetupClone 里把 player 作为参数传进来，这个项目改成了属性查找。修法：Skill_Clone 在 CreatClone 时把 Player（或者攻击者的 CharacterStats）传进去。

问题 P2 FaceClosesttTarget 把旋转写进了循环：一旦找到最近的敌人，之后每遍历一个碰撞体（地面、血条触发器、掉落物……OverlapCircleAll 半径 25 且没有过滤），只要“分身在敌人右边”就再转 180°，最终朝向取决于剩余碰撞体个数的奇偶。实测 E11（每个 n 跑 20 万次，敌人位置和碰撞体顺序随机）：

还有一个表现问题 推断：SetupClone 只拷贝了位置没拷贝朝向，分身默认朝右；玩家向左冲刺且附近没有敌人时（不进入 FaceClosesttTarget 的旋转），残影朝向与玩家相反。最后，每次冲刺都 Instantiate 一个分身、淡出后 Destroy——冲刺冷却 1 s，频率不高，但它是对象池最典型的适用场景（第 12 章）。

8.4 飞剑：七个 bool 拼出四种模式

模式关键逻辑问题
RegularOnTriggerEnter2D → 伤害 + 冻结 0.7 s → StuckInto：关碰撞、变运动学、挂到被击中物体下挂到敌人下后，敌人翻转时剑跟着转；敌人若被销毁，剑作为子物体一起被销毁
Bounce首次碰到敌人时收集 10 m 内所有敌人，按列表轮流飞过去，共 4 次只有 1 个敌人时（Count > 1 不成立）直接插住；列表里的敌人死亡后仍会被“弹到”（重复 Die，第 7 章）；弹完后剑悬在半空、碰撞体重新打开
Pierce每碰到一个敌人伤害一次、计数减一；计数用完后插住计数在 StuckInto 里减，伤害在 OnTriggerEnter2D 里——两个函数共同决定一个规则
Spin飞出 10 m 或碰撞后停下，2 s 内每 hitCoolDown 对 1 m 内敌人伤害 + 冻结，然后自动召回hitCoolDown 场景值 0 → 命中数 = 帧数（E10）；每次命中开一个冻结协程（E8）；停住后直接改 transform.position 而不是 rb.MovePosition
召回MoveTowards 玩家，距离 < 1 m 时 player.CatchTheSword()无视墙体穿墙飞回；CatchTheSword 从任何状态（包括死亡）强切（第 3 章）

Setup 的调用顺序也是隐式契约：SpawnSword 必须先调 SetupBounce / SetupPierce / SetupSpin 再调 SetupSword，因为 SetupSword 里要读 isPiercing 决定是否播放旋转动画。7 个 bool 理论上有 128 种组合，合法的只有十来种，非法组合没有任何东西阻止（例如 isRegular 默认就是 true，只有 Setup 系列函数会把它置假）。

public interface ISwordBehavior { void OnLaunch(Sword s) { } bool OnHit(Sword s, Collider2D other); // 返回 true 表示“这一下消耗掉了”，继续交给下一个行为 void Tick(Sword s, float dt) { } } // 普通剑 = [Damage, StickInto]；穿刺剑 = [Damage, Pierce(n), StickInto] // 弹跳剑 = [Damage, Bounce(n, radius)]；旋转剑 = [SpinAfter(distance, duration, hitInterval)] // 新增“追踪剑”= [Homing(turnRate), Damage, StickInto]——只加一个类，不碰其他模式 [CreateAssetMenu] public class SwordConfig : ScriptableObject { public float gravity, launchSpeed, freezeTime; [SerializeReference] public List behaviors; // 由策划在 Inspector 里拼 }

8.5 数据驱动的技能系统：白板版

项目里的写法放进这个系统后
Skill_Dash 的冷却 1 s 在组件字段；冲刺时长 0.2 s 在 Player 字段；冲刺速度 25 在 Player 字段都在 DashConfig 里；时长与位移由时间轴的“位移轨道”定义（并且在固定步里执行，第 5 章）

8.6 面试追问

技能系统怎么设计的？（Q8-1） ├─ 冷却放在哪？为什么 CanUseSkill 会扣冷却？（Q8-2） ├─ 分身怎么拿到玩家的属性？（Q8-3 → P0） ├─ 飞剑四种模式怎么扩展？加一种追踪剑要改几处？（Q8-4） ├─ 技能能不能被打断？打断了冷却怎么算？（Q8-5） └─ 和 GAS 比你的系统缺什么？（Q8-6）
Q8-1 → Q8-2　技能系统怎么设计？冷却为什么在 CanUseSkill 里扣？

L2　Skill 基类只有冷却：Update 里递减，CanUseSkill 冷却好了就执行 UseSkill 并重置冷却，返回 true。冲刺、分身、飞剑各是一个子类组件，挂在 SkillManager 上。

L3　这个接口的问题是查询带副作用：调用方无法“先问能不能、再决定要不要”。比如冲刺被状态守卫拒绝时，冷却已经扣了。我会改成 TryActivate（名字表明会执行），或者 CanActivate + Commit 两步，Commit 才扣冷却和资源——GAS 的 CommitAbility 就是这个设计。

Q8-3　分身怎么拿到玩家的属性来算伤害？

L2　现在是 GetComponentInParent<Player>()，但分身是独立生成的根物体，找不到玩家，范围内有敌人时空引用。这是我复盘时发现的最严重的问题之一：分身的攻击动画在播，却从来没有造成过伤害。

L3　正确的做法是创建时注入攻击者的属性（或者一个“伤害来源”对象），而且最好是快照：分身存在期间玩家换了装备，分身的伤害按创建时还是按当前？这是一个需要策划决定的规则，代码要能表达两种。

Q8-4　加一种“追踪剑”要改几处？

L2　现在要改：SwordType 枚举、Skill_ThrowSword 的 SetupGravity 和 SpawnSword 两个 switch、控制器加 isHoming 标志、Update 加分支、OnTriggerEnter2D 和 StuckInto 里所有“isXxx”判断都要检查是否与新模式冲突——至少 6 处，而且每处都可能破坏已有模式。

L3　改成行为列表后，追踪剑 = [Homing, Damage, StickInto]，只新增一个 Homing 类和一个配置资源。这就是开闭原则：对扩展开放、对修改关闭。

Q8-5　技能能不能被打断？打断了冷却怎么算？

L2　现状：冲刺可以打断一切（全局检测），瞄准被打断时仍会掷剑（第 4 章）。规则应该写进技能配置：前摇阶段被打断是否返还冷却 / 资源、后摇阶段是否可被移动取消。常见做法是“Commit 发生在前摇结束、判定之前”，所以前摇被打断不扣冷却。

Q8-6　和 UE GAS 比，你的系统缺什么？

L2　缺四样：① 标签系统（技能之间的阻断、取消、需求关系）；② 效果（GameplayEffect）把“改属性”统一成数据，带持续时间、叠加、修正器；③ AbilityTask 这样的异步任务，把“等动画事件”“等输入”“等目标选择”写成可组合的步骤；④ 预测与网络复制。我的项目里这四样分别散落在状态机 if、ItemData_Equipment.AddModifiers、动画事件回调和……没有（单机）。

常见错误回答

错误：“我的飞剑支持四种模式，用了策略模式。”

问题：源码是一个枚举 + 两个 switch + 七个 bool，不是策略模式；面试官只要问“新增一种模式要改哪里”就会暴露。

更好的回答：“现在是枚举 + 标志位实现的，扩展性很差；我设计过改成行为组合的方案，新增模式只加一个类。”——把“做了什么”和“应该怎么做”分开说。

8.7 发散场景题

场景 8-1　加入“冷却缩减 30%”的装备和“可存 2 次的冲刺”，你怎么改？

为什么会问：冷却模型是技能系统的基础。

冷却时长不再是常量，而是 baseCooldown × (1 − CDR)，CDR 来自属性系统（带上限，例如 40%）；冷却缩减变化时，正在冷却的技能是按比例缩短剩余时间还是只影响下一次，要定规则。充能：SkillInstance 存 charges 与 rechargeTimer，使用时 charges − 1，计时器在 charges < max 时运行、到点 +1（累加式计时，第 5 章）。UI 显示层数和环形进度。

场景 8-2　技能 Z 的效果是“3 秒内下一次普攻附带火焰伤害”，放在哪里实现？

为什么会问：考察技能与 Buff 的边界。

技能 Z 只做一件事：给自己上一个 3 秒的 Buff“火焰附魔”（带“下一次普攻”计数 1）；普攻的伤害管线在构造 DamageInfo 时询问身上的 Buff，附魔 Buff 往 DamageInfo.fire 里加数值并消耗计数。这样技能、普攻、Buff 三者互相不知道具体实现，只通过 DamageInfo 和标签交流。

场景 8-3　联机时，飞剑由谁生成？命中由谁判？

为什么会问：投射物同步是联机技能的难点。

状态同步常见做法：客户端本地立刻生成一个“预测投射物”（只做表现），同时把“掷剑（方向、时间戳）”发给服务器；服务器生成权威投射物、判定命中、复制给其他客户端；本地预测物在服务器结果到达后与权威物对齐或替换。轨迹可预测的投射物（抛物线）甚至不需要逐帧复制位置，只复制发射参数，各端自己算（这时 E9 的离散 / 连续一致性就很重要）。

场景 8-4　策划想在不发版的情况下调技能数值，怎么支持？

为什么会问：热更新与配置管线。

数值必须先从组件字段里拿出来（SkillConfig 资源或表格），再走热更通道：资源热更（Addressables / AssetBundle 替换配置资源）或表格热更（下载新的数据表）。逻辑代码不变，只换数据；版本号与校验保证客户端和服务器用同一份配置。项目现在的数值都在场景里，热更只能整场景替换。

方法论延伸

技能与背包、装备如何统一成“配置 / 实例 / 规则 / 表现”四层，并通过属性修正、效果、标签三条通道协作，见第 21 章。

本章速记
  • CanUseSkill = 查询 + 命令；应为 TryActivate 或 CanActivate + Commit。Skill_ThrowSword.Update 没调 base → 冷却永不递减。
  • 分身攻击：GetComponentInParent<Player>() 在独立生成的分身上为 null → 有敌人就空引用、从未造成伤害（#2，P0）。
  • E11：旋转写进 foreach → 朝向正确率 [[e11.2.one|.0f]]%~[[e11.3.one|.0f]]%（n = 2~3 时）。
  • 飞剑：7 个 bool 的标志汤 → 改成行为组合 + 配置资源；数据驱动技能 ≈ GAS 的 Ability / Effect / Tag / Task / Cue。
自测 1：为什么分身的空引用在测试时不容易发现？空引用在 if (enemy != null) 内部，只有分身的攻击范围内恰好有敌人时才触发；而且异常只打印到 Console，不会中断游戏。
自测 2：弹跳剑只有一个敌人时会怎样？BounceLogic 要求 enemyTaget.Count > 1，不满足就不弹；StuckInto 里 isBouncing && Count > 1 也不成立，于是像普通剑一样插在这个敌人身上。
自测 3：SpawnSword 里 Setup 函数的调用顺序为什么重要？SetupSword 里根据 isPiercing 决定是否播放旋转动画，isPiercing 由 SetupPierce 设置，所以必须先调模式 Setup 再调 SetupSword。
