CHAPTER 18

滑墙与蹬墙跳：先定规则，再定检测与参数

问题 ②：“滑墙状态具体应该怎么设计？”——滑墙不是“贴墙时把重力调小”这么简单。它包含进入、维持、退出、蹬墙四段规则，每段都有玩家容错的需求；而“能不能单墙爬上去”这种关键玩法规则，应当是设计决定，而不是参数和检测精度的副作用。本章用关卡里那根 7 m 立柱做实验，说明 Demo 的做法会出现什么、正确的设计是什么。

本章目标
  • 说清滑墙的三个设计目的，以及“单墙能不能爬”为什么必须先决定
  • 画出完整的墙交互状态图：进入条件、维持行为、四个出口、蹬墙跳、墙顶处理
  • 用 F5 实验讲清 Demo 的两个坑：墙顶死区、攀爬成败取决于反应速度
  • 给出每个参数的作用与调参思路：滑速、粘墙时间、墙宽限、蹬墙推力与强制离墙时间

18.1 口径：30 秒怎么讲 · 现状 vs 理想

面试口播

现状我的做法：空中下落时，腰部射线碰到墙就进入滑墙状态，下落速度被固定为 2 m/s（按下键则恢复重力加速）；按跳向反方向蹬出（离墙 4、向上 18）；按离墙方向立刻脱离；着地回到待机。

常见的坑（以我遇到的为例）：① 出口不完整——墙在半空结束时角色会对着空气继续滑；② 检测覆盖不够——只有一条腰部射线，墙顶附近有 1.3 m 的“贴着墙却滑不了”的死区；③ 规则不稳定——我用关卡里 7 m 的立柱测过，单墙能不能爬上去完全取决于玩家在滑墙第几帧按跳：3 帧以内能上，晚 100 ms 就永远卡在墙顶下面。

理想正确做法：先决定“单墙能否攀爬”这条规则；再用多射线 / 形状投射检测墙面覆盖；状态出口覆盖进入条件的否定；加粘墙时间、墙宽限时间和蹬墙后的强制离墙时间；墙顶用翻越或角落修正处理。

18.2 先问“滑墙是为了什么”

① 空中容错

跳歪了还能“抓住”墙，给玩家第二次机会。要求：进入要宽松（自动吸附 / 宽限），减速要明显。

② 垂直移动

两面墙之间来回蹬（墙井），或者单墙连续蹬上去。要求：蹬墙跳的高度、距离稳定可预期。

③ 节奏与关卡语法

下落减速让玩家有时间观察下方；“这面墙能滑 / 那面不能”是关卡设计的词汇。要求：可滑墙面要能被识别和配置。

最关键的设计决定：单墙能不能爬？

不同游戏的选择不同：有的游戏允许贴着同一面墙连续蹬墙攀爬（洛克人 X 系列的“踢墙”是经典例子）；有的游戏在蹬墙后的短时间内强制给一个离墙的水平速度，让玩家必须离开墙一段距离才能再回来——例如 Celeste 公开源码里的常量 WallJumpForceTime = 0.16 s 公开资料。两种都对，错的是“没有决定”：让它取决于推力大小、检测精度和玩家手速，结果就是“有时能爬有时不能”。下面的 F5 实验正好说明了这一点。

18.4 检测：墙要“覆盖”多高才算贴墙

检测方案按精度从低到高：两条射线（脚 + 腰） → 三条射线（脚 + 腰 + 头），用“命中条数”表示覆盖程度 → 侧向盒子投射，返回接触面法线（法线接近水平才算墙，避免把斜坡当墙）。再加两条规则：只在空中检测墙（地面上贴墙是“撞墙停止”，不是滑墙）；左右两侧都检测，这样背对墙时按跳也能蹬墙（是否允许由设计决定）。

18.5 F5 实验：在 7 m 立柱上单墙攀爬

关卡主平台上有一根宽 2 m、高 7 m 的立柱，而普通跳跃的顶点只有约 [[F4.apex|.1f]] m，所以它是一个“必须靠墙交互才能上去”的设计点。实验：玩家从立柱左侧起跳，一直按住朝墙方向（→），每次进入滑墙后经过“反应时间”按一次跳。逐行复刻 Demo 的下落 / 滑墙 / 蹬墙三个状态与检测几何，物理按 0.02 s 步长积分 实测 F5 模型：

三个结论，正好对应三类坑：

  1. 规则不稳定：Demo 的参数下，单墙攀爬是“可能”的，但取决于手速——滑墙第 0~3 帧内按跳能上去（耗时 [[f5.1.t|.1f]]~[[f5.3.t|.1f]] s），晚 100 ms 就永远上不去。对玩家来说，这是一条“有时灵有时不灵”的隐藏规则，最伤手感。
  2. 检测死区才是卡住的直接原因：每次蹬墙其实都在上升（反应 100 ms 时第一次净升高 [[f5.4.gain|.2f]] m），但到了墙顶以下 1.3 m 的区间，弧线回到墙边时腰部射线已经越过墙顶，角色贴着墙往下掉，直到重新低于 11.68 才又进入滑墙——无限循环。只加一条脚部射线，同样 100 ms / 200 ms 的反应就能翻上去（[[f5.9.t|.1f]] s / [[f5.10.t|.1f]] s）。
  3. 推力是“能否单墙攀爬”的开关：离墙推力从 4 提到 6，第一次蹬墙的净升高就变成负数（[[f5.7.gain|.2f]] m）——蹬出去太远，回到墙边时已经低于起点。所以想“禁止单墙攀爬”，加大推力或加强制离墙时间都可以；想“允许”，就要保证在合理反应时间内每次都有正的净升高，并处理好墙顶。
从实验得到的设计方法

① 先写下规则：“允许单墙攀爬，每次蹬墙净升高约 1 m，反应窗口 ≥ 150 ms”或“禁止单墙攀爬，必须在两面墙之间来回”。② 用“蹬墙弧线”反推参数：竖直速度决定弧线高度，水平推力 × 强制离墙时间决定离墙最远距离，空中加速度决定回墙所需时间。③ 用自动化测试固定下来：像 F5 一样让脚本按不同反应时间去爬，CI 里断言“150 ms 反应能爬上去”或“任何反应都爬不上去”。

18.7 面试防守

滑墙怎么做的？（Q18-1） ├─ 什么时候进入、什么时候退出？（Q18-2 → 图 18-1 ①②） ├─ 为什么到墙顶会掉下来？（Q18-3 → 墙顶死区） ├─ 一面墙能不能一直蹬上去？（Q18-4 → F5） ├─ 蹬墙跳的方向和力度怎么定？（Q18-5） └─ 滑墙和下落之间会不会来回抖？（Q18-6）
Q18-1 → Q18-2　滑墙怎么做？进入和退出条件？

L2　滑墙是空中状态的一个子状态：下落中、前方墙面覆盖脚到腰、并且朝墙按住时进入；维持时把下落速度限制在一个较低的上限；出口有四个——墙不再覆盖（回空中）、离墙方向按住超过粘墙时间（回空中）、着地、按跳（蹬墙）。

L3 · Demo　我原来的实现漏了“墙没了”这个出口，墙在半空结束时角色会对着空气继续滑；这让我形成了一个习惯：每写一个状态，先列出它的进入条件，再检查出口是否覆盖了“进入条件不再成立”。

Q18-3　为什么到墙顶会掉下来？

L2　因为墙检测只有一条腰部射线，在脚底上方 1.32 m。接近墙顶时，脚还贴着墙，射线已经越过墙顶，系统认为没有墙，角色就按普通下落掉下去。修法有三层：加脚部射线（最小改动）；到达墙顶时触发翻越；或者做角落修正——蹬墙弧线差几个像素就能上平台时，把角色直接推上去。

Q18-4　一面墙能不能一直蹬上去？

L2　这应该是设计决定。我在 Demo 里测过，原参数下能不能爬上 7 m 的立柱取决于手速：滑墙后 3 帧内按跳能上，晚 100 ms 就卡住。所以我会先定规则：要么允许，保证合理反应时间内每次都有稳定的正升高；要么禁止，用强制离墙时间或更大的推力让玩家必须离开墙。

L4 · 攻击　“玩家觉得禁止单墙攀爬不爽怎么办？”→ 那就在关卡层面给替代路线：两面墙之间的墙井、可抓的边缘、墙上的落脚点。规则一旦稳定，关卡设计才能围绕它展开。

Q18-5 → Q18-6　蹬墙跳参数怎么定？会不会来回抖？

参数　由目标弧线反推：想让玩家在两面相距 d 米的墙之间来回，就让“水平速度 × 到达顶点的时间”大约等于 d；竖直速度决定每次上升多少。强制离墙时间决定玩家多早能改变方向。

抖动　会出现在“刚好贴着墙边缘”的情况：这一步检测到墙、下一步没检测到。用滞回解决：进入滑墙需要墙覆盖（例如两条射线都命中），退出需要完全不覆盖（两条都不命中）并持续 1~2 个物理步。

常见错误回答

错误：“滑墙就是贴墙时把重力调小。”

问题：只回答了“维持”这一段；进入条件、四个出口、粘墙、墙宽限、蹬墙后的控制、墙顶处理都没有覆盖，面试官追问任何一个都会卡住。

更好的回答：“滑墙是空中状态的子状态，我会先定规则（能不能单墙爬），再定检测（墙覆盖率），最后定参数（滑速上限、粘墙时间、墙宽限、蹬墙速度和强制离墙时间）。”

18.8 发散场景题

场景 18-1　加入“抓墙 + 体力”（抓住墙不滑，可以上下爬，体力耗尽后滑落）。

考点：在滑墙基础上扩展新的墙状态。

新增“抓墙”状态（按住抓取键进入），竖直速度由上下输入决定；体力是一个随时间和动作消耗的数值（静止抓墙慢耗、向上爬快耗、抓墙跳一次性扣），着地恢复；体力不足时只能滑墙；UI 和角色表现（出汗、颤抖）提示体力。检测层不变，只多一个状态和一个资源——这正是“感知层与状态机分离”的收益。

场景 18-2　有些墙不能滑（冰墙），有些墙滑得更慢（粘液墙），怎么配？

考点：墙面属性的数据化。

墙面属性放在数据上：瓦片资源或墙对象携带“可滑 / 滑速系数 / 可抓取”等字段；感知层报告“接触的墙面属性”，状态机据此决定能否进入以及用哪个滑速上限。这比在代码里按层名、标签写 if 好维护，关卡设计师可以直接刷不同的墙瓦片。

场景 18-3　手柄玩家反馈“蹬墙跳老是失败”，你怎么排查？

考点：用数据定位手感问题。

录制输入与接触信息：看失败时是“没进入滑墙”（检测 / 进入条件过严）、“按跳太早”（需要跳跃缓冲）、“按跳太晚已离墙”（需要墙宽限）、还是“先按了反方向导致提前脱离”（需要粘墙时间）。手柄摇杆有死区和回中延迟，“松开方向键”在手柄上不是瞬间的，所以粘墙时间对手柄尤其重要。

本章速记
  • 先定规则：单墙能不能爬是设计决定（洛克人 X 允许、Celeste 用 0.16 s 强制离墙）。
  • 六条转移：进入、墙没了 / 主动离开、着地、蹬墙、墙宽限、蹬墙后控制，外加墙顶处理。
  • F5：Demo 参数下单墙攀爬取决于手速（3 帧内能上、100 ms 卡住）；卡住的原因是墙顶以下 1.32 m 的检测死区，加一条脚部射线即可翻上。
  • 参数：滑速上限（限上限不设定值）、粘墙时间、墙宽限、蹬墙速度、强制离墙时间、检测距离、可滑墙面。
自测 1：为什么 Demo 里“先按离墙方向、再按跳”蹬不出去？按离墙方向的那一帧滑墙状态就切到了待机（随后因离地切到下落），跳跃键到来时已经不在滑墙状态；需要粘墙时间。
自测 2：推力从 4 提高到 6，为什么第一次蹬墙净升高就变成负数？蹬出去的水平距离更远，回到墙边需要的时间更长，这段时间里角色已经越过弧线顶点并下落到起点以下。
自测 3：只给墙检测加长射线距离能解决墙顶死区吗？不能。死区是“高度覆盖”问题（射线在腰部、高于墙顶），不是“水平距离”问题；要在更低的位置加射线或用覆盖整个身高的形状投射。
