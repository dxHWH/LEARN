CHAPTER 13

12 条追问链：从一句项目介绍追到底

面试官的追问很少是随机的：他会抓住你话里的一个词往下挖三到五层。每条链给出“面试官的路径”和每一步能直接说出口的回答，括号里是展开时去哪一章找论据和数字。

怎么用这一章
  • 先读每条链的路径，自己口头回答一遍，再对照下面的要点
  • 注意每条链的第 3~4 步——那里通常是“你项目里的具体问题 + 数字”，是拉开差距的地方
  • 最后一节的“危险说法对照表”是面试前一晚必看的

13.1 链 1：项目介绍 → 难点 → 验证 → 反思

介绍一下这个项目 → 你自己做了哪些部分？→ 最难的是什么？→ 你怎么确认它是对的？→ 现在回头看会怎么改？

① 介绍　按第 0 章的一分钟版：结构（Entity + 状态机 + 子系统）→ 亮点（动画事件驱动命中、弹反、飞剑四模式、数值物品）→ 反思（用移植实测找到的问题）。

② 自己做的　主动说明骨架来自教程，自己改了弹反判定方式、异常状态计时、元素选择、掉落抽样，并做了背包 / 装备 / 合成。“哪些是照着做的、哪些是自己改的”说清楚，比含糊地说“都是我写的”可信。

③ 难点　选一个能讲出因果的：状态机的切换入口分散导致死亡可被打断（Ch3）；或弹反判定依赖动画事件同时刻的顺序（Ch4、Ch6）。

④ 验证　“我把状态机和计时逻辑逐行移植成 C++，用脚本化输入逐帧回放，确认了落地贴墙一帧切两次、死亡后冲刺复活；概率类的用 200 万次蒙特卡洛对照解析解。”——这句话本身就是加分项。

⑤ 怎么改　第 12 章的两周路线：先修错后改结构，每步配测试。

13.2 链 2：状态机 → 非法切换 → 同帧多请求 → 预输入

状态机怎么设计的？→ 怎么防止非法切换？→ 同一帧有受击和冲刺两个请求听谁的？→ 预输入怎么做？→ 和行为树怎么选？

①　状态类 + Enter/Update/Exit，Grounded / Air 父类复用输入分支，Enter / Exit 成对设 Animator bool（Ch3.3）。

②　原来没有防：三个切换入口（状态自身、全局冲刺、外部强切）都不检查，死亡后能冲刺复活（E1-S3/S4）；改成 Request + 可打断等级，Death 只接受 Revive（Ch3.9）。

③　请求带等级，同帧只保留最高的，每帧至多提交一次——顺带消灭了“落地贴墙一帧两跳”（E1-S1）。

④　输入采样成快照进带时间戳的缓冲，动作在“可取消窗口”里消费 0.15 s 内的指令；窗口由动画 / 时间轴标记而非写死（Ch3.8）。

⑤　玩家：FSM / HFSM（帧级精确、输入驱动）；AI：行为树（优先级与组合）（Ch3、Ch9）。

13.3 链 3：动画事件 → 帧率 → 打断 → 联网

命中帧怎么做？→ 动画事件在哪个阶段、哪一帧触发？→ 被打断 / 速度为 0 怎么办？→ 两个事件在同一时刻呢？→ 联网还能这样吗？

①　攻击片段上放 AttackTrigger 事件，回调里 OverlapCircleAll（Ch4.3）。

②　Update 之后的动画阶段，在片段时间首次越过事件时刻的那一帧；30 fps 下最多晚 33 ms（Ch4、表 6-1）。

③　事件会被跳过或推迟；逻辑出口不能只靠“动画结束”事件；瞄准被冲刺打断时 Animator 仍会播掷剑片段并触发掷剑（推断，图 4-2）。

④　骷髅的命中与关窗同在 0.4167 s，弹反成功依赖 AttackTrigger 排在前面——隐式契约，应让一个事件携带完整语义或用区间窗口（Ch4.4 ③）。

⑤　帧同步 / 服务器权威都不能依赖动画事件：命中进逻辑时间轴，动画事件只做表现（Ch4.5）。

13.4 链 4：Update / FixedUpdate → 冲刺距离 → 卡顿 → 确定性

Update 和 FixedUpdate 区别？→ 冲刺在高帧率下距离一样吗？→ 卡一帧会怎样？→ 计时器怎么写才对？→ 要做回放 / 帧同步呢？

①　渲染帧 vs 固定 0.02 s 物理步；Update 设的速度在下一个物理步生效（图 5-1）。

②　不一样：冲刺用 Update 计时，120 / 144 fps 时部分情况只有 9 个物理步，4.5 m 而不是 5 m（E10）。

③　卡 250 ms 时冲刺在这一帧结束，但物理已以 25 m/s 补跑完积压时间，冲到 [[e10.hitch.250.max|.1f]] m（图 5-2）。改成按物理步计数。

④　周期计时用累加不用重置；点燃 30 fps 少跳一次、冷却 0 的旋转剑命中数等于帧数（E10）。

⑤　逻辑固定步 + 输入快照 + 可记录种子的 RNG + 不依赖动画与物理引擎；帧同步再加定点数（Ch5 场景 5-4）。

13.5 链 5：命中判定 → 去重 → 弹反 → 伤害管线

攻击判定怎么做？→ 会不会一刀打两次？→ 弹反怎么实现、窗口多宽？→ 为什么弹反成功还掉血？→ 你会怎么重新设计？

①　命中帧 OverlapCircleAll；缺 LayerMask、缺 Hurtbox 分层（Ch6.2）。

②　按碰撞体遍历会：多碰撞体的敌人挨多刀；按实体 HashSet 去重（Q6-3）。

③　受击时处于反击状态且怪物窗口开着就眩晕；成功按键区间宽 [[e2.60.cw|.2f]] s，原教程写法 [[e2.60.ow|.2f]] s，都能预按（E2，图 6-2）。

④　表现（DamageEffect）和结算（DoDamage）是两次独立调用，互不知道结果；同理闪避时也会闪白击退（图 6-1）。

⑤　DamageInfo → 受击方 Receive 唯一裁决 → HitResult；完美窗口从按键起算 0.15 s，落空有收招硬直（Ch6.6）。

13.6 链 6：伤害公式 → 概率 → 护甲 → 伪随机 → 权威

伤害怎么算？→ 暴击率准吗？→ 护甲用减法有什么问题？→ 连续不暴击玩家骂怎么办？→ 联网后在哪算？

①　闪避 → 攻击 + 力量 → 暴击 ×(150 + 力量)% → 减护甲 → 扣血（图 7-1）。

②　暴击用 <= 比较 0~99，实际 (c+1)%，暴击率 0 也有 1%；闪避用 < 是对的；冰冻破甲判断的是攻击者（E3）。

③　低伤害被完全免疫、高伤害几乎无视护甲；改百分比 armor/(armor+K)（Q7-3）。

④　伪随机分布 PRD：未暴击时概率递增、暴击后重置，期望不变、连败被压缩（场景 7-2）。

⑤　状态同步：服务器算，客户端表现；帧同步：确定性 RNG + 定点数（场景 7-3）。

13.7 链 7：Buff → 叠加 → 修正器栈 → 表现推导

Buff 怎么做？→ 冻结和减速同时存在怎么办？→ 多次冻结重叠呢？→ 属性加成的顺序？→ 表现（颜色）怎么跟上？

①　现状：三个 bool + 计时器，协程 / Invoke 恢复（Ch7.6）。

②　三个系统都给 moveSpeed、animator.speed 赋绝对值，谁最后写谁赢（图 7-3）。

③　每次命中开一个冻结协程，最早的到点就解冻，实际只冻住 [[e8r.min|.0f]]%~[[e8r.max|.0f]]% 的时间（E8）；改成截止时间取最大。

④　(base + ΣFlat) × (1 + ΣPercentAdd) × ΠPercentMult，修正带来源、脏标记缓存（Ch7.8）。

⑤　颜色同样由“当前所有效果”推导，MPB 写 Shader 参数（Ch11.3）。

13.8 链 8：技能系统 → 冷却 → 分身 → 扩展 → GAS

技能系统怎么设计？→ 冷却在哪扣？→ 分身的伤害从哪来？→ 加一种飞剑要改几处？→ 和 GAS 比缺什么？

①　Skill 基类管冷却，三个子类组件挂 SkillManager（Ch8.2）。

②　CanUseSkill 查询带副作用，应是 TryActivate 或 CanActivate + Commit（Q8-2）。

③　GetComponentInParent 在独立生成的分身上为 null，范围内有敌人即空引用——分身攻击从未生效（P0，Ch8.3）；创建时注入攻击者属性快照。

④　现在至少 6 处（枚举、两个 switch、标志、Update、碰撞回调）；改行为组合后只加一个类（Ch8.4）。

⑤　标签、Effect、AbilityTask、预测与复制（Q8-6）。

13.9 链 9：AI → 自转移 → 脱战 → 感知 → 规模

怪物 AI 怎么写？→ 状态之间怎么复用？→ 追不到玩家怎么办？→ 能隔墙看见吗？→ 100 只怪呢？

①　6 状态 FSM，GroundState 负责发现玩家（图 9-1）。

②　Battle 继承了 GroundState，看见玩家每帧自转移 + Find，10 s [[E7.A.self]] 次；行为不变所以测不出（E7）。

③　计时器每帧重置永不超时，玩家跳上平台后骷髅在脚下 10 s 转身 [[E7.C.flips]] 次；修复后 5 s 脱战（表 9-2）。

④　能：射线 LayerMask 只有 Player；改为候选 + 遮挡射线 + 最后看见位置（Q9-3）。

⑤　感知降频、AI LOD、批量 Tick、攻击令牌、对象池（场景 9-1、9-2）。

13.10 链 10：背包 → 实例 → 合成 → 掉落 → 存档防刷

背包用什么结构？→ +5 的剑怎么存？→ 合成怎么保证正确？→ 掉率怎么算？→ 存档和防刷？

①　List 保序 + Dictionary 以 SO 定义作键（Ch10.2）。

②　存不了：没有物品实例；引入 ItemInstance（uid + defId + 实例数据）（Q10-2）。

③　先校验后提交；源码每种材料只扣一份，10 皮 10 铁做 [[e6.10_10.bc]] 件而不是 [[e6.10_10.fc]] 件（E6）。

④　判定 <= 多 1%，“最多 3 件”的截断让 35.4% 变成 [[e5.Nice_Armor.final|.1f]]%（E5）。

⑤　存稳定 defId + 版本迁移；产出全在服务器、请求 id 去重（场景 10-2、10-3）。

13.11 链 11：生命周期 → 单例 → fake null → 执行顺序 → 池化

Awake 和 Start？→ 单例怎么写？→ Destroy 之后是 null 吗？→ 初始化顺序怎么控制？→ 对象池复用后为什么出 bug？

①　Awake 我自己、Start 我和别人；项目把取组件放在 Start（Ch2.2）。

②　后来者自毁；项目里两个单例写反，可能导致“冲刺只能用一次”（推断，图 2-2）。

③　帧末才销毁；之后 == null 为真但 ?. 不认（Ch2.4）。

④　执行顺序不被子类继承，CharacterStats 300 无效；更推荐显式初始化（Ch2.5）。

⑤　Awake / Start 不再调用，重置要放 OnSpawn；残留 Invoke 与旧引用用代数句柄防（Ch12.4）。

13.12 链 12：性能 → 工具 → GC → 工程化

项目有哪些性能问题？→ 怎么定位？→ 哪些写法会 GC？→ 怎么防止“编辑器能跑、打包失败”？→ 给你两周先做什么？

①　按频率 × 单次成本排：自转移带来的 Find、瞄准的重复坐标转换、Overlap 分配、协程、实例化（Ch12.2）。

②　Profiler（CPU 时间线 + GC Alloc + Deep Profile）、Memory Profiler 快照 Diff、Frame Debugger（Q12-1）。

③　返回数组的 API、字符串、new 引用类型、协程；不报没测过的字节数（Ch12.3）。

④　asmdef 分离、CI 每日真打包；项目里两处 using UnityEditor 就是例子（Ch2.6）。

⑤　先错后构：P0 → 逻辑 → 帧率 → 结构，每步配测试（图 12-2）。

13.13 危险说法对照表

危险说法为什么危险（会被哪一行代码戳穿）更好的说法
“我的状态机很完善。”Player.Update 的全局冲刺能打断死亡“结构清晰，但切换入口分散，我发现并修了死亡可被打断。”
“动画事件是精确的。”事件按帧量化、可被打断、受速度影响“动画事件按帧量化，适合表现；严格判定我用逻辑时间轴。”
“乘了 deltaTime 就帧率无关。”冲刺距离和点燃跳数随帧率变“乘 dt 只管速率；时长和离散次数要用固定步或累加计时。”
“弹反窗口是 0.33 秒。”那是骷髅开窗的时长，按键成功区间约 1 s“开窗 0.33 s，但判定在命中时刻，按键区间由 1 s 的架势决定。”
“暴击率配多少就是多少。”<= 让实际值多 1%“我测过，判定写成了 <=，统一成一个 Roll 函数后修好了。”
“我的飞剑用了策略模式。”实际是枚举 + switch + 7 个 bool“现在是标志位实现，我设计了行为组合的重构。”
“分身会攻击敌人。”攻击回调里 player 为 null“分身的攻击动画在播，但伤害有空引用，这是我复盘时发现的 P0。”
“怪物 AI 没什么问题。”每帧自转移、永不脱战、穿墙可见“行为看起来正常，但我用逐帧计数发现了三个结构性问题。”
“背包用字典，O(1)。”没有实例、没有容量、合成少扣料“从定义 / 实例 / 容器 / 事务四层讲。”
“我优化了 GC，减少了 X KB 分配。”没在 Profiler 里测过的数字“我定位到这些分配点，并在 Profiler 里确认过修复前后的差异。”（只报测过的）
