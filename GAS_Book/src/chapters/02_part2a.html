CHAPTER 04

GameplayTags：系统之间的通用语言

Tag 是 GAS 中最简单、也最重要的概念。Tag 体系设计得好，后面大部分规则可以只靠配置完成。

4.1 Tag 是什么

FGameplayTag 本质上是一个注册过的 FName，用点号表示层级，例如 State.Debuff.Stun。它比 FName 和枚举更适合描述状态，原因有三点：

  • 层级匹配：查询 State.Debuff 时，State.Debuff.Stun 也会命中。"驱散所有负面效果"只需要一行。
  • 全局注册：所有 Tag 都在 TagManager 中注册，编辑器里可以下拉选择，拼错名字会在加载时报错。
  • 网络友好：复制时传的是索引而不是字符串（开启 Fast Replication 后），带宽开销很小。

4.2 定义 Tag 的三种方式

方式适合备注
Project Settings → GameplayTags（写入 Config/DefaultGameplayTags.ini）策划配置使用的 Tag可以拆成多个 Config/Tags/*.ini 文件，减少多人修改同一文件时的冲突
DataTable（行结构 GameplayTagTableRow）批量导入在 GameplayTagTableList 中注册
Native Tag（C++）代码中需要直接引用的 Tag推荐。编译期可检查，不用担心字符串拼错

4.4 ASC 上的 Tag：带计数

ASC 内部通过 FGameplayTagCountContainer 记录每个 Tag 的引用计数。两个 GE 都授予了 State.Debuff.Slow，计数为 2；移除其中一个后计数为 1，Tag 依然存在。这样不同来源的同一状态就不会互相覆盖。

技能激活期间GA 的 ActivationOwnedTags技能结束时自动移除各端在本地激活时各自添加
Loose TagAddLooseGameplayTag必须手动移除不复制

🌐 网络视角：Tag 计数只在服务器可靠

Mixed / Minimal 模式下，其他客户端（Simulated Proxy）上的 Tag 来自 MinimalReplicationTags，只同步"有没有"，不同步"有几个"。所以不要把 Tag 计数当作玩法计数器（比如层数），层数应该用 GE 的 StackCount 或属性表示。

4.5 推荐的 Tag 命名体系

根节点用途示例
Ability.*技能身份 / 类型（技能的 AssetTags）Ability.Hero.Q、Ability.Type.Attack、Ability.Type.Passive
State.*角色状态（被检查的条件）State.Dead、State.Debuff.Stun、State.Casting
Cooldown.*冷却 GE 授予的 TagCooldown.Hero.Q
Effect.*GE 自身的分类（AssetTags），用于驱散、免疫、查询Effect.Type.CC、Effect.RemoveOnDeath
Event.*GameplayEventEvent.Montage.Hit、Event.Hit.Received
Damage.Type.*伤害类型Damage.Type.Physical、Damage.Type.Magic
SetByCaller.*运行时传入的数值键SetByCaller.Damage、SetByCaller.Cooldown
GameplayCue.*表现（必须以此开头）GameplayCue.Hero.Q.Hit
InputTag.*输入映射InputTag.Ability.Q
✅ 实践建议

Tag 改名时，在 DefaultGameplayTags.ini 中加 +GameplayTagRedirects=(OldTagName="...",NewTagName="...")，否则已经引用旧 Tag 的资产会失效。开启 FastReplication 后，客户端和服务器的 Tag 列表必须完全一致。

本章小结
  • Tag 是层级化、全局注册的名字；HasTag 会向上匹配父级，HasTagExact 只做精确匹配。
  • ASC 上的 Tag 带引用计数，可以来自 GE、技能激活或 Loose 添加；Loose Tag 默认不复制。
  • 先规划好 Tag 树（Ability / State / Cooldown / Effect / Event / GameplayCue），后面大部分规则都能靠配置完成。
CHAPTER 05

Attribute 与 AttributeSet：数值的家

理解 Base 与 Current 的区别、回调的调用顺序，以及 Meta 属性的用法，是写好伤害和数值系统的前提。

5.1 BaseValue 与 CurrentValue

每个属性是一个 FGameplayAttributeData，里面同时保存两个 float：

⚠️ 坑点：不要把"最大生命值"当作 Health 的 Base

新手常以为 Health 的 Base 就是满血值。正确的建模是：Health 和 MaxHealth 是两个独立属性，Health 被 Instant 伤害或治疗修改 Base，MaxHealth 由装备、Buff 等持续型 GE 修改 Current。

5.4 钳制与 Meta 属性：伤害的标准写法

为什么不让伤害 GE 直接 Health −= X？因为扣血之前往往还有很多步骤：护盾吸收、伤害反弹、吸血、击杀判定、伤害数字显示。Meta 属性（例如 IncomingDamage）就是一个临时中转站：GE 只往它里面写数值，在 PostGameplayEffectExecute 中统一处理后清零。

void UMyAttributeSet::PreAttributeChange(const FGameplayAttribute& Attribute, float& NewValue) { Super::PreAttributeChange(Attribute, NewValue); if (Attribute == GetHealthAttribute()) { NewValue = FMath::Clamp(NewValue, 0.f, GetMaxHealth()); } } void UMyAttributeSet::PostAttributeChange(const FGameplayAttribute& Attribute, float OldValue, float NewValue) { Super::PostAttributeChange(Attribute, OldValue, NewValue); // MaxHealth 变化时，按比例调整当前血量（例如 500/1000 → 加装备后 600/1200） if (Attribute == GetMaxHealthAttribute() && OldValue > 0.f) { UAbilitySystemComponent* ASC = GetOwningAbilitySystemComponent(); if (!ASC || !ASC->IsOwnerActorAuthoritative()) return; // 只在服务器修正，客户端等复制 const float NewHealth = GetHealth() * NewValue / OldValue; ASC->ApplyModToAttribute(GetHealthAttribute(), EGameplayModOp::Override, NewHealth); } } bool UMyAttributeSet::PreGameplayEffectExecute(FGameplayEffectModCallbackData& Data) { // 无敌：直接拒绝本次伤害执行 if (Data.EvaluatedData.Attribute == GetIncomingDamageAttribute() && Data.Target.HasMatchingGameplayTag(MyTags::State_Buff_Invulnerable)) { return false; } return true; } void UMyAttributeSet::PostGameplayEffectExecute(const FGameplayEffectModCallbackData& Data) { Super::PostGameplayEffectExecute(Data); if (Data.EvaluatedData.Attribute == GetIncomingDamageAttribute()) { const float Damage = GetIncomingDamage(); SetIncomingDamage(0.f); // Meta 属性用完立即清零 if (Damage <= 0.f) return; const float NewHealth = FMath::Clamp(GetHealth() - Damage, 0.f, GetMaxHealth()); SetHealth(NewHealth); // 来源信息都在 Context 里：谁打的、用什么打的、命中点 const FGameplayEffectContextHandle& Ctx = Data.EffectSpec.GetContext(); AActor* Instigator = Ctx.GetOriginalInstigator(); if (NewHealth <= 0.f && !Data.Target.HasMatchingGameplayTag(MyTags::State_Dead)) { // 通知"死亡"：发 GameplayEvent，由死亡技能去处理（掉落、计分、复活计时） FGameplayEventData Payload; Payload.Instigator = Instigator; Payload.EventMagnitude = Damage; Data.Target.HandleGameplayEvent(MyTags::Event_Death, &Payload); } } }
🔬 深入源码：SetHealth 做了什么

宏生成的 SetHealth(v) 内部调用的是 ASC->SetNumericAttributeBase(Attr, v)，也就是修改 Base 并让聚合器重新计算 Current，而不是直接改 float 字段。所以在 AttributeSet 外部，请始终使用这些 Setter 或 GE 来修改属性，不要直接给 Health.SetCurrentValue() 赋值，否则聚合器状态会被绕过。

5.6 派生属性

"最大生命值 = 体质 × 10 + 200"这种派生关系，不要在代码里手动同步。做法是给角色挂一个 Infinite GE，其中 MaxHealth 的 Modifier 使用 Attribute Based 类型的数值，捕获自身的 Vitality，并且不勾选 Snapshot。之后 Vitality 发生变化时，聚合器会自动重新计算 MaxHealth。

5.7 多个 AttributeSet

一个 ASC 可以有多个 AttributeSet，例如 Lyra 把属性拆成 HealthSet 和 CombatSet。但同一个类的 AttributeSet 只能有一个，ASC 按类查找属性集，有重复时只会返回第一个。

本章小结
  • Instant 改 Base，Duration / Infinite 改 Current。Base 不被持续型效果修改，因此撤销总是精确的。
  • 回调顺序：PreGEExecute → PreBaseChange → Base → PreAttributeChange → Current → PostAttributeChange → PostGEExecute；后两个 Execute 回调只在 Instant / Periodic 时触发。
  • 伤害走 Meta 属性 IncomingDamage，在 PostGameplayEffectExecute 中统一结算后清零。
  • 复制使用 REPNOTIFY_Always + GAMEPLAYATTRIBUTE_REPNOTIFY，原因在第 13 章解释。
