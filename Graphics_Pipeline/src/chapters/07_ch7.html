7.1 像素着色器做什么

像素着色器（Fragment Shader）对每个片元运行一次，输入是插值好的属性（uv、法线、世界坐标……）和系统值（SV_Position 的像素坐标、SV_IsFrontFace、MSAA 的 SV_SampleIndex 等），输出是一个或多个颜色（MRT），可选输出深度和覆盖掩码。

在 PS 里做的事对管线的影响
纹理采样、光照计算正常；开销取决于 ALU 指令数和纹理带宽
discard / clip()（Alpha Test）深度写入必须等 PS 执行完才能决定 → Early-Z 的写入被推迟，移动端 TBDR 的隐藏面消除也会失效（第 8、10 章）
写 SV_Depth深度要等 PS 算完才知道 → Early-Z 完全关闭；可以用 SV_DepthGreaterEqual 等保守深度挽回一部分
写 UAV / 原子操作有副作用的 PS 不能被跳过，需要 [earlydepthstencil] 显式要求早测

7.2 纹理是被采样的信号

纹理是一张离散的 texel 网格，而像素着色器给出的 uv 是连续的。于是有两种情况：

缩小时的走样有一个精确的信号处理解释：采样定理要求采样频率至少是信号最高频率的两倍。一个像素覆盖 8×8 个 texel，相当于每 8 个 texel 只采一次，纹理里任何周期小于 16 texel 的细节都会"折叠"成错误的低频图案——这就是远处地面的摩尔纹，镜头移动时它还会闪烁。解决办法只有一个：采样之前先把高频去掉。

7.3 Mipmap：预先滤好波的金字塔

Mipmap 预先把纹理逐级缩小一半（box 滤波或更好的 Kaiser 滤波），得到 Level 0（原图）、1（1/2）、2（1/4）……直到 1×1。采样时根据"一个像素覆盖多少个 texel"选择合适的层级，于是每次采样都只需要读少量 texel，却得到了大范围的平均值。

  • 内存开销：1 + 1/4 + 1/16 + … = 4/3，只多 33%。
  • 带宽收益：远处像素读的是小 Mip，texel 在内存里很集中，缓存命中率大幅提高（E9：80.8% → 99.3%）。

LOD 怎么算

用第 6 章的屏幕空间导数：一个像素在纹理空间里的"脚印"可以用两个向量近似——沿屏幕 x 方向走一个像素，uv 变化 (∂u/∂x, ∂v/∂x)；沿 y 方向变化 (∂u/∂y, ∂v/∂y)。乘以纹理尺寸换成 texel 单位后：

ρ = max( √((∂u/∂x·W)² + (∂v/∂x·H)²),　√((∂u/∂y·W)² + (∂v/∂y·H)²) )　　LOD λ = log₂ ρ
float lx = std::sqrt(dudx * W * dudx * W + dvdx * H * dvdx * H); // 像素 x 方向在纹理中的长度（texel） float ly = std::sqrt(dudy * W * dudy * W + dvdy * H * dvdy * H); // 像素 y 方向 float lod = log2f(std::max(std::max(lx, ly), 1e-8f)); // 取长边 → 宁可模糊，不可闪烁 return trilinear(u, v, lod); // 在 floor(lod) 和 floor(lod)+1 两层间插值

7.4 四种过滤方式

过滤做法每次采样读 texel问题
点采样 Point取最近的一个 texel，LOD 01放大成马赛克、缩小严重闪烁
双线性 Bilinear取最近的 2×2 texel 按距离加权4放大平滑；缩小仍然走样（只是"软一点的走样"）
三线性 Trilinear在相邻两层 Mip 上各做一次双线性，再按 LOD 小数部分插值8斜视角下过度模糊（用长边选 LOD，短边方向被过度平均）
各向异性 Anisotropic (N×)沿像素脚印的长轴方向取多个三线性样本，LOD 按短边选最多 8N贵；但对地面、道路这种掠射角表面效果显著

7.5 实测：远处的地面

E9 渲染一块高 1 米视角、一直延伸到 300 米的棋盘格地面。参考图用 8×8=64 次超采样（每个子样本做 LOD0 双线性）近似"像素内的真实平均颜色"，然后比较各种过滤方式的误差和开销：

soft_raster.exe · E9

点采样 LOD0（无 mip）       0.3063    0.2152    0.3694          1.0      80.8%     0.00
双线性 LOD0（无 mip）       0.2210    0.0873    0.2913          4.0      93.7%     0.00

🔬 从输出里能读出什么
  • Mipmap 是降误差的第一功臣：从双线性到三线性，全图误差降为 40%，中距离降为 44%。
  • Mipmap 同时也是省带宽的功臣：每像素虽然读了 7.6 个 texel（比双线性多），但缓存命中率从 93.7% 升到 99.3%——真正打到显存的未命中次数反而更少。"开 Mipmap 会更慢"是错误的直觉。
  • 各向异性把误差再降到 1/3（0.087 → 0.026），平均 LOD 从 2.5 降到 0.7（用短边选 LOD，所以更清晰），代价是每像素读 39 个 texel、是三线性的 5 倍。真实硬件对此做了大量优化（按实际各向异性程度自适应取样数），桌面 GPU 上 16× 各向异性几乎免费，移动端则要慎重（常用 2×～4×，只对地面开）。
  • LOD Bias −2 "看起来更清楚"，误差却比三线性高 40%——它用更高分辨率的 Mip 去采样，等于又把高频放了回来。TAA/DLSS 这类时域方法会刻意使用负 LOD Bias，因为它们靠多帧抖动累积来去走样。

7.6 纹理缓存、压缩与格式

纹理采样的瓶颈通常不是计算，而是带宽和延迟。几个关键事实：

纹理缓存按块组织

texel 在显存中按 Tile / Morton（Z 序）排列，2D 上相邻的 texel 在内存里也相邻；缓存行一次取一小块（实测程序模拟为 4×4）。所以"屏幕上相邻像素采样纹理上相邻位置"时命中率极高——这依赖 Mipmap 和规则的 uv。

块压缩（BCn / ASTC / ETC2）

以 4×4（ASTC 可变）为块固定码率压缩，GPU 解压是硬件完成的、可随机访问。RGBA8 是 32 bpp，BC1/ETC2 RGB 是 4 bpp，ASTC 6×6 约 3.56 bpp——带宽直接降为 1/8～1/9。移动端统一用 ASTC。

sRGB 纹理

颜色贴图以 sRGB 存储（感知均匀，8 位够用），采样时硬件自动转成线性空间再插值和计算；法线、粗糙度、遮罩等"数据纹理"必须标记为线性，否则数值被错误地做了伽马变换。

依赖纹理读取

用一次采样的结果去算另一次采样的 uv（视差、扭曲特效）会让第二次采样无法提前发出，延迟隐藏能力下降；在 Warp 数少（寄存器多）时尤其明显。

⚠️ 面试易错
  • "Mipmap 是为了让远处的纹理更清楚"——错，Mipmap 让远处更模糊，它是为了消除走样和闪烁、提高缓存命中率。
  • "UI 也应该开 Mipmap"——不一定。UI 通常 1:1 显示，不会缩小，开 Mipmap 只会多占 33% 内存；但会被缩放显示的图标、世界空间 UI 应该开。
  • "纹理 Wrap 模式不影响 Mip"——图集（Atlas）里相邻的子图在低 Mip 会互相渗色，需要留出足够的 padding 或使用 Texture Array。

7.7 游戏实战：贴图预算与 Mip Streaming

  • Mip Streaming / 纹理流送：根据物体在屏幕上的大小只加载需要的 Mip 层级（例如远处的建筑只加载 256×256 及以下），内存可省一半以上。Unity 的 Mipmap Streaming、UE 的 Texture Streaming 都基于第 7.3 节的 LOD 估计。
  • MOBA 的地表：俯视 45°～60° 左右，各向异性需求没有第一/三人称游戏强，但地面贴图分辨率大、重复多，Mipmap + ASTC 必不可少；地表常用多层混合（Splat Map），每多一层就多一组采样。
  • 特效贴图：粒子常用小尺寸的序列帧图集，注意图集 padding 和 Mip 渗色；全屏扭曲/热浪是依赖纹理读取，移动端要控制使用范围。
本章小结
  • discard 推迟深度写入、写 SV_Depth 关闭 Early-Z——PS 的写法会反过来影响固定功能阶段。
  • 纹理放大要插值（双线性），缩小要先滤波（Mipmap），否则高频折叠成摩尔纹和闪烁。
  • LOD = log₂(像素脚印在纹理中的长边长度)，长度来自 2×2 Quad 求出的 uv 导数。
  • E9：三线性比无 Mip 误差降 60%、缓存命中 99%；16× 各向异性误差再降 70%，但取样数是 5 倍；负 LOD Bias 重新引入走样。
  • 块压缩（ASTC/BCn）把纹理带宽降到 1/8 左右；颜色贴图用 sRGB，数据贴图用线性。
自测：为什么非 2 的幂（NPOT）纹理在老设备上有限制？

Mip 链每级减半，NPOT 尺寸在逐级缩小时会出现奇数，需要定义取整规则和滤波方式；Wrap 寻址对 2 的幂可以用位与实现（实测程序里就是 x &= w-1）；部分压缩格式要求 4 的倍数。早期 GLES2 设备对 NPOT 纹理不支持 Mipmap 和 Repeat。现代硬件都支持，但 2 的幂仍是贴图制作的默认规范。

自测：同样的 Shader，换成更小的贴图为什么能明显变快？

有两种情况：①纹理被缩小显示时，更小的贴图意味着更少的未命中（虽然 Mip 已经在帮你选小层级，但若没开 Mipmap，效果就非常明显）；②纹理被放大显示时，小贴图更容易整体放进纹理缓存。这两种都说明该 Pass 是纹理带宽受限。如果换小贴图毫无变化，说明瓶颈在别处（ALU、顶点或 ROP）。这正是第 12 章"改变一个变量看帧时间"的定位思路。
