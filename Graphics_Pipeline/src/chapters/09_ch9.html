输出合并：模板、混合与抗锯齿

片元通过了所有测试，最后一步是和帧缓冲里已有的东西"合"在一起——这一步决定了半透明能不能画对、锯齿能不能消掉。

9.2 模板缓冲：给像素打标签

模板缓冲为每个像素存一个 8 位整数（通常与 24 位深度打包成 D24S8，或 D32F + S8）。模板测试把参考值与缓冲值按位掩码比较，并根据三种结果——模板失败 / 模板通过但深度失败 / 都通过——分别执行 Keep、Replace、Increment、Decrement、Invert、Zero 等操作。

效果做法
角色描边Pass 1 正常画角色并把模板写成 1；Pass 2 把角色沿法线外扩一点，只在模板 ≠ 1 的地方画描边色
遮挡显示（X-Ray / 透视轮廓）角色被墙挡住的部分显示一个半透明剪影：画角色时 ZTest Greater（只在被挡住时通过），并用模板防止同一像素被叠多次
UI 遮罩（Mask）先把遮罩形状写进模板，再只在模板匹配处画子元素；嵌套遮罩用递增的模板值
传送门 / 镜子门框区域写模板，再在模板区域内用另一个相机矩阵渲染门后的场景
延迟光照的光源体积用模板标记"被光源体积覆盖且在几何体前面"的像素，只对这些像素做光照（第 11 章）
阴影体（Shadow Volume）Depth-Fail（Carmack's Reverse）：正面深度失败 +1、背面深度失败 −1，模板非零即在阴影中
🎮 游戏实战：MOBA 里的模板

英雄走进草丛或被建筑挡住时显示轮廓/半透明剪影、选中目标的高亮描边、技能指示器只画在地面上（不画到英雄身上）——这些都是模板的典型用法。注意：模板值是全局共享的 8 位资源，引擎要统一分配位（例如 bit0～2 给描边、bit3 给 UI 遮罩、bit4 标记角色），否则不同系统会互相覆盖。

9.3 混合方程

混合把像素着色器输出的颜色（源，src）和帧缓冲中已有的颜色（目标，dst）合成：

9.4 半透明为什么必须排序

E11 在白色背景上依次叠加 3 层 alpha=0.5 的红、绿、蓝，穷举全部 6 种顺序：

soft_raster.exe · E11
白色背景上依次叠加 3 层 alpha=0.5 的 红/绿/蓝（Over 混合 src*a + dst*(1-a)）：
  顺序 R->G->B : Over 结果 (0.250, 0.375, 0.625)    Additive 结果 (1.30, 1.30, 1.30)
  顺序 R->B->G : Over 结果 (0.250, 0.625, 0.375)    Additive 结果 (1.30, 1.30, 1.30)
  顺序 G->R->B : Over 结果 (0.375, 0.250, 0.625)    Additive 结果 (1.30, 1.30, 1.30)
  顺序 G->B->R : Over 结果 (0.625, 0.250, 0.375)    Additive 结果 (1.30, 1.30, 1.30)
  顺序 B->R->G : Over 结果 (0.375, 0.625, 0.250)    Additive 结果 (1.30, 1.30, 1.30)
  顺序 B->G->R : Over 结果 (0.625, 0.375, 0.250)    Additive 结果 (1.30, 1.30, 1.30)
结论：Over 混合不满足交换律 -> 半透明必须排序；Additive 满足交换律 -> 粒子特效常用加法混合免排序。

Over 混合 dst' = a·src + (1−a)·dst 的含义是"src 盖在 dst 上面"，所以必须先画远的（dst）、后画近的（src）。半透明物体的标准做法：

  1. 先画完所有不透明物体（写深度）；
  2. 半透明物体从后往前排序，开启深度测试（被不透明物体挡住的不画）、关闭深度写入（否则近处的半透明会把后画的、更远的半透明挡掉——但我们已经排过序了，这种情况本不该发生；关闭写入是为了让排序不完美时也不至于"消失"）。
⚠️ 面试易错：按物体排序也不完全对

引擎按物体中心到相机的距离排序，但物体之间可能互相穿插（两片交叉的玻璃），或者一个物体自身有多层（一个半透明的球，前表面和后表面）——这些情况下物体级排序必然有错。常见缓解手段：自身多层的模型先画背面再画正面（Cull Front 再 Cull Back 两个 Pass）；或先用一个 Pass 只写深度、再用 LEQUAL 只画最前面一层（"半透明但只显示最外层"）；彻底解决需要 OIT。

顺序无关透明（OIT）

深度剥离 Depth Peeling

每个 Pass 剥出"下一层"最近的表面，N 层需要 N 个 Pass。结果精确但开销与层数成正比。

逐像素链表 / A-Buffer

每个像素用原子操作把所有片元追加到链表，最后排序合成。精确，显存不可控。

加权混合 WBOIT

用与深度相关的权重做可交换的加权平均，一个 Pass 完成。近似，但对烟雾、粒子足够好，移动端也可用。

Moment / MLAB / 等

用矩或固定数量的片上层数近似透射率，在质量和成本之间折中；移动端可借助 Pixel Local Storage 实现。

9.5 预乘 Alpha：消灭"黑边"

贴图里完全透明的像素颜色通常是任意值（常见的是黑色）。双线性过滤时，不透明像素和透明像素的颜色会被先插值再按 alpha 混合，透明像素的黑色就渗进了边缘：

soft_raster.exe · E11 双线性过滤 + 混合
双线性过滤的"黑边"：texel A=不透明白(1,1,1,a=1)，texel B=全透明但颜色为黑(0,0,0,a=0)，在两者正中采样，背景为绿(0,1,0)
  直通 Alpha：过滤后 (0.50,0.50,0.50,a=0.50) -> 混合结果 (0.250, 0.750, 0.250)   <-- 偏暗，出现黑边
  预乘 Alpha：过滤后 (0.50,0.50,0.50,a=0.50) -> 混合结果 (0.500, 1.000, 0.500)   <-- 正确：白与绿各半

直通（Straight）Alpha 下，过滤后的颜色 0.5 代表的是"一半白一半黑"，再乘以 alpha 0.5 混合，等于把黑色也算了进去。预乘（Premultiplied）Alpha 把颜色事先乘好 alpha（透明像素的颜色自然是 0），过滤时颜色和 alpha 按同样的比例变化，结果在数学上就是正确的。

  • 预乘后混合因子变成 One, OneMinusSrcAlpha，还能用同一个混合状态同时表达 Over 和 Additive（alpha=0 时就是纯加法）——粒子系统可以把两种粒子合进一个批次。
  • Mipmap 生成、缩放图片、多层合成也应该在预乘空间里做。

9.6 抗锯齿：三种走样，四种方案

"锯齿"其实是几种不同的走样：

几何走样

三角形边缘：每个像素只看中心一个点是否被覆盖（第 5 章）。

着色走样

像素内部：高频的高光、法线贴图、细条纹在每个像素只算一次时闪烁。

纹理走样

纹理缩小时（第 7 章），由 Mipmap/各向异性解决。

方案做法解决代价
SSAA（超采样）以 N 倍分辨率渲染再降采样；每个样本都跑 PS几何 + 着色PS、带宽、显存全部 ×N
MSAA（多重采样）每像素 N 个覆盖/深度样本，PS 只跑一次，结果写入所有被覆盖的样本；最后 Resolve 平均几何（边缘）深度/颜色存储 ×N；PS 几乎不变；对着色走样无效
FXAA / SMAA（后处理）在最终图像上检测高对比度边缘并沿边方向模糊几何（部分）很便宜；会糊掉细节文字和纹理；时间上不稳定
TAA（时域）每帧对投影矩阵做亚像素抖动，用运动矢量把历史帧重投影后与当前帧混合几何 + 着色 + 部分纹理需要运动矢量；会产生拖影/鬼影，需要邻域裁剪；画面偏软

E10 用一个高频条纹着色的场景（含一个细长条），与 256 样本的参考图比较边缘像素和内部像素的误差：

🔬 从输出里能读出什么
  • 纯色几何（最后一列）上，MSAA 4× 与 SSAA 4× 的边缘误差完全相同（0.1063）——对几何走样，两者等效；而 MSAA 的 PS 执行次数只比无 AA 多 5%（4946 vs 4705，多出来的是只被部分样本覆盖、但中心不在三角形内的边缘像素），SSAA 则是 4 倍。
  • 内部着色走样 MSAA 毫无改善（0.1683 与无 AA 相同），SSAA 降到 0.0067。这就是"MSAA 治不了高光闪烁和法线贴图闪烁"的直接证据。
  • 两者的深度/颜色样本数都是 4 倍（18810）：MSAA 省的是着色，不省存储和带宽——在桌面 IMR 上这意味着 4 倍的帧缓冲带宽（第 10 章 E12：IMR 下 MSAA 4× 的流量是 TBR 的 134 倍）。
🧠 深入：MSAA 的几个细节
  • 采样点位置：4× 用旋转栅格（实测程序里的 (-2,-6),(6,-2),(-6,2),(2,6)/16），让接近水平和竖直的边也能得到 4 级灰度。
  • PS 在哪里求值：默认在像素中心，即使中心不在三角形内（外插）；用 centroid 改为在被覆盖样本的重心处求值。
  • Alpha To Coverage：把 PS 输出的 alpha 转成覆盖掩码（alpha=0.5 → 覆盖 2 个样本），让 Alpha Test 的树叶边缘也能被 MSAA 平滑，且不需要排序。
  • 延迟渲染与 MSAA 不兼容：G-Buffer 要按样本存储，带宽和显存爆炸；这是延迟渲染普遍用 TAA 的原因之一（第 11 章）。
🎮 游戏实战：移动端 MOBA 选哪种 AA

移动端 TBR 上 MSAA 很便宜：多重采样的颜色和深度只存在片上 Tile 内存里，Resolve 也在片上完成，只写回最终的 1× 结果（第 10 章）。所以前向渲染的手游通常首选 MSAA 2×/4×，并把 MSAA 渲染目标设为 memoryless（不分配系统内存）。注意如果中途需要把颜色或深度"拷出来"给后处理用（比如读深度做软粒子），就会触发 Resolve + 写回，MSAA 的优势就没了。TAA 在移动端则要考虑运动矢量 Pass 的开销和快速镜头移动下的拖影。

本章小结
  • 输出合并顺序：Scissor → 模板 → 深度 → 混合 → 写掩码（硬件会把模板/深度尽量提前）。
  • 模板缓冲是 8 位"像素标签"：描边、遮挡剪影、UI 遮罩、传送门、光源体积；引擎要统一分配模板位。
  • Over 混合不满足交换律（E11：6 种顺序 6 种颜色），半透明必须从后往前、开深度测试、关深度写入；加法和乘法混合可交换，可免排序。
  • 预乘 Alpha 让过滤和混合在数学上一致，消除黑边，还能把 Over 和 Additive 合并成一种混合状态。
  • E10：MSAA 4× 对几何走样等效于 SSAA 4×，PS 只多 5%；但对着色走样无效，且存储/带宽是 4 倍。
自测：UI 为什么是移动端 Overdraw 的大户？怎么优化？

UI 几乎全是半透明（圆角、阴影、渐隐），无法利用深度测试剔除，而且常常是全屏面板层层叠加，每层都要读写帧缓冲。优化：全屏不透明面板打开时关闭下层 UI 和 3D 场景的渲染；图片尽量裁掉透明区域（用多边形网格代替四边形，减少透明像素）；合并图集减少批次；静态 UI 缓存成一张 RT；避免大面积的全透明点击区域仍参与渲染。

自测：为什么开了 MSAA，角色身上的高光还是在闪？

MSAA 只对三角形覆盖做多次采样，像素着色仍然每像素一次，所以着色走样（高光、法线贴图、细节纹理的高频变化）完全不受影响。解决办法是从源头降低着色频率：法线贴图做 Mip 并配合 Toksvig / LEAN 之类的方法调整粗糙度（"镜面抗锯齿"），或者用 TAA。
