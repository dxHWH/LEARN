CHAPTER 03

投影与裁剪

投影矩阵把"距离"藏进 w；裁剪必须赶在除以 w 之前完成。

本章目标
  • 能从相似三角形出发推导透视投影矩阵，说清每一项的来历
  • 理解 NDC 深度是距离的倒数的线性函数——这是透视校正和深度精度问题的共同根源
  • 说清为什么要在齐次裁剪空间裁剪，以及 w<0、w=0 会发生什么
  • 了解保护带（Guard Band）：为什么 GPU 实际上几乎只裁近平面
  • 掌握 D3D / OpenGL / Vulkan / Metal 在 NDC 和视口上的差异

3.1 视锥体：正交投影与透视投影

3.2 推导透视投影矩阵

在观察空间里，相机在原点、看向 −Z。一个点 (x, y, z) 投影到距离为 n 的近平面上，由相似三角形：

xproj = n · x / (−z)　　　yproj = n · y / (−z)

除以 −z 不是线性运算，矩阵做不到。办法是：让矩阵输出 w = −z，把除法推迟给硬件。所以投影矩阵的第 4 行是 (0, 0, −1, 0)。

x 和 y 再乘一个缩放，使视野边缘落到 ±1：设垂直视场角为 fovy、宽高比为 aspect，令 t = 1 / tan(fovy/2)，则第 1、2 行是 (t/aspect, 0, 0, 0) 和 (0, t, 0, 0)。

最后是 z。我们也需要深度用于遮挡判断，而且希望它在除以 w 之后落在固定区间。z 只能写成 zclip = A·z + B（第 3 行是 (0,0,A,B)），于是：

zndc = (A·z + B) / (−z) = −A − B / z　　令 z=−n ⇒ 0，z=−f ⇒ 1（D3D 约定）

解这两个方程得 A = f/(n−f)，B = n·f/(n−f)。整理得到右手系、深度范围 [0,1] 的透视矩阵（实测程序 perspective() 的 DM_D3D 分支）：

P = ⎡ t/aspect　0　　0　　　0　　⎤
　　⎢ 0　　　　t　　0　　　0　　⎥
　　⎢ 0　　　　0　 f/(n−f)　 nf/(n−f) ⎥
　　⎣ 0　　　　0　 −1　　　　0　　⎦
static M4 perspective(float fovyDeg, float aspect, float n, float f, int mode) { M4 r{}; float t = 1.f / tanf(fovyDeg * (float)M_PI / 360.f); r.m[0][0] = t / aspect; r.m[1][1] = t; r.m[3][2] = -1; // w_clip = -z_view switch (mode) { case DM_D3D: r.m[2][2] = f / (n - f); r.m[2][3] = n * f / (n - f); break; // near->0, far->1 case DM_REV: r.m[2][2] = n / (f - n); r.m[2][3] = n * f / (f - n); break; // near->1, far->0 case DM_GL: r.m[2][2] = (f + n) / (n - f); r.m[2][3] = 2 * f * n / (n - f); break; // [-1,1] case DM_REVINF: r.m[2][2] = 0; r.m[2][3] = n; break; // far->∞，z_ndc = n / d } return r; }

3.3 一个关键事实：NDC 深度是"距离倒数"的线性函数

把上面的 zndc 换成距离 d = −z：

zndc(d) = −A + B/d　＝　a + b · (1/d)

深度值和 1/d 成线性关系，而不是和 d 成线性关系。这个看似不起眼的事实，在后面会被引用三次：

① 深度可以在屏幕空间线性插值

在屏幕空间里，1/w 是线性变化的（第 6 章证明），所以 zndc 也是。硬件可以直接用重心坐标线性插值深度，不需要透视校正。

② 属性插值必须做透视校正

反过来，uv、颜色这些属性是在三维空间里线性分布的，在屏幕空间就不是线性的，必须借助 1/w 校正（第 6 章 E5）。

③ 深度精度极不均匀

1/d 在近处变化剧烈、远处几乎不变，深度值大量集中在近平面附近。E6 实测：near=0.1 时，一半的深度值花在了前 0.2 米（第 8 章）。

3.4 为什么必须在除以 w 之前裁剪

直觉上，先除以 w 得到 NDC，再把超出 [−1,1] 的部分切掉，似乎更简单。但这在有顶点位于相机背后时会出大问题：

  • 相机背后的点 z>0，于是 w = −z < 0。除以负数会让 x、y 变号——点被"翻"到屏幕另一侧。
  • 恰好在相机平面上的点 w = 0，除法直接得到无穷大。

实测程序 E2 构造了这样一个三角形：A、B 在相机前方 2 米，C 在相机背后 1 米（想象一块从你脚下延伸到前方的地面）：

实际光栅化：输入 1 个三角形，被裁剪 1 个，送入光栅化 2 个，覆盖 38760 个像素（地面从脚下一直铺到远处）。

在齐次空间里，"点在视锥内"可以写成 6 个不需要除法的不等式：

−w ≤ x ≤ w　　−w ≤ y ≤ w　　0 ≤ z ≤ w（D3D/Vulkan/Metal）或 −w ≤ z ≤ w（OpenGL）

每个不等式都是 4D 空间里的一个"平面"，裁剪就是用 Sutherland–Hodgman 算法依次用平面切多边形：保留在内侧的顶点，对跨越平面的边按有符号距离插值出新顶点。一个三角形被一个平面切，最多变成四边形；被 6 个平面切，最多变成 9 边形，再拆成扇形三角形送去光栅化。

static float nearDist(int mode, const V4& c) { // 有符号距离：>=0 在内侧 switch (mode) { case DM_D3D: return c.z; // 0 <= z case DM_GL: return c.z + c.w; // -w <= z default: return c.w - c.z; } // Reversed-Z：z <= w } static int clipNear(const State& s, const VOut* in, VOut* out, int na) { int n = 0; for (int i = 0; i < 3; i++) { const VOut& a = in[i]; const VOut& b = in[(i + 1) % 3]; float da = nearDist(s.clip, a.c), db = nearDist(s.clip, b.c); if (da >= 0) out[n++] = a; // a 在内侧，保留 if ((da >= 0) != (db >= 0)) out[n++] = lerpV(a, b, da / (da - db), na); // 边跨越平面，插出交点 } return n; // 0、3 或 4 个顶点 }
🧠 深入：为什么在 4D 里线性插值是对的

裁剪空间到观察空间之间只差一个线性变换（投影矩阵可逆），所以观察空间里的直线在裁剪空间里仍是直线，在裁剪空间里对 (x,y,z,w) 和所有属性按同一个 t 线性插值，得到的就是三维空间中那条边上的真实点。一旦除以 w，这条性质就没有了——这又是"必须在除法之前裁剪"的一个理由。

3.5 保护带：GPU 其实很少真的裁 x/y

注意 E2 输出里的 P2：屏幕坐标 (2450, 1739)，远远超出 640×360 的屏幕。实测程序并没有对 x/y 平面做裁剪，而是让光栅化器直接遍历被钳制到屏幕范围内的包围盒——超出屏幕的像素根本不会被访问。

真实 GPU 也是这么做的，叫保护带（Guard Band）：光栅化器的定点坐标范围远大于屏幕（例如 ±32K 像素），只要三角形落在这个大范围内，就不需要真正生成新顶点，靠 Scissor 和包围盒丢掉屏幕外的部分即可。真正必须裁剪的只有：

  • 近平面：因为 w≤0 会导致除法翻转或除零，保护带帮不了；
  • 超出保护带范围的极大三角形（定点数会溢出）；
  • 远平面（可选，D3D 有 DepthClipEnable 开关；关掉时叫"深度钳制"，阴影渲染常用来避免投射体被远/近平面切掉）。
✅ 面试答法

问"裁剪是怎么做的"，可以分三层答：①在哪：在齐次裁剪空间、透视除法之前；②为什么：避免 w≤0 导致的翻转和除零，且 4D 空间插值保持线性；③实际硬件：x/y 依赖保护带 + 包围盒钳制，真正生成新顶点的只有近平面（以及超出保护带的情况），因为裁剪会改变图元数量、打断流水，硬件尽量避免。

3.6 视口变换与各 API 的差异

透视除法后得到 NDC，再由视口变换映射到像素坐标。以 W×H 的屏幕、左上角为原点为例：

xscreen = (xndc + 1) / 2 · W　　yscreen = (1 − yndc) / 2 · H　　depth = zndc（D3D）或 (zndc+1)/2（GL）
APINDC 深度范围NDC y 方向屏幕原点备注
Direct3D 11/12[0, 1]向上左上视口变换里翻转 y
OpenGL[−1, 1]向上左下可用 glClipControl 改成 [0,1]（GL 4.5）
Vulkan[0, 1]向下左上从 GL 移植要翻 y（负视口高度或改投影矩阵）
Metal[0, 1]向上左上纹理坐标原点在左上
⚠️ 面试易错：渲染到纹理后画面上下颠倒

这是跨平台引擎最常见的问题之一：GL 的纹理坐标原点在左下，D3D/Metal/Vulkan 在左上。Unity 用 _ProjectionParams.x 和 UNITY_UV_STARTS_AT_TOP 宏来处理；自己写引擎时要统一一个约定，并在"采样渲染目标"这条路径上集中做翻转。

3.7 游戏实战：近平面和 FOV 怎么设

近平面不能太小

深度精度主要由 near 决定（第 8 章）：E6 实测中 near 从 0.1 改成 1.0，1000 米处的 Z-Fighting 从 30.5% 降到 0%。第一人称游戏常设 0.01～0.1，第三人称/俯视角可以设到 0.3～1。

近平面不能太大

太大时相机贴近墙壁或角色会被"切开"（穿模）。第一人称的手臂/武器经常用单独的相机或单独的投影矩阵渲染。

宽屏适配

固定垂直 FOV、让水平 FOV 随宽高比变大（Hor+），宽屏玩家能看到更多。MOBA 这类竞技游戏会限制最大视野，避免超宽屏获得信息优势。

正交相机

UI、小地图、平行光阴影都用正交投影。正交投影 w 恒为 1，深度与距离线性相关，精度均匀，不需要透视校正。

本章小结
  • 透视投影矩阵用第 4 行 (0,0,−1,0) 把距离放进 w，除法由硬件完成；x、y 由 fovy 和 aspect 缩放，z 的两个系数由"near→0、far→1"解出。
  • NDC 深度是 1/d 的线性函数：所以深度能在屏幕空间线性插值、属性插值需要透视校正、深度精度集中在近处。
  • 裁剪必须在齐次空间、除以 w 之前：避免 w<0 翻转和 w=0 除零；4D 中线性插值仍正确。
  • 硬件依赖保护带，x/y 基本不真正裁剪，近平面才必须裁。
  • D3D/Vulkan/Metal 深度 [0,1]，GL 默认 [−1,1]；Vulkan NDC y 向下。
自测：正交投影需要透视除法吗？深度精度有什么特点？

正交投影矩阵的第 4 行是 (0,0,0,1)，w 恒为 1，透视除法相当于什么都没做；深度与观察空间 z 呈线性关系，精度在 near 到 far 之间均匀分布。所以平行光阴影贴图通常用正交投影，精度问题比透视的聚光灯阴影小，主要矛盾是"覆盖范围 vs 分辨率"（级联阴影 CSM 就是为此而生）。

自测：一个三角形三个顶点都在视锥外，它一定看不见吗？

不一定。三个顶点分别在左、右、上三个平面外侧时，三角形的中间部分仍可能横穿视锥。只有三个顶点都在同一个平面外侧时才能直接剔除（这就是实测程序里 clipOut 的判断条件：三个顶点都在近平面外）。视锥剔除包围盒时也是同理。
