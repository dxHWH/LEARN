CHAPTER 08

深度与可见性：Z-Buffer、Early-Z 与 Reversed-Z

深度缓冲回答"谁在前面"；Early-Z 决定"被挡住的像素要不要白算"；深度格式决定"远处还分不分得清前后"。

本章目标
  • 理解 Z-Buffer 算法，以及它为什么让不透明物体可以"任意顺序绘制"
  • 说清 Early-Z 的生效条件和失效条件，理解 Hi-Z 的作用
  • 用实测数据比较随机顺序、从前往后、从后往前、Z-Prepass 四种画法
  • 理解深度精度为什么集中在近处、Z-Fighting 的成因，以及 Reversed-Z 为什么能"免费"大幅提升精度

8.1 Z-Buffer：为每个像素记住"目前最近的距离"

深度缓冲为每个像素（MSAA 下为每个采样点）存一个深度值。每个片元到达时，拿它的深度与缓冲中的值比较：通过则写入颜色（和深度），不通过则丢弃。

优点：与绘制顺序无关

不透明物体以任意顺序绘制，最终结果都正确（深度相等的情况除外）。这让引擎可以按材质排序来减少状态切换，而不必严格按距离排序。

局限：只能记住一层

每个像素只存最近的一个深度，无法处理半透明（需要知道多层）。所以半透明物体必须单独排序绘制，且通常关闭深度写入（第 9 章）。

深度比较函数可配置：LESS（默认）、LEQUAL、GREATER（Reversed-Z 用）、EQUAL（Z-Prepass 后的着色 Pass 用）、ALWAYS（UI、全屏后处理）。深度写入也可以单独开关（ZWrite On/Off）。

8.2 Early-Z：在着色之前就丢掉被挡住的片元

按照逻辑管线，深度测试在像素着色器之后（输出合并阶段）。但如果一个片元注定被挡住，它的像素着色就白做了。现代 GPU 会尽量把深度测试提前到像素着色之前，这就是 Early-Z：

Hi-Z（Hierarchical Z）是 Early-Z 的粗粒度版本：硬件为每个 Tile（如 8×8 像素）维护一个保守的最远深度。三角形光栅化到某个 Tile 时，如果它在这个 Tile 内的最近深度都比 Tile 的最远深度还远，整个 Tile 直接跳过，连逐像素的深度读取都省了。

8.3 实测：同一批不透明方块，四种画法

E7 在 640×360 的屏幕上画 400 个随机大小、随机深度的不透明矩形（平均 Overdraw 约 27 层），像素着色器是一段 48 次循环的"重"计算。分别用五种方式绘制：

soft_raster.exe · E7
画法                             光栅片元   PS执行 平均overdraw 深度剔除   耗时ms
Late-Z（先着色后测试） 随机顺序    5992422    5992422      26.69    5254439     3763.7
  （屏幕覆盖像素 224506 / 230400）
Early-Z 随机顺序                  5992422     737983       3.29    5254439      510.8
Early-Z 从前往后排序            5992422     224506       1.00    5767916      190.8
Early-Z 从后往前排序            5992422    5992422      26.69          0     3771.3
Z-Prepass + EQUAL 着色             11984844     224506       1.00    5767916      248.2
🔬 从输出里能读出什么
  • Early-Z 对随机顺序就已经很有效：PS 执行从 599 万次降到 74 万次（−88%），耗时从 3.8 秒降到 0.5 秒。因为随机顺序下，一个被 N 层覆盖的像素，"新片元比当前所有已画片元都近"的期望次数是调和级数 1+½+⅓+…+1/N ≈ ln N + 0.58（N=27 时约 3.9）；各像素实际层数不一，平均下来就是实测的 3.29。
  • 从前往后排序让 PS 执行次数恰好等于可见像素数（224506，Overdraw 1.00），耗时再降到 191ms，是 Late-Z 的 1/20。
  • 从后往前是 Early-Z 的最坏情况：每一层都"更近"，全部通过——和关掉 Early-Z 一样慢。半透明必须从后往前画，所以半透明 Overdraw 无法靠深度测试省掉（第 9 章）。
  • Z-Prepass：先用一个极简的 Pass 只写深度（光栅化片元翻倍到 1198 万），再用 EQUAL 测试做着色，PS 同样只跑 224506 次，耗时 248ms。它不依赖排序，代价是多一遍几何处理。
✅ Z-Prepass 值不值？

值得的情况：像素着色很重（复杂 PBR、多光源）、场景 Overdraw 高、很难精确排序（大物体互相穿插）；同时深度缓冲还能被后续的 SSAO、屏幕空间反射、软粒子等复用。不值得的情况：顶点很多而像素着色便宜（多一遍几何得不偿失）；移动端 TBDR：硬件自带隐藏面消除（HSR/FPK，第 10 章），Prepass 往往是纯开销。

8.4 深度精度：为什么远处会"打架"

第 3 章得出：标准 D3D 深度 z = a + b/d，即深度值与距离的倒数线性相关。E6 用 near=0.1、far=10000 计算各距离处"深度缓冲中相邻两个可表示值对应的世界距离差"（越小越好）：

距离 d   标准Z float  标准Z 24bit       GL float Reversed float  Rev 无限远

10.0        5.96044e-05m   5.96044e-05m   2.98021e-05m   9.31313e-07m   9.31323e-07m
100.0        0.00596048m    0.00596048m    0.00298033m   1.16414e-05m   1.16415e-05m
1000.0         0.596371m      0.596371m      0.298096m   7.27588e-05m   7.27596e-05m
5000.0          14.9254m       14.9254m       7.45157m   0.000227371m   0.000454747m
9000.0           48.353m        48.353m       24.2414m   9.20854e-05m   0.000736691m
标准Z 的非线性：z=0.5 对应 d=0.2000m，z=0.9 对应 d=0.9999m，z=0.99 对应 d=9.990m —— 一半的深度值花在了前 0.20 米

1000 米处标准 Z 只能分辨 0.6 米的前后差——两个相距 0.3 米的面在那里就会随机地"你压我、我压你"，这就是 Z-Fighting。

Reversed-Z：把 near 映射到 1、far 映射到 0

为什么仅仅反过来就能好这么多？关键在于两个"不均匀"恰好可以互相抵消：

🔬 从输出里能读出什么
  • 标准 Z 下 float 和 24 位定点的结果完全一样：在 [0.5, 1) 区间里 float 的间隔 2⁻²⁴ 恰好与 24 位定点相同，用 float 存标准 Z 是浪费。
  • 把 near 从 0.1 调到 1.0，1000 米处的错误从 30.5% 降到 0——near 对精度的影响远大于 far（深度误差近似与 d²/near 成正比）。
  • OpenGL 的 [−1,1] 映射比 D3D 还差一点：中间的 0 落在近处，远处挤在 1 附近，且 (z+1)/2 的转换又损失了精度。glClipControl(GL_ZERO_TO_ONE) 才能在 GL 上用好 Reversed-Z。
  • Reversed-Z 在 8 公里处仍然零错误；"无限远平面"版本（far→∞）也同样好，所以用 Reversed-Z 时甚至可以不设远平面。

🎮 游戏实战：不透明物体的绘制顺序

引擎通常按"渲染队列 → 材质/Shader → 距离"排序：不透明物体大致从前往后（利用 Early-Z）但优先合并相同材质（减少 SetPass）；天空盒放在不透明物体之后、深度设为最远（只填充没被挡住的像素）；Alpha Test 物体（草、树叶）放在纯不透明之后，避免它们推迟深度写入影响其他物体的 Early-Z。MOBA 的俯视角下，地面会被英雄、建筑、草丛挡住一部分，所以"先画英雄和建筑、最后画大地面"能明显减少地面的着色量——E13 的主 Pass 就这么做了，地面有 8215 个片元被 Early-Z 剔除。

本章小结
  • Z-Buffer 让不透明物体与绘制顺序无关，但只能记住一层，处理不了半透明。
  • Early-Z 把深度测试提前到 PS 之前；写深度、discard、Alpha To Coverage、UAV 写入会让它失效或受限；Hi-Z 以 Tile 为单位粗剔除。
  • E7：Early-Z 随机顺序 PS −88%；从前往后 PS 次数 = 可见像素数（20 倍提速）；从后往前等于没有 Early-Z；Z-Prepass 不依赖排序，代价是两遍几何。
  • 标准 Z 精度集中在近处：near=0.1 时一半深度值用于前 0.2 米；1000 米处只能分辨 0.6 米。
  • Reversed-Z + 浮点深度让投影的不均匀与浮点的不均匀互相抵消：E6 中 8 公里内零 Z-Fighting。24 位定点深度反转无效。
  • 修 Z-Fighting 的第一选择是增大 near。
自测：Alpha Test 的物体为什么会影响 Early-Z？应该怎么画？

像素是否被丢弃要等 PS 执行完才知道，所以硬件不能在 PS 之前就把深度写进去（否则被 discard 的像素也挡住了后面的东西）。它仍然可以"早测"（用已有深度剔除自己），但"早写"被推迟，导致后续物体的 Early-Z 效果变差；在 TBDR 上更会打断隐藏面消除。做法：把 Alpha Test 物体放在不透明物体之后绘制；或者对它们做一个只写深度的 Prepass，然后着色 Pass 用 EQUAL 测试且不再 discard。

自测：深度缓冲里存的是线性深度吗？后处理要用线性深度怎么办？

不是，存的是 z/w（与 1/d 线性相关）。后处理（雾、景深、SSAO）需要线性深度时要做反变换：标准 D3D 下 d = n·f / (f − z·(f − n))，Reversed-Z 下 d = n·f / (z·(f − n) + n)。Unity 的 LinearEyeDepth()、UE 的 ConvertFromDeviceZ() 就是这个公式；实测程序 E6 的 dStd/dRev 函数也是。
