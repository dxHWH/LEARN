CHAPTER 06

属性插值：重心坐标、透视校正与 2×2 Quad

顶点只有三个，像素有成百上千个。每个像素的 uv、法线、颜色都要从三个顶点"插"出来——而屏幕空间里的直线插值是错的。

本章目标
  • 理解重心坐标及其与边函数的关系
  • 证明"1/w 在屏幕空间线性"，推导透视校正插值公式，并用实测看清不校正的后果
  • 知道 nointerpolation、noperspective、centroid 这些插值修饰符的用途
  • 理解像素着色器为什么按 2×2 Quad 执行、ddx/ddy 怎么来、Helper Lane 是什么
  • 用实测数据说明小三角形为什么"贵"

6.1 重心坐标

三角形内任一点 p 都可以唯一写成三个顶点的加权和：

p = λ₀·v₀ + λ₁·v₁ + λ₂·v₂，　λ₀ + λ₁ + λ₂ = 1，　内部时 λᵢ ≥ 0

λᵢ 就是 p 与"对边"围成的小三角形面积占总面积的比例。而第 5 章的边函数恰好是 2 倍有符号面积，所以光栅化时重心坐标几乎是免费的：

λ₀ = E₁₂(p) / 2A，　λ₁ = E₂₀(p) / 2A，　λ₂ = E₀₁(p) / 2A

有了重心坐标，任何顶点属性都可以插值：attr(p) = λ₀·a₀ + λ₁·a₁ + λ₂·a₂。问题在于：这里的 λ 是在屏幕空间算的，而属性是在三维空间里沿三角形表面线性分布的。

6.2 为什么屏幕空间线性插值是错的

推导：什么在屏幕空间里是线性的

考虑观察空间中一条线段，端点的齐次裁剪坐标为 c₀、c₁（w 分别为 w₀、w₁）。线段上的点 c(t) = (1−t)c₀ + t·c₁，它的 w 也是 w(t) = (1−t)w₀ + t·w₁。屏幕坐标是 x/w，设屏幕上的插值参数为 s：

xs(t) = [(1−t)x₀ + t·x₁] / [(1−t)w₀ + t·w₁]　＝　(1−s)·(x₀/w₀) + s·(x₁/w₁)

解出 s 与 t 的关系，可以得到一个关键结论（把 s 看成屏幕上的线性参数）：

1/w(s) = (1−s)·(1/w₀) + s·(1/w₁)　　a/w(s) = (1−s)·(a₀/w₀) + s·(a₁/w₁)

即：1/w 和 a/w 在屏幕空间是线性的，a 本身不是。所以透视校正插值的做法是：插值 a/w 和 1/w，再相除：

a(p) = ( Σ λᵢ · aᵢ / wᵢ ) / ( Σ λᵢ / wᵢ )
void interp(float px, float py, float* out) const { // 屏幕空间重心坐标：三个边函数 / 总面积 float e0 = (sx[2] - sx[1]) * (py - sy[1]) - (sy[2] - sy[1]) * (px - sx[1]); float e1 = (sx[0] - sx[2]) * (py - sy[2]) - (sy[0] - sy[2]) * (px - sx[2]); float e2 = (sx[1] - sx[0]) * (py - sy[0]) - (sy[1] - sy[0]) * (px - sx[0]); float s = e0 + e1 + e2; float b0 = e0 / s, b1 = e1 / s, b2 = e2 / s; if (persp) { // 透视校正：权重乘以各顶点的 1/w，再归一化 float w0 = b0 * iw[0], w1 = b1 * iw[1], w2 = b2 * iw[2]; float r = 1.f / (w0 + w1 + w2); b0 = w0 * r; b1 = w1 * r; b2 = w2 * r; } for (int i = 0; i < na; i++) out[i] = b0 * a[0][i] + b1 * a[1][i] + b2 * a[2][i]; }
🧠 深入：为什么深度不需要透视校正

zndc = zclip/w 本身就是"某个量除以 w"的形式，而 zclip 在三维中是线性的，所以 zndc 和 a/w 一样在屏幕空间线性。硬件直接用屏幕空间重心坐标插值深度（实测程序里 zs[si] 就是这样算的）。这也是"深度缓冲存的是 z/w 而不是 z"的根本原因：为了能线性插值，而代价是第 8 章的精度不均匀。

6.3 实测：不做透视校正会怎样

E5 渲染一块从相机脚下延伸到 60 米外的地面（棋盘格纹理），对比三种方式，并对每个像素用射线与地面求交得到 uv 的解析真值来计算误差：

仿射插值，地面细分 16x16=512 三角形       0.3785       0.6835           0.4684

🔬 从输出里能读出什么
  • 只有 2 个大三角形时，仿射插值的平均 uv 误差高达 17 个纹理重复——这块地面的 uv 范围是 24×24，几乎完全错了。
  • 细分到 512 个三角形，误差降到 0.38（不到一格）：细分能缓解但不能消除，因为误差和三角形在深度方向上的跨度成正比。这正是 PS1 时代的补救办法——地面和墙壁都切得很碎。
  • 透视校正的结果与射线求交的解析真值在第 4 位小数上一致，最大误差 0.0066 来自 float 精度和像素中心的离散化。

6.5 2×2 Quad 与屏幕空间导数

像素着色器里经常需要知道"一个属性在屏幕上变化得有多快"——最典型的就是纹理采样选 Mip 层级（第 7 章）：uv 在相邻像素间变化越大，说明纹理被缩小得越厉害，越应该用更模糊的 Mip。

GPU 的做法简单粗暴：像素着色器永远以 2×2 的像素块（Quad）为单位执行，四个像素同时跑同一段代码，于是任何变量的导数都可以用 Quad 内相邻像素的差分得到：

实测程序没有真的按 Quad 并行执行，而是在需要导数时直接用三角形的插值函数在 (x+1, y) 和 (x, y+1) 处再求一次值（效果等价于 Quad 差分的解析版本）：

float a1[MAXA], a2[MAXA]; f.t->interp(f.px + 1, f.py, a1); // 右边一个像素处的属性（≈ Quad 里的邻居） f.t->interp(f.px, f.py + 1, a2); // 下边一个像素处的属性 float dudx = a1[6] - f.a[6], dvdx = a1[7] - f.a[7]; // ddx(uv) float dudy = a2[6] - f.a[6], dvdy = a2[7] - f.a[7]; // ddy(uv)

🔬 从输出里能读出什么
  • 面积 0.5 像素的三角形，一半（1511/3000）一个像素都没覆盖——它们的顶点着色、三角形设置全部白做；覆盖到像素的那些，每覆盖 1 个像素要跑 4 个通道（效率 25%）。

🎮 游戏实战：Micro-Triangle 问题

远处的高模角色、过度细分的地形、密集的毛发卡片都会产生大量 1～2 像素的三角形。对策：① LOD：保证三角形在屏幕上至少有约 10 像素量级的面积；② 不要对远处开曲面细分；③ UE5 Nanite 的做法是对小三角形改用计算着色器软光栅，绕过硬件的 Quad 打包——这在本章的数据下就很好理解了。

6.7 交互实验：透视校正插值

🧪 实验 2 · 仿射插值 vs 透视校正

一块贴了棋盘格纹理的正方形平面，绕水平轴倾斜。左边在屏幕空间直接线性插值 uv，右边做透视校正。增大倾角或减少细分，观察左图的"折痕"。

本章小结
  • 重心坐标 = 边函数 / 2 倍面积，光栅化时顺手得到。
  • 透视投影下 1/w 与 a/w 在屏幕空间线性，a 本身不是；透视校正：a = Σλᵢaᵢ/wᵢ ÷ Σλᵢ/wᵢ。
  • 深度 z/w 本身是"除以 w"的形式，可直接线性插值。
  • E5：不校正时平均 uv 误差 17 个重复；细分 512 份降到 0.38 但仍有折线；校正后与解析真值一致。
  • PS 按 2×2 Quad 执行，导数由 Quad 内差分得到；三角形外的像素作为 Helper Lane 陪跑。
  • E8：面积 1 像素的三角形 Quad 效率 27%，细长三角形不到 50%——小三角形和细长三角形都很贵。
自测：为什么在 if 分支里用 tex.Sample() 可能出现"块状"错误？

Sample() 依赖 Quad 内差分得到的导数来选 Mip。如果分支条件在 Quad 内的四个像素上不一致，有的像素没有执行这段代码，它对应的 uv 值就是未定义的，导数也就错了，表现为 2×2 块状的 Mip 错误或闪烁。解决办法：把采样移到分支外；或在分支外先用 ddx/ddy 求好导数，分支内用 SampleGrad；或干脆用 SampleLevel 指定 Mip。

自测：顶点光照（Gouraud）和逐像素光照（Phong）的区别和插值有什么关系？

Gouraud 在顶点着色器里算好光照颜色，再在三角形内插值颜色；Phong 着色插值的是法线，在像素着色器里逐像素计算光照。高光是强烈非线性的函数，插值颜色会把三角形中间的高光"抹掉"或在顶点处出现亮斑，所以高光必须逐像素算。移动端为了省 PS 开销，会把漫反射或远处 LOD 的光照放到顶点阶段。
