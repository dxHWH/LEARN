    先背这个：30 秒面试版答案

    面试官问“讲讲 A*”，先用一分钟讲清全貌，再等他挑一个点深挖。

    问：讲讲 A* 算法。

    A* 是带启发信息的最短路搜索。它给每个节点算一个 f(n) = g(n) + h(n)：g 是从起点走到 n 的真实代价，h 是从 n 到终点的估计代价。每次从 open list 里取 f 最小的节点展开，更新邻居的 g，直到取出终点。

    • 它是 Dijkstra 和贪心的折中：h ≡ 0 就退化成 Dijkstra（只看走了多远，向四周均匀扩散）；只看 h 就是贪心最佳优先（直奔终点，快但不保证最短）。
    • 最优性的前提是 h 可采纳（admissible）：h 永远不高估真实剩余代价。如果再满足一致性（h(n) ≤ cost(n, n') + h(n')），节点第一次出 open 时 g 就已经最优，closed 节点不用重开。
    • h 要和移动规则匹配：4 方向用曼哈顿，8 方向用 Octile（对角距离），任意角度用欧几里得。h 越接近真实值，展开的节点越少；高估就会丢掉最优性，但能换来速度（加权 A*）。

    工程上：open list 用二叉堆，配合“重复入队 + 出队时丢弃过期条目”的惰性删除；节点状态用整图数组 + generation 计数复位，不要每次查询清零；f 相同时优先展开 h 小的节点（平局决胜）。

    放到游戏里：大地图用导航网格（Recast/Detour：多边形上做 A*，再用漏斗算法拉直路径）或分层寻路；格子图可以用 JPS 加速；长路径要分帧做；先用连通块编号判断终点是否可达；帧同步游戏里代价用整数，比较器用 (f, h, 节点编号) 的全序，否则各端走出的路径会不一样。

    面试注意：最容易丢分的五句话
    • “A* 一定比 Dijkstra 快”——不一定。启发函数被障碍误导时，A* 也会搜很大一片（本书 E1：迷宫里 A* 展开 79476 个节点，Dijkstra 是 80180 个，几乎一样）；目标不可达时两者都要把整个连通块搜完。
    • “h 越大越好”——错。h 一旦超过真实代价就不再保证最短（E2：8 方向地图用曼哈顿距离，随机障碍图上 40 条路径没有一条最短，最多比最短路长 9.8%）。
    • “8 方向用欧几里得距离最准”——不对。8 方向下的真实最短距离是 Octile，欧几里得偏小，搜得更多（E2：16105 对 11758 个节点）。
    • “open list 用 std::set 方便改 key”——能用，但比二叉堆慢（E5：2.21 ms 对 1.30 ms）。最常见的做法是允许重复入队，出队时丢弃过期条目。
    • “寻路结果只要代价对就行”——在帧同步游戏里不行。只比 f 的话，两份堆实现给出的路径 40 次里 40 次不同（E9），各端单位走的路不一样，状态就会不同步。

    寻路问题的建模，以及 A* 的四位前辈

    先把“地图”变成“图”，再看四种算法各自按什么顺序访问节点。

    本章目标

    • 理解 4 / 8 方向、移动代价和“禁止切角”这几条移动规则

    1.1 把地图变成图

    寻路的本质是在带权图 G = (V, E, cost) 上求起点到终点代价最小的路径。游戏地图本身不是图，要先选一种表示方法：

    表示优点缺点典型场景
    格子图实现最简单；动态障碍改一个格子就行；天然适合 JPS、流场节点多、内存大；路径是锯齿状的，要做平滑RTS、塔防、战棋、2D 游戏、服务器上的粗略寻路
    路点图节点很少，速度最快只能沿边走；美术改地图就要重摆路点；覆盖不全时会“走不到”早期 FPS、固定路线的 NPC、MOBA 小兵沿兵线走
    导航网格节点少，又能覆盖整片可走区域；路径自然生成复杂（体素化、区域划分、三角化）；动态修改代价高3D 游戏的主流：UE、Unity 内置寻路，Recast/Detour

    后面的算法讲解统一用格子图，因为它最直观；第 7 章再回到导航网格。A* 本身和图的表示无关：只要能回答“这个节点有哪些邻居、走过去花多少、离终点估计还有多远”，就能跑 A*。

    1.2 移动规则：方向、代价与“切角”

    • 4 方向：只能上下左右，每步代价 1。
    • 8 方向：再加 4 个斜向。斜走代价应为 √2 ≈ 1.414；如果也算 1，路径会莫名其妙地多走斜线。工程上常用整数 10 / 14 或 1000 / 1414，避免浮点误差。
    • 禁止切角：斜走时，两侧的直邻格都必须可走。否则角色会贴着墙角“穿”过去，在 3D 里表现为模型卡进墙里。
    面试注意：切角是一个常见的线上 bug

    “小兵卡在墙角”“角色贴墙穿过去了”，很多时候就是寻路允许切角，而物理碰撞不允许。这时寻路给出的路径物理上走不通，角色会卡住或抖动。寻路的移动规则必须和角色真实的碰撞体积一致，导航网格要按角色半径向内收缩（agent radius），也是这个道理。

    1.3 四位前辈：按什么顺序访问节点

    所有图搜索都有同一个骨架：维护一个“待处理”集合（open / frontier），每次取出一个节点展开，把它的邻居放进去。区别只在于“每次取哪一个”：

    算法open 的数据结构每次取出看了什么信息
    BFS队列（FIFO）最早放进去的只看步数
    Dijkstra优先队列g 最小的（离起点代价最小）只看“已经走了多远”
    贪心最佳优先优先队列h 最小的（估计离终点最近）只看“估计还要走多远”
    A*优先队列f = g + h 最小的两者都看：经过它的整条路径估计有多长

    下面四张图是在同一张带 U 型障碍的地图上，四种算法跑完后的状态。蓝色是已经展开过的节点（closed），绿色是还在 open 里等待的节点，橙色是最终路径。标题里的“代价”用的是直走 10、斜走 14。

    BFS：只在等权图上最优

    BFS 一层一层往外扩，第一次碰到终点时走的步数最少。但 8 方向时斜走代价是 1.414，步数最少不等于代价最小。实测 E1 中，随机障碍图上 BFS 有 72% 的路径不是最短的。BFS 的价值在于简单、常数小：在等权图上（比如 4 方向、每步代价相同的战棋），它就是最好的选择；它还常用来做 flood fill、计算连通块、计算“几步之内能走到哪”（战棋的移动范围）。

    Dijkstra：按 g 扩散

    Dijkstra（1959）每次取出 g 最小的节点。边权非负时，一个节点第一次被取出，它的 g 就是最短距离。它的搜索范围是以起点为圆心的“等代价圈”，完全不知道终点在哪个方向，所以要把离起点比终点更近的点全部展开一遍。

    Dijkstra · 伪代码
    dist[S] = 0；把 S 放入优先队列
while 队列非空:
    u = 取出 dist 最小的节点
    if u 已处理: continue
    标记 u 已处理
    if u == G: break               // 单目标时可以提前结束
    for 每条边 (u, v, w):
        if dist[u] + w < dist[v]:
            dist[v] = dist[u] + w；parent[v] = u；把 v 放入队列

    它的优点是一次搜索能得到起点到所有点的最短路。游戏里如果要“从一个点出发，算到很多目标的距离”（比如 AI 要从所有资源点里挑最近的一个，或者计算整张图的距离场），一次 Dijkstra 比跑很多次 A* 划算得多。

    贪心最佳优先：按 h 直冲

    只看 h，每次都走“看起来离终点最近”的节点。开阔地上它快得惊人（E1：开阔地展开 228 个节点，Dijkstra 要 127329 个），但它对已经走了多远毫不在意，会钻进凹形障碍再绕出来，路径也不保证最短（E1：随机障碍图上 100% 非最优，平均长 14%）。

    A*：把两者加起来

    Hart、Nilsson、Raphael 在 1968 年提出 A*。f(n) = g(n) + h(n) 估计的是“经过 n 的那条完整路径有多长”。g 保证它不会像贪心那样无视已走过的代价，h 让它像贪心一样朝终点偏。只要 h 不高估，A* 就和 Dijkstra 一样能找到最短路，同时搜得更少。

    自测：战棋游戏里要显示“这个单位这回合能走到哪些格子”，用什么算法？

    每步代价相同时用 BFS，限制层数为移动力；不同地形代价不同（沼泽 2、道路 1）时，用以单位为起点、代价上限为移动力的 Dijkstra。这里没有单一终点，A* 用不上。

    自测：要从 30 个补给点里找离玩家最近的一个，跑 30 次 A* 合适吗？

    不合适。以玩家为起点跑一次 Dijkstra，第一个被取出的补给点就是最近的，可以立刻停止。也可以把 30 个补给点同时作为起点（多源 Dijkstra）反向搜索。

    CHAPTER 02

    A* 逐步拆解

    open、closed、g、h、f、parent，六个概念，一个循环。

    本章目标
    • 准确说出 g、h、f 和 open / closed 的含义
    • 能跟着一张 7×5 的小地图手算前几步，理解 f 为什么会逐步上升
    • 写出 5 分钟能写完、没有经典 bug 的面试版 A*

    2.1 六个概念

    符号含义谁来维护
    g(n)从起点到 n 目前找到的最小代价，是真实走出来的每次发现更短的路就更新
    h(n)从 n 到终点代价的估计，由启发函数给出，不依赖搜索过程第一次见到 n 时计算一次
    f(n)g(n) + h(n)：经过 n 的整条路径的估计长度g 变化时一起变
    parent(n)目前最短路径上 n 的前一个节点与 g 同时更新；最后沿它回溯出路径
    open已发现、还没展开的节点（搜索的“边界”）优先队列，按 f 取最小
    closed已展开、g 已确定为最优的节点布尔数组或标记

    2.2 算法主循环

    A* · 伪代码
    A*(S, G):
    g[S] = 0；parent[S] = 空
    open = { S }，按 f = g + h 排序
    while open 非空:
        cur = open 中 f 最小的节点；从 open 移到 closed
        if cur == G:                       // ① 出队时才判断终点
            return 沿 parent 从 G 回溯到 S 的路径
        for nb in cur 的每个邻居:
            if nb 是障碍 或 nb 在 closed: continue
            ng = g[cur] + cost(cur, nb)
            if nb 不在 open 或 ng < g[nb]:  // ② 发现更短的路才更新
                g[nb] = ng；parent[nb] = cur
                f[nb] = ng + h(nb)
                把 nb 放入 open（已在 open 中则更新它的 f）
    return 无路径                          // ③ open 空了还没取出 G

    三个标注点就是面试里最常被追问的细节：

    1. 为什么在出队时判断终点，而不是在入队时？ G 第一次入队时的 g 可能来自一条较长的路径，之后还有机会被更短的路径更新。只有当 G 成为 open 里 f 最小的节点时，才能确定没有更短的路了（第 4 章证明）。
    2. 为什么要比较 ng < g[nb]？ 同一个节点可以从多个方向被发现，只保留最短的那条。忘记这个判断会让 parent 被较差的路径覆盖。
    3. open 空了意味着什么？ 起点所在连通块已经搜完了，终点不可达。这是 A* 的最坏情况，第 4 章会专门讨论。

    2.3 手算一遍：7×5 地图，中间一堵墙

    8 方向、禁止切角，直走 10、斜走 14，启发函数用 Octile 距离 h = 10·max(dx, dy) + 4·min(dx, dy)。S 在 (1, 2)，G 在 (5, 2)，中间 x = 3 一列有三格墙。下图每个格子里：中间大字是 f，左下蓝字是 g，右下橙字是 h；小箭头指向 parent。

    逐步解读

    • 第 1 步：S 的 g = 0，h = 40（离 G 横向 4 格），f = 40。展开后 8 个邻居入 open。正右方的 (2, 2) g = 10，h = 30，f = 40；斜向的 (2, 1) g = 14，h = 34，f = 48；左侧的 (0, 2) g = 10，h = 50，f = 60。朝着终点的方向 f 小，背离终点的方向 f 大，这就是 h 起的作用。
    • 第 2 步：取出 f = 40 的 (2, 2)。它右边就是墙，只能发现上下几个格子，它们都已经在 open 里了，而且经过 (2, 2) 并不会更短，所以不更新。
    • 第 3～4 步：open 里最小的 f 变成 48，是 (2, 1) 和 (2, 3)。它们的 f 和 h 都相同，谁先出队取决于平局决胜规则（这里按入队顺序）。注意 f 从 40 涨到了 48：墙挡住了直线，估计值 h 太乐观了，现实把 f 抬了上去。
    • 之后：f = 54、60、62……依次被展开，直到绕过墙的那条路的 f 达到 68，并取出 G。最终 f(G) = g(G) = 68：终点的 h = 0，所以它的 f 就是真实代价。
    深入一层：被展开节点的 f 永远不减

    回看第 1～4 步取出的 f：40, 40, 48, 48, 54, 54, 60, 62……从不下降。这不是巧合：当 h 满足一致性（第 3 章）时，沿着任何一条边走，f 都不会变小，所以 A* 是按 f 从小到大“一圈一圈”地展开节点，和 Dijkstra 按 g 一圈一圈展开完全对应。A* 就是在“修改过边权”的图上跑 Dijkstra，修改后的边权是 cost(u, v) − h(u) + h(v)。

    同一张图上，最终路径可以从墙的上方或下方绕过，两条都是 68。上图走的是下方，而第 2.4 节的面试版代码在同一张图上走的是上方（demos/interview_output.txt）。代价相同时走哪条，完全取决于平局时谁先出队，这一点在第 7 章的帧同步部分会变得很重要。

    astar_interview.cpp（面试版：二叉堆 + 惰性删除 + 禁止切角）
    struct Grid {
    int w, h;
    std::vector<uint8_t> blocked;
    bool walkable(int x, int y) const { return x >= 0 && y >= 0 && x < w && y < h && !blocked[y * w + x]; }
};

struct Node { int f, g, idx; };
struct Cmp {   // priority_queue 是大顶堆：返回 true 表示 a 的优先级更低
    bool operator()(const Node& a, const Node& b) const { return a.f != b.f ? a.f > b.f : a.g < b.g; }   // f 小优先；f 相同 g 大优先
};

std::vector<int> astar(const Grid& grid, int sx, int sy, int tx, int ty) {
    const int W = grid.w, H = grid.h;
    auto id = [W](int x, int y) { return y * W + x; };
    auto h = [&](int x, int y) {                               // Octile：8 方向、直走 10、斜走 14
        int dx = std::abs(x - tx), dy = std::abs(y - ty);
        return 10 * std::max(dx, dy) + 4 * std::min(dx, dy);
    };
    std::vector<int> g(W * H, INT_MAX), parent(W * H, -1);
    std::vector<char> closed(W * H, 0);
    std::priority_queue<Node, std::vector<Node>, Cmp> open;
    g[id(sx, sy)] = 0;
    open.push({h(sx, sy), 0, id(sx, sy)});
    static const int DX[8] = {1, -1, 0, 0, 1, 1, -1, -1}, DY[8] = {0, 0, 1, -1, 1, -1, 1, -1};
    while (!open.empty()) {
        Node cur = open.top(); open.pop();
        if (closed[cur.idx]) continue;                         // 过期条目：该节点已用更小的 g 展开过
        closed[cur.idx] = 1;
        if (cur.idx == id(tx, ty)) break;                      // 出队时才判断终点
        int x = cur.idx % W, y = cur.idx / W;
        for (int d = 0; d < 8; ++d) {
            int nx = x + DX[d], ny = y + DY[d];
            if (!grid.walkable(nx, ny)) continue;
            if (d >= 4 && (!grid.walkable(nx, y) || !grid.walkable(x, ny))) continue;   // 禁止切角
            int j = id(nx, ny);
            if (closed[j]) continue;
            int ng = g[cur.idx] + (d < 4 ? 10 : 14);
            if (ng >= g[j]) continue;                          // 没有变短：忽略
            g[j] = ng; parent[j] = cur.idx;
            open.push({ng + h(nx, ny), ng, j});                // 允许重复入队（惰性删除）
        }
    }
    std::vector<int> path;
    if (g[id(tx, ty)] == INT_MAX) return path;                 // 不可达
    for (int i = id(tx, ty); i != -1; i = parent[i]) path.push_back(i);
    std::reverse(path.begin(), path.end());
    return path;
}

    CHAPTER 03

    启发函数：A* 的灵魂

    同一个 A*，换一个 h，展开的节点数可以差 25 倍，结果也可能从最短变成不是最短。

    本章目标
    • 准确区分可采纳（admissible）与一致（consistent），知道两者分别保证了什么
    • 能根据移动规则选出正确的距离公式，并说出其他公式错在哪
    • 理解加权 A* 的取舍，以及它的次优上界
    • 知道平局决胜为什么能让开阔地上的展开数降一个数量级

    3.1 两个性质

    记 h*(n) 为从 n 到终点的真实最短代价。

    可采纳（admissible）

    对所有节点 n：h(n) ≤ h*(n)。

    也就是“只会低估，不会高估”。它保证 A* 找到的路径是最短的。

    一致（consistent / 单调）

    对每条边 (n, n')：h(n) ≤ cost(n, n') + h(n')，且 h(G) = 0。

    这是三角不等式。它保证节点第一次出队时 g 已最优，closed 节点永远不用重开。

    • 一致 ⇒ 可采纳：沿着从 n 到 G 的最短路径反复使用三角不等式，把每条边加起来，就得到 h(n) ≤ h*(n)。
    • 可采纳 ⇏ 一致：可以构造出“h(A) = 10，走一步代价 1 到 B，h(B) = 2”的例子，h 都不高估，但相邻两点的 h 落差比边长还大。这种 h 下，一个节点可能先以较大的 g 进入 closed，后来又发现更短的路，需要重开（reopen），否则就会丢失最优性。
    • 实际使用的几种距离公式（曼哈顿、Octile、欧几里得等），只要和移动规则匹配，都是一致的。所以工程实现里通常直接不重开 closed 节点。

    3.3 h 的强弱光谱

    如果能拿到完美的启发函数 h = h*，A* 会径直沿着最短路径走，一个多余的节点都不展开。现实中拿不到 h*，但可以预计算出更接近它的下界，比如 ALT 算法预先算出到若干“地标”的距离，用三角不等式得到更紧的 h（第 6 章）。

    3.5 平局决胜：开阔地上的大问题

    在没有障碍的开阔地上，从 S 到 G 有大量代价完全相同的最短路径，这些路径上的所有节点 f 都相等。如果 f 相同时随便选，A* 会把这一大片“平局区域”全部展开。规则很简单：f 相同时，优先展开 h 更小（g 更大）的节点，也就是离终点更近的那个，它会一路往前推，不再横向铺开。

    CHAPTER 04

    为什么 A* 是对的，以及它最慢的时候

    一段反证法说明最优性，一张图说明它为什么比 Dijkstra 搜得少，再看最坏情况：终点根本到不了。

    本章目标
    • 能在面试里用 30 秒讲清 A* 最优性的证明
    • 理解“f < C* 的节点必展开、f > C* 的节点必不展开”，以及 A* 的最优效率
    • 说出时间、空间复杂度，以及不可达时的应对手段

    4.1 最优性证明（h 可采纳）

    记最短路径代价为 C*。反证：假设 A* 取出终点 G 时 g(G) > C*。

    1. 此时，最短路径上一定还有一个节点 n 在 open 里，并且 g(n) 已经等于它的最短距离 g*(n)。（起点在最短路径上；最短路径上第一个还没被展开的节点，它的前驱已被展开过，所以它一定已经以最优的 g 进入了 open。）
    2. 由可采纳性：f(n) = g*(n) + h(n) ≤ g*(n) + h*(n) = C*。
    3. 而 f(G) = g(G) + 0 > C* ≥ f(n)。
    4. A* 每次取 f 最小的节点，n 的 f 更小，应该先于 G 被取出，矛盾。

    所以 G 被取出时 g(G) = C*。这也解释了为什么必须在出队时判断终点：入队时 G 的 f 可能大于 C*，那时还有 f 更小的节点没展开。

    面试速答版

    “反证：如果取出终点时它的 g 比最优大，那最短路径上一定还有一个节点在 open 里。因为 h 不高估，这个节点的 f 不超过最优值，比终点的 f 小，按规则它应该先出队，矛盾。”

    4.2 一致性带来的两个好处

    若 h 一致，对任意边 (n, n')：f(n') = g(n) + c(n, n') + h(n') ≥ g(n) + h(n) = f(n)。也就是说沿着任何一条边走，f 都不会变小。由此：

    • 被展开节点的 f 序列单调不减（第 2 章手算时看到的 40, 40, 48, 48, 54…）。
    • 节点第一次出队时 g 就是最优的，以后不可能再找到更短的路。所以 closed 节点不必重开，惰性删除版只需“出队时跳过已 closed 的条目”。

    只可采纳、不一致的 h 下，一个节点可能先以偏大的 g 出队，之后又被更短的路径更新。这时要么允许重开（从 closed 移回 open，最坏会导致指数次展开），要么接受次优。实际项目里用的几何距离都是一致的，这个问题一般只出现在自己设计的“组合启发函数”里。

    4.3 A* 到底省在哪：f = C* 这条等值线

    由 4.1 的论证还能推出：任何使用同一个可采纳启发函数、并保证找到最短路的算法，都必须展开所有 f < C* 的节点，否则它无法排除“那里藏着一条更短的路”。A* 恰好只展开这些节点（加上一部分 f = C* 的节点），所以说 A* 是最优效率（optimally efficient）的。想比 A* 更快，只有两条路：换一个更准的 h，或者放弃最优（加权、分层、JPS 之类的剪枝不算放弃最优，它们改变的是图本身）。

    4.4 复杂度

    维度结论说明
    时间（图上）O(E log V)每个节点最多展开一次（一致 h），每条边最多引起一次入堆；二叉堆每次操作 log。格子图 E ≈ 8V，所以是 O(V log V)
    时间（树搜索视角）最坏 O(bd)，b 为分支数，d 为解的深度h 完美时降到 O(d)；h 误差有界（|h − h*| ≤ O(log h*)）时是多项式级
    空间O(V)open + closed 要存下所有展开过的节点。A* 的瓶颈通常是内存，而不是时间
    最好情况O(d)开阔地 + 完美启发 + 正确的平局决胜（E1：开阔地 266 格长的路只展开 228 个节点）
    深入一层：省内存的变体

    IDA*（迭代加深 A*）：以 f 为阈值做深度优先搜索，超过阈值就回溯，每轮把阈值提高到上一轮被剪掉的最小 f。内存只有 O(d)，但会大量重复展开，在有环的格子图上很慢，适合 15 数码这类状态空间巨大的谜题。SMA*：内存满时丢掉 f 最大的叶子。游戏寻路里几乎不用它们，更常见的做法是把图变小（导航网格、分层）。

    4.5 最坏情况：终点不可达

    A* 只有在 open 被取空时才能断定“无路可走”，而这意味着起点所在的整个连通块都被展开了一遍。启发函数在这里完全帮不上忙，还会因为堆变大而比 BFS 更慢。

    E8 · 随机障碍 25%，终点在一个被围死的小区域里
    A* 直接搜：展开 195130 个节点（= 起点所在连通块 195130 格），耗时 20.529 ms，结果：无路径
连通块预计算：加载时 flood fill 一次 3.602 ms（946 个连通块）；之后每次判定 0.0003 us（一次数组比较）
展开上限 20000：2.681 ms 后放弃，可退而求其次走向“h 最小的已探索点”

    20 ms 已经超过一帧（60 FPS 下 16.7 ms）。点击一次“走到那个被围起来的位置”，游戏就卡一下。四种应对手段：

    ① 连通块编号

    加载地图时 flood fill，给每个格子标上所属区域编号。查询前先比较编号，不同就直接返回不可达，O(1)。动态障碍改变连通性时要局部重算，导航网格可以在多边形上维护。

    ② 展开上限

    超过 N 个节点就放弃。比较安全，但可能把“可达但很远”误判为不可达，所以要和 ① 搭配使用。

    ③ 退而求其次

    搜索失败时，返回已展开节点中 h 最小（离终点最近）的那个，让单位走到“能走到的最近处”。玩家点了一个不可达的位置时，这通常就是期望的表现。

    ④ 终点吸附

    玩家点的位置在障碍里时，先把终点吸附到最近的可走点，再寻路。Detour 的 findNearestPoly 就做这件事。

    面试注意

    “A* 最坏情况是什么”的标准答案不是 O(bd) 这种教科书公式，而是“终点不可达，要把整个连通块搜完；还有启发函数被凹形障碍误导，要把陷阱填满”，然后给出对应手段。这体现的是工程判断。

    本章速记
    • 最优性：反证，最短路径上总有一个 f ≤ C* 的节点在 open 里，终点不可能以更大的 g 先出队。
    • 一致性 ⇒ f 沿边不减 ⇒ 出队即最优 ⇒ closed 不用重开。
    • A* 展开所有 f < C* 的节点，不展开 f > C* 的节点，是最优效率的。
    • 复杂度：时间 O(E log V)，空间 O(V)，内存往往是瓶颈。
    • 最坏情况是不可达（E8：20.5 ms 搜完 19.5 万格）→ 连通块编号 O(1) 预判 + 展开上限 + 返回最近点。
    自测：证明里为什么要求“最短路径上的那个节点 g 已经是最优的”？

    因为 f(n) ≤ C* 依赖 g(n) = g*(n)。如果 n 的 g 偏大，f(n) 可能超过 C*，论证就不成立。这一点由“它的前驱已经以最优 g 被展开过”保证，归纳的起点是 g(S) = 0。

    自测：双向 A* 能更快地发现“不可达”吗？

    能缓解。如果终点在一个很小的封闭区域里，从终点出发的反向搜索很快就会把那个小区域搜完、open 变空，从而判定不可达，不必把起点那一侧的大连通块搜完。但如果两侧都是大区域，仍然要搜很多。连通块编号仍是最可靠的做法。

    open list 与节点状态：数据结构决定常数

    5.1 A* 的时间花在哪

    每展开一个节点要做：一次出堆（log n）、8 次邻居可走性检查、若干次 g 比较和入堆。另外每次查询开始前，要让所有节点的状态回到“未访问”。前者决定长查询的耗时，后者决定短查询的耗时，而游戏里绝大多数查询都是短查询：追击目标、走到旁边的掩体、技能落点附近的绕行。

    5.2 open list 的四种实现

    • std::set 慢 70%：红黑树每个节点单独分配内存，指针跳转多。
    • 无序数组在短查询上最快，因为 open 里只有几十个元素，线性扫描完全在 L1 缓存里，没有堆调整的开销；长查询时 open 有上千个元素，就慢了 2.8 倍。这再次说明：先看你的查询分布，再选数据结构。
    深入一层：整数代价可以用桶队列

    代价是小整数时，可以把 f 值相同的节点放进同一个桶（数组下标就是 f），取最小只要从当前 f 往后找第一个非空桶，插入和取出都是 O(1)。一致 h 下 f 单调不减，所以“当前桶”的指针只会前进，这叫 bucket queue / Dial 算法；值域大时可以用基数堆（radix heap）。它们在大规模寻路服务（比如服务器批量寻路）里能比二叉堆快不少，代价是要预估 f 的范围。另一个常见的小优化是 4 叉堆：树更矮，一个节点的孩子在内存里相邻。

    5.4 其他常数优化

    • 邻居偏移预计算：8 个方向的下标偏移 {1, −1, W, −W, W+1, …} 提前算好，不要每次做乘法。
    • 地图加一圈边框：在地图外围加一圈“障碍”，邻居检查就不用判断越界。
    • 压缩节点状态：g 用 int32 就够（512×512 迷宫最长路径 36968 格 × 1414 ≈ 5200 万）；可走性用位图；parent 可以只存 3 比特的方向而不是 int 下标。内存越小，缓存命中率越高。
    • SoA 布局：g、parent、gen 分别放在连续数组里，热循环只碰需要的字段。
    • 容器复用：open 的 vector 每次 clear() 而不是重新构造，保留容量。

    5.5 工程版 GridPathfinder

    把上面的要点组合起来：generation 复位、惰性删除二叉堆、全序比较器（为帧同步准备）、禁止切角、展开上限。代码在 demos/astar_engineering.cpp，在 256×256 随机图上和 Dijkstra 对比了 300 次查询，代价全部一致（engineering_output.txt：294 次最短且正确，6 次不可达，0 错误，平均 0.446 ms）。

    GridPathfinder（工程版，可直接用于项目；demo 中另有 cost() / lastExpanded() 两个访问器，此处省略）
    class GridPathfinder {
public:
    explicit GridPathfinder(const Grid& grid)
        : grid_(grid), n_(grid.w * grid.h), g_(n_), parent_(n_), seenGen_(n_, 0), closedGen_(n_, 0) {
        const int W = grid.w;
        const int off[8] = {1, -1, W, -W, W + 1, -W + 1, W - 1, -W - 1};   // 与 DX/DY 顺序一致
        std::copy(off, off + 8, offset_);
        heap_.reserve(4096);
    }

    // 找到返回 true，path 为格子下标序列（含起终点）；maxExpand 限制单次查询的展开数
    bool find(int s, int t, std::vector<int>& path, int maxExpand = INT_MAX) {
        if (++gen_ == 0) {                                   // 40 亿次查询后回绕：整体清零一次
            std::fill(seenGen_.begin(), seenGen_.end(), 0u);
            std::fill(closedGen_.begin(), closedGen_.end(), 0u);
            gen_ = 1;
        }
        heap_.clear();                                       // 保留容量，不重新分配
        path.clear();
        const int W = grid_.w, tx = t % W, ty = t / W;
        auto h = [&](int i) {                                // Octile，直走 1000、斜走 1414
            int dx = std::abs(i % W - tx), dy = std::abs(i / W - ty);
            return 1000 * std::max(dx, dy) + 414 * std::min(dx, dy);
        };
        push(s, 0, -1, h(s));
        int expanded = 0;
        while (!heap_.empty()) {
            std::pop_heap(heap_.begin(), heap_.end(), Cmp{});
            OpenE e = heap_.back(); heap_.pop_back();
            if (closedGen_[e.i] == gen_) continue;           // 惰性删除
            closedGen_[e.i] = gen_;
            if (e.i == t) { build(t, path); return true; }
            if (++expanded > maxExpand) break;
            const int x = e.i % W, y = e.i / W;
            for (int d = 0; d < 8; ++d) {
                if (!canMove(x, y, d)) continue;
                const int j = e.i + offset_[d];
                if (closedGen_[j] == gen_) continue;
                const int ng = g_[e.i] + (d < 4 ? 1000 : 1414);   // int32 足够：最长路径 × 1414 远小于 2^31
                if (seenGen_[j] == gen_ && ng >= g_[j]) continue;
                push(j, ng, e.i, h(j));
            }
        }
        return false;
    }

private:
    struct OpenE { int f, h, i; };
    struct Cmp {   // 全序：f 小 → h 小 → 下标小。任何平台、任何堆实现结果都相同
        bool operator()(const OpenE& a, const OpenE& b) const {
            if (a.f != b.f) return a.f > b.f;
            if (a.h != b.h) return a.h > b.h;
            return a.i > b.i;
        }
    };
    static constexpr int DX[8] = {1, -1, 0, 0, 1, 1, -1, -1};
    static constexpr int DY[8] = {0, 0, 1, -1, 1, -1, 1, -1};
    bool canMove(int x, int y, int d) const {
        if (!grid_.walkable(x + DX[d], y + DY[d])) return false;
        return d < 4 || (grid_.walkable(x + DX[d], y) && grid_.walkable(x, y + DY[d]));   // 禁止切角
    }
    void push(int i, int g, int p, int h) {
        seenGen_[i] = gen_; g_[i] = g; parent_[i] = p;
        heap_.push_back({g + h, h, i});
        std::push_heap(heap_.begin(), heap_.end(), Cmp{});
    }
    void build(int t, std::vector<int>& path) const {
        for (int i = t; i != -1; i = parent_[i]) path.push_back(i);
        std::reverse(path.begin(), path.end());
    }

    const Grid& grid_;
    int n_;
    std::vector<int> g_, parent_;
    std::vector<uint32_t> seenGen_, closedGen_;   // == gen_ 才算本次查询的有效数据
    uint32_t gen_ = 0;
    std::vector<OpenE> heap_;
    int offset_[8];
};

    5.6 多线程寻路

    寻路是只读地图、彼此独立的计算，很适合放到工作线程：

    • 每个线程一份搜索状态：GridPathfinder 里的 g / parent / gen / heap 都是可变状态，不能共享，每个工作线程各持有一个实例。地图数据只读共享。Detour 的 dtNavMeshQuery 也是这个设计：navmesh 共享，query 对象每线程一个。
    • 请求队列 + 回调：游戏逻辑提交请求，下一帧或几帧后拿到结果。UE 的 FindPathAsync 就是这种异步接口。
    • 地图修改要同步：动态障碍改变地图时，要么加读写锁，要么用双缓冲（逻辑帧末尾交换），保证搜索过程中地图不变。
    • 帧同步游戏要小心：异步寻路的结果必须在一个确定的逻辑帧生效（比如“请求帧 + 2”），而不是“哪一帧算完就哪一帧用”，否则各端时序不同就会不同步。
    本章速记
    • open：priority_queue + 惰性删除是默认选择，和索引堆一样快（1.30 对 1.39 ms），std::set 慢 70%；open 很小时线性数组最快。
    • 节点状态：整图数组 + generation 计数，O(1) 复位；每次清零整图会让短查询慢 90 倍（504 对 5.6 us）。gen 回绕时整体清零一次。
    • 常数优化：邻居偏移预计算、外围加边框、int32 g、SoA、容器复用。
    • 多线程：地图只读共享、搜索状态每线程一份；帧同步下异步结果必须在确定的逻辑帧生效。
    自测：惰性删除会让堆变多大？

    每次发现更短的 g 都会多一个条目，堆的大小上限是总入堆次数，约为展开数 × 平均有效邻居数。格子图上同一节点被改进的次数很少（一般 0～2 次），实际只比索引堆大一些。如果担心内存，可以在堆过大时重建一次，丢掉过期条目。

    6.1 JPS：跳过对称路径

    开阔的格子地图上，两点之间有大量代价相同的路径，比如“先右后下”和“先下后右”。A* 会把这些等价路径上的节点都放进 open。JPS（Jump Point Search，Harabor & Grastien，2011）的观察是：沿着一个方向走时，大多数邻居经过当前格到达并不比绕别的路更好，可以直接剪掉。于是它沿直线或对角线一路“跳”过去，只在必须拐弯的地方（跳点）停下来、放进 open。

    6.2 HPA*：把大图变小

    A* 的代价和图的规模直接相关。HPA*（Hierarchical Pathfinding A*，Botea 等，2004）把地图切成若干簇（cluster），只在簇的边界上选出“入口”节点，预先算好同一个簇内入口之间的距离，形成一张小得多的抽象图：

    • 收益：大地图上查询快一到两个数量级；内存只多了抽象图；细化可以分段做，降低首帧延迟。
    • 代价：结果通常比最短路长几个百分点（入口位置是固定选的），所以一般最后还要做平滑；地图修改时要重算受影响的簇。
    • 导航网格本身也是一种“分层”：多边形已经比格子粗很多。超大世界还会在 navmesh tile 之上再建一层图（比如城镇、道路网络）。

    6.3 双向 A* 与预计算启发

    双向 A*

    从起点和终点同时搜索，两边相遇时停止。直觉上两个半径减半的圆面积之和只有一个大圆的一半。

    坑：两边第一次相遇时得到的路径不一定最短。正确的停止条件是：已找到的最好路径长度 μ ≤ 两侧 open 中最小 f 的较大者（或使用更细的双向搜索终止条件）。实现复杂，在游戏里用得不多；它更大的价值是能更快地发现“终点被困在小区域里”。

    ALT（地标 + 三角不等式）

    预先选 k 个地标 L，用 Dijkstra 算出每个地标到所有节点的距离 d(L, ·)。查询时：

    h(n) = maxL |d(L, G) − d(L, n)|

    由三角不等式，它可采纳且一致，通常比几何距离准得多，迷宫、绕路多的地图上效果明显。代价是内存 k × V。

    完全预计算

    节点少（如路点图几百个点）时，直接用 Floyd 或 n 次 Dijkstra 算出全源最短路的“下一跳表”，查询时 O(路径长度) 查表即可。内存 O(V²)，只适合小图。

    6.4 路径平滑：拉绳

    格子图上 8 方向的最短路，在真实空间里并不是最短的：它只能走 0°、45°、90° 这几个角度，看起来像锯齿。拉绳（string pulling）的思路很简单：从起点出发，沿着原始路径往后找，只要还能“看见”（中间没有障碍），就跳过中间的路点；看不见了，就把上一个看得见的点作为新的拐点。

    拉绳：贪心找最远可见点
    // los：格子级视线检测，线段经过格角时，两侧格子都必须可走（与禁止切角一致）
std::vector<int> string_pull(const Map& m, const std::vector<int>& path) {
    std::vector<int> out = {path[0]};
    size_t a = 0;
    while (a + 1 < path.size()) {
        size_t b = a + 1;
        while (b + 1 < path.size() && los(m, path[a], path[b + 1])) ++b;   // 能看见就继续往后
        out.push_back(path[b]);
        a = b;
    }
    return out;
}

    深入一层：Theta* 与“任意角度”寻路

    拉绳是寻路之后的后处理，结果仍然受原始路径走向的约束，不一定是真实空间里的最短路。Theta*（Nash 等，2007）把视线检测放进搜索过程：更新邻居时，如果邻居能直接看见当前节点的 parent，就把邻居的 parent 设为“祖父”，g 用直线距离计算。这样搜出来的路径天然是任意角度的，代价是每次松弛都多一次视线检测。导航网格上对应的做法是第 7 章的漏斗算法。

    7.1 导航网格：3D 游戏的主流

    UE 和 Unity 的内置寻路都是导航网格。UE 直接集成了开源的 Recast/Detour（作者 Mikko Mononen）：Recast 负责从场景几何体离线生成导航网格，Detour 负责运行时查询。

    • 多边形图上的 A*：节点是凸多边形，邻居是共享边的多边形。Detour 的代价按“多边形边上的点之间的距离”累计，启发函数是到终点的欧几里得距离乘以 0.999（H_SCALE，留一点余量，防止浮点误差导致高估）。
    • 结果是“近似最短”：多边形内部可以自由走，但搜索时只用边上的固定点估算代价，所以搜出的多边形走廊不一定是真实空间里最短的那条，不过一般足够接近。
    • agent radius：烘焙时把可走区域向内收缩一个角色半径，运行时就可以把角色当成一个点来寻路。不同体型的角色需要不同的 navmesh（UE 中叫 Supported Agents）。

    7.2 漏斗算法：把多边形走廊拉成直线

    A* 在 navmesh 上给出的是一串多边形，相邻多边形之间的公共边叫入口（portal）。最短路径一定是一条只在入口端点处拐弯的折线。漏斗算法（Simple Stupid Funnel Algorithm）用一次线性扫描求出它：

    漏斗算法 · 伪代码（Simple Stupid Funnel）
    apex = S；left = right = S                      // 漏斗顶点与左右两条边的端点
for 每个入口 portal[i] = (pl, pr)，最后加一个退化入口 (G, G):
    // 尝试收紧右边
    if pr 在当前右边的左侧（或与右边重合）:
        if apex == right 或 pr 在左边的右侧:      // 收紧后漏斗没有翻转
            right = pr
        else:                                     // 右边越过了左边：左端点成为拐点
            输出 left 作为拐点；apex = left
            从 left 所在的入口之后重新开始扫描
    // 对左边做对称的操作
    ...
输出 G

    每个入口最多被处理常数次，整体接近 O(n)。拉直之后的拐点通常还要沿多边形的法线方向往里挪一点（Detour 有专门的选项），避免角色紧贴墙角走。

    7.3 分帧寻路：别让一次长查询卡一帧

    A* 的主循环天然可以暂停：把 open、g、parent 保存在对象里，每帧只展开固定数量的节点，下一帧接着跑。本书的 Search::step(budget) 就是这样实现的。

    • 每帧总预算：比如每帧所有寻路请求加起来最多展开 2 万个节点，或者最多花 1 ms。
    • 优先级：玩家控制的单位、视野内的单位、离目标近的请求优先。
    • 请求合并与作废：同一个单位连续点了三次目标，只保留最后一次；单位死亡时取消它的请求。
    • 等待期间的表现：单位可以先朝目标的直线方向起步，或者播放“思考”动作；分层寻路可以先给出抽象路径的前几段。
    • Detour 提供了分帧接口：initSlicedFindPath / updateSlicedFindPath(maxIter) / finalizeSlicedFindPath；dtPathQueue 就是一个现成的请求队列。

    7.4 动态障碍与重新规划

    情况常见做法
    门开关、桥塌、建筑放下格子图：改格子，更新连通块编号；navmesh：按 tile 局部重建（Recast 的 TileCache 支持用圆柱体 / 盒子作为临时障碍，只重建受影响的 tile）
    已规划的路径被挡住每帧只检查路径前方几个路点是否仍然可走；被挡时从当前位置重新寻路，而不是每帧都重新寻路

    频繁小范围变化增量搜索算法 LPA* / D* Lite 能复用上次的搜索结果，机器人领域常用；游戏里因为实现复杂、内存大，较少使用

    7.5 很多单位去同一个地方：流场

    RTS 里一次框选 200 个单位点击地图，跑 200 次 A* 很浪费：目标相同，路径大部分重叠。流场（flow field）反过来做：

    1. 从目标出发跑一次 Dijkstra（或 BFS），得到每个格子到目标的距离，叫积分场；
    2. 每个格子指向相邻格子里距离最小的那个，得到方向场；
    3. 每个单位每帧只需查自己所在格子的方向，O(1)。
    • 代价与单位数量无关：一次 Dijkstra 的代价摊给所有单位。目标多、单位少时不划算。
    • 《最高指挥官 2》采用了按区块（tile）划分、按需计算的流场（Elijah Emerson，Game AI Pro 中有专文介绍），配合局部避障处理大规模单位移动。
    • 塔防游戏里所有敌人走向同一个基地，流场几乎是标准做法；玩家放下塔时重算一次。

    7.6 全局寻路与局部避障是两层

    面试注意：“两个单位在窄路上互相卡住怎么办”

    这不是 A* 的问题，而是局部避障的问题。回答思路：全局寻路不考虑移动单位；局部用 RVO/ORCA 互相让行；仍然卡住时（死锁）设置超时，让一方等待、后退，或者临时把对方当作障碍重新寻路。MOBA 里小兵互相推挤，通常是“沿兵线路点走 + 分离力 / 避让”这一套，而不是每个小兵都跑一次 A*。

    7.7 帧同步：寻路必须逐位确定

    帧同步（lockstep）游戏的各个客户端只交换玩家输入，各自运行完全相同的逻辑。只要某一端单位走的路和别的端不一样，后面的伤害、技能判定就全部分叉。寻路是最容易出问题的地方之一，因为等长的路径很多，走哪条取决于平局怎么处理。

    帧同步寻路检查清单

    1. 代价和启发函数用整数或定点数：不要用 float 和 sqrt。不同编译器、指令集、优化选项下，浮点结果可能有末位差异，平局判断就会不同。8 方向用 10 / 14 或 1000 / 1414，欧几里得距离用整数平方根或定点数。
    2. 比较器是全序：(f, h, 节点编号)，任何两个不同节点都能分出先后。
    3. 邻居遍历顺序固定：方向数组写死；navmesh 上多边形邻接表的顺序要来自确定的烘焙数据。
    4. 不依赖哈希容器的遍历顺序：std::unordered_map 的遍历顺序取决于实现和插入历史。
    5. 导航数据各端相同：烘焙产物是资源，不能在各端运行时各自生成（浮点体素化在不同机器上可能有差异）。
    6. 动态障碍按逻辑帧生效：障碍的增删必须是逻辑帧里的确定事件，而不是“渲染帧里某个时刻”。
    7. 异步 / 分帧的结果在确定的逻辑帧生效：比如“请求帧 + 2”，而不是“算完就用”。每帧的展开预算也要是逻辑上的固定值，不能按真实耗时（毫秒）分帧。
    8. 平滑、视线检测同样要确定：拉绳用整数格子检测；如果用浮点射线检测，同样存在跨平台差异。
    游戏客户端视角：MOBA 里哪些地方会用到寻路

    摇杆操作的英雄移动本身不需要寻路，碰到墙沿墙滑动即可。寻路一般出现在：AI 控制的英雄（人机、掉线托管）、召唤物和宠物跟随、野怪脱战回到出生点、点击小地图自动移动、小兵在兵线之外追击目标。它们都在逻辑帧里运行，以上清单全部适用。排查不同步时，可以把每次寻路的输入（起终点、地图版本）和输出路径的哈希写进逻辑日志，第一处不一致的地方往往就能直接定位到问题。

    8.2 从数据中得出的十条结论

    1. A* 的表现取决于地图：开阔地 0.018 ms，U 型陷阱 3.9 ms，相差 200 多倍。h 被凹形障碍误导时，A* 要先把陷阱填满。
    2. 迷宫里 A* ≈ Dijkstra（79476 对 80180）：真实路径长 19146 格，启发函数估计的直线距离只有几百格，几乎不提供信息；A* 还多了算 h 的开销。
    3. BFS 在 8 方向上不保证最短：随机图、房间图上 58%～72% 的路径偏长；但它常数小，开阔地比 Dijkstra 快 3 倍。
    4. 贪心是一把双刃剑：开阔地和 A* 一样快，有障碍时路径平均长 10%～14%，没有上界。
    5. JPS 擅长“开阔 + 障碍”：U 型陷阱快 7.5 倍、房间快 4.8 倍；在纯开阔地上反而比 A* 慢 25 倍（扫描线铺满全图）。
    6. Octile 是 8 方向的正确启发：比欧几里得少展开 27%～52%，曼哈顿会丢掉最优性（E2）。
    7. 加权 A* 收益依地图而定：随机图 w = 1.2 展开数降到 1/10，路径只长 3%；U 型陷阱几乎没有收益（E3）。
    8. 平局决胜在开阔地上至关重要：228 对 10772，差 47 倍（E4）。
    9. 短查询的瓶颈是复位，不是搜索：每次清零整图慢 90 倍（E5）；open 很小时线性数组最快。
    10. 不可达是最坏情况：20.5 ms 搜完 19.5 万格，而连通块编号的判断只要一次数组比较（E8）。
    面试注意：用数据说话要带条件

    说“JPS 比 A* 快 4.8 倍”时要加上“在房间类地图、512×512、8 方向禁止切角的条件下”。同样的 JPS 在开阔地上慢 25 倍。面试官更看重你知道“什么情况下快、什么情况下慢、为什么”，而不是一个孤立的倍数。

    40 道面试追问

    每道题的参考答案都压缩到 30～60 秒能讲完的长度。

    9.1 基础（1～8）

    1. A* 的 f、g、h 分别是什么？

    g 是起点到当前节点的真实已走代价；h 是当前节点到终点的估计代价；f = g + h 是经过该节点的完整路径的估计长度。每次展开 open 中 f 最小的节点。

    2. A* 和 Dijkstra、BFS、贪心是什么关系？

    都是“取一个节点展开”的图搜索，区别是取哪个：BFS 取最早入队的（只在等权图最短），Dijkstra 取 g 最小，贪心取 h 最小（快但不最短），A* 取 g + h 最小。h ≡ 0 时 A* 就是 Dijkstra。

    3. open list 和 closed list 是什么？

    open 是已发现、未展开的节点，用优先队列按 f 排序；closed 是已展开、g 已确定最优的节点。一致的 h 下 closed 节点不会再被更新。

    4. 为什么要在出队时判断终点，而不是入队时？

    入队时终点的 g 可能来自较长的路径，之后还可能被更新。只有当它成为 open 中 f 最小的节点时，才能保证没有更短的路径（最优性证明依赖这一点）。

    5. 8 方向寻路的代价怎么设？什么是切角？

    直走 1、斜走 √2，工程上用整数 10/14 或 1000/1414。切角指斜走时擦过墙角；通常要求斜走两侧的直邻格都可走，否则角色会卡进墙角。寻路规则要和碰撞体积一致。

    6. 游戏里寻路图有哪几种表示？各自优缺点？

    格子图：简单、动态障碍好改，但节点多、路径锯齿。路点图：节点少最快，但只能沿边走、覆盖不全。导航网格：节点少又覆盖整片可走区域，路径自然，但生成复杂、动态修改代价高，是 3D 游戏主流。

    7. 什么时候用 BFS / Dijkstra 而不是 A*？

    等权图（如 4 方向战棋）用 BFS；没有单一终点的问题用 Dijkstra：求移动范围、求到多个目标中最近的一个、生成距离场或流场。

    8. 如何从 A* 的结果得到路径？

    每次更新 g 时同时记录 parent，取出终点后沿 parent 从终点回溯到起点，再反转。

    9.2 启发函数（9～16）

    9. 什么是可采纳？什么是一致？

    可采纳：h(n) ≤ h*(n)，从不高估，保证最短。一致：h(n) ≤ c(n, n') + h(n')（三角不等式），保证出队即最优、closed 不用重开。一致 ⇒ 可采纳，反之不成立。

    10. 4 方向、8 方向、任意角度分别用什么启发？

    曼哈顿、Octile（D·max + (D₂−D)·min）、欧几里得。8 方向用曼哈顿会高估（E2：路径最多长 9.8%），用欧几里得会低估、搜得多（16105 对 11758）。

    11. h 高估会怎样？h = 0 会怎样？

    高估：搜得更少、更快，但不保证最短。h = 0：退化为 Dijkstra，最短但向四周均匀扩散。

    12. 有地形代价时启发函数怎么设计？

    乘以最便宜地形的单价，保证不高估。代价是大部分区域 h 低估得厉害，引导变弱，搜索变慢。

    13. 加权 A* 是什么？有什么保证？

    f = g + w·h（w > 1），h 可采纳时路径代价 ≤ w × 最优。E3：随机图 w = 1.2 展开数降到 1/10，路径平均只长 3%；但对凹形陷阱几乎无效。

    14. 什么是平局决胜？为什么重要？

    f 相同时先展开谁。优先 h 小（g 大）的节点，搜索会一路向前推而不是横向铺开。开阔地上展开数 228 对 10772（E4）。帧同步游戏里还要做成全序 (f, h, id) 保证确定性。

    15. 两个可采纳的 h 怎么组合？

    取 max，仍然可采纳且更强。ALT 就是对多个地标的下界取 max。

    16. 改成整数代价后要注意什么？

    重新检查启发函数是否还可采纳。例如斜走取 1414（小于 1000·√2），长对角线上欧几里得（取整）会略微高估。Detour 用 0.999 的系数留余量。

    9.3 正确性与复杂度（17～22）

    17. 证明 A* 的最优性。

    反证：若取出终点时 g(G) > C*，最短路径上必有一个节点 n 在 open 中且 g(n) 最优，由可采纳 f(n) ≤ C* < f(G)，n 应先出队，矛盾。

    18. 一致性为什么能保证“出队即最优”？

    一致 ⇒ 沿任何边 f 不减 ⇒ 节点按 f 非降序出队；一个节点出队时，所有可能给它更短路径的节点 f 都更小、已经出队并松弛过它了。

    19. A* 的时间、空间复杂度？

    图上 O(E log V)（二叉堆），格子图 O(V log V)；空间 O(V)。树搜索视角最坏 O(b^d)，完美 h 时 O(d)。实际瓶颈常是内存。

    20. 什么叫 A* 最优效率？

    使用同一可采纳 h 并保证最短的算法，都必须展开所有 f < C* 的节点；A* 只展开这些（加部分 f = C* 的）。要更快只能换更准的 h 或改变图。

    21. A* 的最坏情况是什么？怎么应对？

    终点不可达，要把整个连通块搜完（E8：20.5 ms）；以及凹形障碍误导启发。应对：连通块编号 O(1) 预判、展开上限、失败时返回 h 最小的已探索点、终点吸附到最近可走点。

    22. h 只可采纳不一致，会出什么问题？

    节点可能先以偏大的 g 出队，之后发现更短的路。要么允许重开 closed（最坏指数次展开），要么接受次优。几何距离都是一致的，问题多出在自己组合的启发函数上。

    9.4 工程实现（23～29）

    23. open list 用什么数据结构？decrease-key 怎么做？

    二叉堆。std::priority_queue 不支持改 key，通常允许重复入队，出队时发现已 closed 就丢弃（惰性删除）。E5：惰性删除 1.30 ms，索引堆 1.39 ms，std::set 2.21 ms。

    24. 每次寻路都要清空整张图的状态吗？

    不要。用整图数组 + generation 计数：节点的 gen 等于当前查询号才算有效，新查询把号加 1 即可。每次清零 512×512 的数组会让短查询慢 90 倍（504 对 5.6 us）。gen 回绕时整体清零一次。

    25. A* 还有哪些常数优化？

    邻居偏移预计算、地图外加一圈边框省越界判断、int32 代价、位图存可走性、SoA 布局、容器 clear 复用容量、平局决胜；整数小代价可用桶队列。

    26. 一帧内有很多寻路请求怎么办？

    全局请求队列 + 每帧展开预算 + 优先级 + 请求合并 / 作废；单个长查询分帧执行（E7：单帧峰值 4.3 ms → 0.045 ms）；或放到工作线程异步计算。

    27. 寻路怎么做多线程？

    地图只读共享，搜索状态（g、parent、gen、堆）每线程一份；地图修改用锁或双缓冲。Detour 的 navmesh 共享、dtNavMeshQuery 每线程一个。帧同步下异步结果必须在确定的逻辑帧生效。

    28. A* 写出来路径是锯齿状的怎么办？

    拉绳：从锚点往后找最远的视线可达路点（E10：路点少 40%、长度短 4%，耗时不到寻路的 1%）；或用 Theta* 在搜索中做视线检测；navmesh 上用漏斗算法。

    29. 手写 A* 常见 bug？

    入队时判终点；惰性删除不检查 closed；更新 g 后不重新入堆；h 与移动规则不匹配；斜走代价错；允许切角；float 代价用 == 比较；不处理不可达。

    9.5 加速算法（30～34）

    30. JPS 的原理？

    均匀代价格子图上存在大量对称的等价路径。JPS 按来向剪枝邻居，沿直线 / 对角线一直跳，只在终点、强制邻居（障碍造成的必经拐点）处停下入堆。保证最短。

    31. JPS 一定比 A* 快吗？限制是什么？

    不一定。开阔地上 A* 已近乎完美，JPS 的扫描线铺满全图，反而慢 25 倍；房间 / 陷阱类地图快 4.8～7.5 倍（E6、E1）。只适用于均匀代价格子图，不能用于导航网格、带地形权重的图。JPS+ 预计算跳跃距离，适合静态地图。

    32. HPA* 的原理和代价？

    切簇、在簇边界选入口、预计算簇内入口间距离形成抽象图；查询时插入起终点、抽象图上 A*、再分段细化。快一到两个数量级，结果近似最短，地图修改要重算受影响的簇。

    33. 双向 A* 的坑？

    两侧第一次相遇的路径不一定最短；要用正确的终止条件（已知最优 μ ≤ 两侧 open 最小 f 的较大者）。实现复杂，游戏里少用，但能更快发现终点被困在小区域里。

    34. ALT 是什么？

    预选 k 个地标，Dijkstra 算出地标到所有节点的距离；h(n) = max |d(L, G) − d(L, n)|，由三角不等式可采纳且一致，比几何距离准。内存 k × V，适合静态、绕路多的地图。

    9.6 游戏场景（35～40）

    35. 导航网格上的寻路流程？

    Recast 离线烘焙：体素化 → 坡度 / 净高 / 台阶过滤 → 按角色半径收缩 → 区域划分 → 凸多边形 → 细节网格。Detour 查询：findNearestPoly 吸附 → findPath 多边形 A* → findStraightPath 漏斗拉直 → 跟随与避让。

    36. 漏斗算法的原理？

    A* 给出多边形走廊，相邻多边形的公共边是入口。从起点维护漏斗顶点和左右两条边，逐个入口收紧；某一边越过另一边时，那一边的端点成为拐点、成为新顶点。结果只在入口端点处拐弯，近似 O(n)。

    37. 动态障碍怎么处理？

    静态变化（门、建筑）：格子改格子并更新连通块；navmesh 按 tile 局部重建（TileCache 临时障碍）。路径只检查前方几个路点，被挡再重新寻路。移动单位不进寻路图，交给局部避障。增量算法 LPA* / D* Lite 游戏里少用。

    38. 200 个单位去同一个地方怎么寻路？

    流场：从目标跑一次 Dijkstra 得积分场，每格指向代价最小的邻居得方向场，单位每帧 O(1) 查表；再配合分离 / 避障。塔防、RTS 常用。

    39. 两个单位在窄路上互相卡住怎么办？

    这是局部避障问题：全局寻路不考虑移动单位；局部用 RVO / ORCA 让行；死锁时超时、一方等待或后退、临时把对方当障碍重新寻路。

    40. 帧同步游戏里寻路要注意什么？

    整数 / 定点代价与启发（不用 float、sqrt）；全序比较 (f, h, id)；邻居顺序固定；不依赖 unordered_map 遍历；导航数据各端一致；动态障碍、异步结果都在确定的逻辑帧生效；平滑也用整数检测。E9：只比 f 时两份堆实现 40 次里 40 次路径不同，全序后完全一致。

    9.7 速记卡

    一页纸背完 A*
    • 核心：f = g + h，展开 open 中 f 最小者；出队时判终点；ng < g 才更新；open 空即不可达。
    • 家族：BFS（等权）、Dijkstra（h = 0）、贪心（只看 h）、加权 A*（≤ w 倍最优）。
    • 启发：可采纳 → 最短；一致 → 出队即最优、不重开。4 向曼哈顿、8 向 Octile、任意角度欧几里得；有地形乘最小单价。
    • 证明：最短路径上总有 f ≤ C* 的节点在 open 里；A* 展开 f < C* 的全部节点，最优效率。
    • 复杂度：O(E log V) 时间、O(V) 空间；最坏是不可达 → 连通块编号预判。
    • 工程：priority_queue + 惰性删除；generation 复位；f 同取 h 小；整数代价；分帧 + 请求队列；多线程状态各自一份。
    • 加速：JPS（均匀格子、开阔 + 障碍）、JPS+、HPA*（分层）、ALT（地标）、双向（注意终止条件）；拉绳 / Theta* / 漏斗做平滑。
    • 游戏：Recast/Detour = 烘焙 + 多边形 A* + 漏斗；流场管大量单位；全局寻路与局部避障分层；帧同步要整数 + 全序 + 确定帧生效。
