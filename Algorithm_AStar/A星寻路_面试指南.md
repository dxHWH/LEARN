## 0. 30 秒面试版答案（先背这个）

**问：讲讲 A* 算法。**

**A* 是带启发信息的最短路搜索。**它给每个节点算 `f(n) = g(n) + h(n)`：g 是从起点到 n 的真实代价，h 是从 n 到终点的**估计**代价。每次从 open list 取 f 最小的节点展开、更新邻居的 g，直到取出终点。

- **它是 Dijkstra 和贪心的折中**：h ≡ 0 就是 Dijkstra（只看走了多远，向四周均匀扩散）；只看 h 就是贪心最佳优先（直奔终点，快但不保证最短）。
- **最优性的前提是 h 可采纳**：h 永远不高估。如果还满足**一致性**（h(n) ≤ cost(n, n') + h(n')），节点第一次出 open 时 g 已经最优，closed 节点不用重开。
- **h 要和移动规则匹配**：4 方向用曼哈顿，8 方向用 Octile，任意角度用欧几里得。h 越接近真实值展开越少；高估会丢最优性，但能换速度（加权 A*）。

**工程上**：open 用二叉堆 + “重复入队、出队时丢弃过期条目”的惰性删除；节点状态用整图数组 + generation 计数复位，不要每次清零；f 相同时优先 h 小的节点。

**游戏里**：大地图用导航网格（Recast/Detour：多边形 A* + 漏斗拉直）或分层寻路；格子图可用 JPS；长路径分帧；先用连通块编号判断可达；帧同步游戏代价用整数、比较器用 (f, h, 节点编号) 全序，否则各端路径不同。

### 家族速查表

| 算法 | 取出顺序 | 最优？ | 搜索范围 | 一句话特点 |
|---|---|---|---|---|
| BFS | 先进先出（按步数） | 只在等权图最优 | 以起点为圆心向外扩 | 不看代价：8 方向时斜走也算 1 步 |
| Dijkstra | g 最小 | ✔ | 以起点为圆心按代价扩 | 一次能求出到所有点的最短路 |
| 贪心最佳优先 | h 最小 | ✘ | 朝终点直冲，碰壁才绕 | 开阔地极快，凹形障碍会钻进去 |
| A* | g + h 最小 | ✔（h 可采纳） | 朝终点的“椭圆” | h 越准搜得越少；h = 0 即 Dijkstra |
| 加权 A* | g + w·h 最小 | 代价 ≤ w × 最优 | 介于 A* 与贪心之间 | 有上界的次优换速度 |
| JPS | g + h 最小（只对跳点） | ✔ | 沿直线跳，只把拐点入堆 | 只适用于均匀代价格子图 |

> ⚠️ **面试注意：最容易丢分的五句话**
> - “A* 一定比 Dijkstra 快”——**不一定**。启发被障碍误导时 A* 也会搜很大一片（E1：迷宫里 A* 展开 79476 个节点，Dijkstra 80180 个）；不可达时两者都要搜完整个连通块。
> - “h 越大越好”——**错**。h 超过真实代价就不保证最短（E2：8 方向用曼哈顿，随机障碍图上 40 条路径没有一条最短，最多长 9.8%）。
> - “8 方向用欧几里得最准”——**不对**。8 方向的真实距离是 Octile，欧几里得偏小、搜得更多（E2：16105 对 11758）。
> - “open list 用 std::set 方便改 key”——能用但比二叉堆慢（E5：2.21 ms 对 1.30 ms）。最常见的做法是**允许重复入队，出队时丢弃过期条目**。
> - “寻路结果只要代价对就行”——帧同步游戏里不行。只比 f 时两份堆实现的路径 40 次里 40 次不同（E9）。

> 实测统一条件：**512×512 格子图，8 方向，禁止切角，直走 1000、斜走 1414（整数）**；五种地图：开阔地、随机障碍 25%、U 型陷阱、迷宫、房间；每张图 40 次查询取平均。下文步骤图用直走 10、斜走 14，数字均由脚本真实运行得到。

## 1. 寻路问题的建模，以及 A* 的四位前辈

### 1.1 把地图变成图

寻路 = 在带权图 G = (V, E, cost) 上求代价最小的路径。游戏里三种表示：

```
① 格子图                 ② 路点图                  ③ 导航网格
┌──────────────┐        ┌──────────────┐         ┌─────┬──┬─────┐
│. . . . . . . │        │   o──────o   │         │     │B │     │
│. . . ██ . . .│        │  /  ████  \  │         │  A  ├──┤  D  │
│S . . ██ . . G│        │ S   ████   G │         │ S   │██│   G │
│. . . ██ . . .│        │  \  ████  /  │         │     ├──┤     │
│. . . . . . . │        │   o──────o   │         │     │C │     │
└──────────────┘        └──────────────┘         └─────┴──┴─────┘
节点 = 格子             节点 = 摆放的点            节点 = 凸多边形，边 = 公共边
512×512 = 26 万节点      节点少，只能沿边走          节点最少，多边形内可自由走
```

| 表示 | 优点 | 缺点 | 典型场景 |
|---|---|---|---|
| 格子图 | 实现最简单；动态障碍改一个格子；适合 JPS、流场 | 节点多、内存大；路径锯齿要平滑 | RTS、塔防、战棋、2D、服务器粗略寻路 |
| 路点图 | 节点很少，最快 | 只能沿边走；改地图要重摆；覆盖不全 | 早期 FPS、固定路线 NPC、MOBA 小兵沿兵线 |
| 导航网格 | 节点少又覆盖整片可走区域；路径自然 | 生成复杂；动态修改代价高 | 3D 主流：UE、Unity 内置，Recast/Detour |

**A* 与图的表示无关**：能回答“有哪些邻居、走过去多少代价、离终点估计还有多远”就能跑。

### 1.2 移动规则

- 4 方向：每步代价 1。8 方向：斜走 √2（整数 10/14 或 1000/1414）；斜走也算 1 会让路径莫名多走斜线。
- **禁止切角**：斜走时两侧直邻格都必须可走，否则角色贴墙角穿过去，3D 里会卡进墙。

```
允许切角（错）           禁止切角（对）            两侧都堵
 . G                     . G                       █ G
 S █   S 斜穿墙角          S █   先上再右             S █   不能斜穿
```

本书统一禁止切角；此时“8 方向可达”等价于“4 连通”，连通性用 4 连通 flood fill 即可。

> ⚠️ “小兵卡墙角”“角色贴墙穿过去”常是寻路允许切角而物理不允许导致的。**寻路规则必须和碰撞体积一致**，navmesh 按角色半径向内收缩也是这个道理。

### 1.3 四位前辈：每次取出谁

|---|---|---|---|
| BFS | 队列 | 最早放进去的 | 只看步数 |

| **A*** | 优先队列 | **f = g + h 最小** | 两者都看 |

- **BFS**：第一次碰到终点时步数最少，但 8 方向下步数最少 ≠ 代价最小（E1：随机障碍图 72% 非最短）。等权图（4 方向战棋）最合适；也用于 flood fill、连通块、“几步内能走到哪”。
- **Dijkstra**（1959）：按 g 扩散，边权非负时节点第一次出队 g 即最短；**完全不知道终点方向**。优点是一次搜索得到到所有点的最短路——“从很多目标里找最近的”时一次 Dijkstra 比多次 A* 划算。

```text
dist[S] = 0；S 入优先队列
while 队列非空:
    u = 取出 dist 最小的节点；若已处理则跳过；标记已处理
    if u == G: break                // 单目标可提前结束
    for 每条边 (u, v, w):
        if dist[u] + w < dist[v]: dist[v] = dist[u] + w；parent[v] = u；v 入队
```

- **贪心**：只看 h，开阔地极快（E1：228 个节点 vs Dijkstra 127329），但会钻进凹形障碍，路径不保证最短（随机图 100% 非最短，平均长 14%）。
- **A***（Hart、Nilsson、Raphael，1968）：f 估计“经过 n 的完整路径长度”。g 防止无视已走代价，h 让搜索偏向终点。h 不高估就和 Dijkstra 一样最优且搜得更少。

## 2. A* 逐步拆解

### 2.1 六个概念

| 符号 | 含义 | 维护 |
|---|---|---|
| `g(n)` | 起点到 n **目前找到的**最小代价（真实走出来的） | 发现更短的路就更新 |
| `h(n)` | n 到终点代价的**估计**（启发函数，与搜索过程无关） | 第一次见到 n 时计算 |
| `f(n)` | g + h：经过 n 的整条路径的估计长度 | g 变化时一起变 |
| `parent(n)` | 目前最短路径上 n 的前一个节点 | 与 g 同时更新，最后回溯 |
| open | 已发现、未展开（搜索边界） | 优先队列按 f |
| closed | 已展开、g 已最优 | 布尔数组 / 标记 |

### 2.2 主循环

```text
A*(S, G):
    g[S] = 0；parent[S] = 空；open = { S }，按 f = g + h 排序
    while open 非空:
        cur = open 中 f 最小的节点；从 open 移到 closed
        if cur == G:                       // ① 出队时才判断终点
            return 沿 parent 从 G 回溯到 S 的路径
        for nb in cur 的每个邻居:
            if nb 是障碍 或 nb 在 closed: continue
            ng = g[cur] + cost(cur, nb)
            if nb 不在 open 或 ng < g[nb]:  // ② 发现更短的路才更新
                g[nb] = ng；parent[nb] = cur；f[nb] = ng + h(nb)
                放入 open（已在则更新）
    return 无路径                          // ③ open 空了还没取出 G
```

1. **为什么出队时判终点**：G 第一次入队时的 g 可能来自较长路径，之后还会被更新；只有它成为 f 最小时才能确定没有更短的（第 4 章证明）。
2. **为什么比较 ng < g[nb]**：同一节点可从多方向发现，只保留最短；漏掉会让 parent 被较差路径覆盖。
3. **open 空**：起点所在连通块已搜完，终点不可达——A* 的最坏情况。

- **第 2 步**：取出 f = 40 的 (2,2)。右边是墙，上下邻居已在 open 且经过它不会更短，不更新。

> 🟣 **深入一层**：被展开节点的 f（40, 40, 48, 48, 54, 54, 60, 62…）单调不减。h 一致时沿任何边 f 不减，A* 就是按 f 一圈圈展开——**A* 等价于在边权改为 cost(u,v) − h(u) + h(v) 的图上跑 Dijkstra**。

### 2.4 面试手写版 C++（已编译运行，`demos/astar_interview.cpp`）

```cpp
struct Grid {
    int w, h;
    std::vector<uint8_t> blocked;
    bool walkable(int x, int y) const { return x >= 0 && y >= 0 && x < w && y < h && !blocked[y * w + x]; }
};

struct Node { int f, g, idx; };
struct Cmp {   // priority_queue 是大顶堆：返回 true 表示 a 的优先级更低
    bool operator()(const Node& a, const Node& b) const { return a.f != b.f ? a.f > b.f : a.g < b.g; }   // f 小优先；f 相同 g 大优先
};

std::vector<int> astar(const Grid& grid, int sx, int sy, int tx, int ty) {
    const int W = grid.w, H = grid.h;
    auto id = [W](int x, int y) { return y * W + x; };
    auto h = [&](int x, int y) {                               // Octile：8 方向、直走 10、斜走 14
        int dx = std::abs(x - tx), dy = std::abs(y - ty);
        return 10 * std::max(dx, dy) + 4 * std::min(dx, dy);
    };
    std::vector<int> g(W * H, INT_MAX), parent(W * H, -1);
    std::vector<char> closed(W * H, 0);
    std::priority_queue<Node, std::vector<Node>, Cmp> open;
    g[id(sx, sy)] = 0;
    open.push({h(sx, sy), 0, id(sx, sy)});
    static const int DX[8] = {1, -1, 0, 0, 1, 1, -1, -1}, DY[8] = {0, 0, 1, -1, 1, -1, 1, -1};
    while (!open.empty()) {
        Node cur = open.top(); open.pop();
        if (closed[cur.idx]) continue;                         // 过期条目：该节点已用更小的 g 展开过
        closed[cur.idx] = 1;
        if (cur.idx == id(tx, ty)) break;                      // 出队时才判断终点
        int x = cur.idx % W, y = cur.idx / W;
        for (int d = 0; d < 8; ++d) {
            int nx = x + DX[d], ny = y + DY[d];
            if (!grid.walkable(nx, ny)) continue;
            if (d >= 4 && (!grid.walkable(nx, y) || !grid.walkable(x, ny))) continue;   // 禁止切角
            int j = id(nx, ny);
            if (closed[j]) continue;
            int ng = g[cur.idx] + (d < 4 ? 10 : 14);
            if (ng >= g[j]) continue;                          // 没有变短：忽略
            g[j] = ng; parent[j] = cur.idx;
            open.push({ng + h(nx, ny), ng, j});                // 允许重复入队（惰性删除）
        }
    }
    std::vector<int> path;
    if (g[id(tx, ty)] == INT_MAX) return path;                 // 不可达
    for (int i = id(tx, ty); i != -1; i = parent[i]) path.push_back(i);
    std::reverse(path.begin(), path.end());
    return path;
}
```

写完主动说明：
- **open 允许重复入队**（priority_queue 不能改 key），出队发现已 closed 就跳过——惰性删除。
- **整数代价** 10/14：平局判断精确。
- **平局决胜**：f 相同优先 g 大（h 小），开阔地展开数差一个数量级（E4：3582 对 228）。
- **每次调用分配整图数组**：面试足够；游戏里要换 generation 复位（E5：短查询 504 us 对 5.6 us）。

## 3. 启发函数

### 3.1 两个性质

记 h*(n) 为 n 到终点的真实最短代价。

- **可采纳**：h(n) ≤ h*(n)，只低估不高估 → 保证**最短**。
- **一致（单调）**：h(n) ≤ cost(n, n') + h(n')，h(G) = 0 → 节点**第一次出队 g 即最优**，closed 不必重开。
- **一致 ⇒ 可采纳**（沿最短路径把三角不等式累加）；**可采纳 ⇏ 一致**（例：h(A)=10，A→B 代价 1，h(B)=2，都不高估但落差比边长大）。不一致时节点可能先以偏大的 g 进 closed，要重开才能保最优。
- 与移动规则匹配的几何距离**都是一致的**，所以工程实现通常不重开。

### 3.2 四种距离公式（D 直走代价，D₂ = √2·D）

| 名称 | 公式 | 它是哪种移动的真实距离 |
|---|---|---|
| 曼哈顿 | `D·(dx + dy)` | 4 方向 |
| Octile | `D·max(dx,dy) + (D₂ − D)·min(dx,dy)` | 8 方向、斜走 √2 |
| 切比雪夫 | `D·max(dx, dy)` | 8 方向、斜走也算 D |
| 欧几里得 | `D·√(dx² + dy²)` | 任意角度（navmesh、连续空间） |

“单位圆”关系（h = 12 格的等值线，8 方向真实距离是正八边形 Octile）：

```
        切比雪夫：正方形（在八边形外 → 低估，可采纳）
        欧几里得：圆（八边形内接于圆 → 低估，可采纳）
        Octile  ：正八边形 = 8 方向真实距离
        曼哈顿  ：菱形（在八边形里 → 八边形上的点 h > 12 → 高估，不可采纳）
```

## 4. 正确性与复杂度

### 4.1 最优性证明（h 可采纳）

反证：设取出 G 时 g(G) > C*。
1. 此时最短路径上必有节点 n 在 open 且 g(n) = g*(n)（最短路径上第一个未展开的节点，其前驱已以最优 g 展开过）。
2. 可采纳：f(n) = g*(n) + h(n) ≤ g*(n) + h*(n) = C*。
3. f(G) = g(G) > C* ≥ f(n)。
4. A* 取 f 最小，n 应先于 G 出队，矛盾。

> ✅ 速答：“如果取出终点时 g 比最优大，最短路径上一定还有一个节点在 open 里；h 不高估，它的 f 不超过最优值，比终点小，应该先出队，矛盾。”

### 4.2 一致性的两个好处

f(n') = g(n) + c(n,n') + h(n') ≥ g(n) + h(n) = f(n)：沿边 f 不减 →
- 被展开节点的 f 单调不减；
- 节点第一次出队 g 即最优，closed 不必重开。

只可采纳不一致时，要么允许重开（最坏指数次展开），要么接受次优；问题一般只出在自己组合的启发函数上。

### 4.3 A* 省在哪：f = C* 这条等值线

```
          ┌ Dijkstra：g < C*，以 S 为圆心、半径 C* 的圆，全部展开 ┐
          │        ╭──────────────────────────╮                    │
          │      ╭─┤  f < C*：一定会被展开       ├─╮                  │
          │      │ S ━━━━━━━━━━━━━━━━━━━━━━━━ G │  ← 开阔地上是以     │
          │      ╰─┤  （椭圆边界 f = C*：看平局）├─╯     S、G 为焦点的椭圆
          │        ╰──────────────────────────╯                    │
          └────────────── f > C*：A* 一定不展开 ───────────────────┘
```

**最优效率**：任何使用同一可采纳 h、保证最短的算法，都必须展开所有 f < C* 的节点；A* 只展开这些（加部分 f = C*）。想更快：换更准的 h，或改变图（JPS、分层），或放弃最优。

### 4.4 复杂度

| 维度 | 结论 | 说明 |
|---|---|---|
| 时间（图） | **O(E log V)** | 一致 h 下每节点展开一次，每条边至多一次入堆；格子图 E ≈ 8V |
| 时间（树搜索） | 最坏 O(b^d) | h 完美 O(d)；误差 \|h − h*\| ≤ O(log h*) 时多项式 |
| 空间 | **O(V)** | open + closed；**瓶颈通常是内存** |
| 最好 | O(d) | 开阔地 + 完美 h + 正确平局决胜（E1：266 格长的路只展开 228 个） |

省内存变体：IDA*（f 阈值迭代加深，内存 O(d)，大量重复展开，适合 15 数码类谜题）、SMA*（内存满丢 f 最大的叶子）。游戏里更常见的是把图变小。

### 4.5 最坏情况：终点不可达

open 取空才能断定无路 → 起点所在**整个连通块**被展开，h 帮不上忙，堆变大反而比 BFS 慢。

```
E8 · 随机障碍 25%，终点在被围死的小区域
A* 直接搜：展开 195130 个节点（= 起点所在连通块 195130 格），耗时 20.529 ms，结果：无路径
连通块预计算：加载时 flood fill 一次 3.602 ms（946 个连通块）；之后每次判定 0.0003 us
展开上限 20000：2.681 ms 后放弃，可退而求其次走向“h 最小的已探索点”
```

20 ms 超过一帧（60 FPS 16.7 ms）。四种手段：
1. **连通块编号**：加载时 flood fill，查询前比较编号，O(1)；动态障碍改变连通性时局部重算。
2. **展开上限**：超过 N 放弃；可能误判“可达但很远”，要和 ① 搭配。
3. **退而求其次**：失败时返回 h 最小的已探索点，让单位走到“能到的最近处”。
4. **终点吸附**：点在障碍里时先吸附到最近可走点（Detour `findNearestPoly`）。

> ⚠️ “A* 最坏情况”的好答案不是 O(b^d)，而是“**终点不可达要搜完整个连通块；启发被凹形障碍误导要把陷阱填满**”，再给出手段。

> 自测：证明里为何要求那个节点 g 已最优？——f(n) ≤ C* 依赖 g(n) = g*(n)；由前驱已最优展开保证，归纳起点 g(S) = 0。
> 自测：双向 A* 能更快发现不可达吗？——终点困在小区域时反向搜索很快把小区域搜完、open 变空；两侧都大时仍要搜很多，连通块编号最可靠。

## 5. 工程实现：数据结构决定常数

### 5.1 时间花在哪

每次展开：一次出堆（log n）、8 次可走性检查、若干次 g 比较与入堆；每次查询开始还要让节点状态回到“未访问”。前者决定长查询，后者决定短查询——**游戏里绝大多数是短查询**（追击、走到掩体、技能落点附近绕行）。

### 5.2 open list 四种实现

| 实现 | 取最小 | 插入 | 改 key | 特点 |
|---|---|---|---|---|
| **二叉堆 + 惰性删除** | O(log n) | O(log n) | 再插一份，出队跳过过期 | 最简单，priority_queue 即可 |
| 索引二叉堆 | O(log n) | O(log n) | O(log n) 原地上浮 | 维护位置数组，无重复 |
| std::set | O(log n) | O(log n) | 删旧再插 | 红黑树，逐节点分配，缓存差 |
| 无序数组 | O(n) | O(1) | O(1) | open 小时快，大时 O(n²) |

| E5：随机障碍 25%，512×512 | 长查询（展开 11757） | 短查询（≤16 格，展开 49） |
|---|---|---|
| priority_queue + 惰性删除 | **1.301 ms** | 5.60 us |
| 索引二叉堆 + decrease-key | 1.388 ms | 5.54 us |
| std::set + 删除再插入 | 2.212 ms | 9.22 us |
| 无序数组 + 线性找最小 | 3.593 ms | **5.01 us** |

- 惰性删除与索引堆几乎一样快：格子图上同一节点改 key 次数很少，索引堆每次交换多写位置数组。**默认选 priority_queue + 惰性删除**。
- std::set 慢 70%：逐节点分配、指针跳转。
- 无序数组短查询最快（几十个元素全在 L1），长查询慢 2.8 倍——**先看查询分布再选结构**。

> 🟣 整数小代价可用**桶队列 / Dial 算法**（f 当下标，一致 h 下指针只前进，O(1)）或基数堆；**4 叉堆**树更矮、孩子相邻。

### 5.3 节点状态复位

| 做法 | 长查询 | 短查询 | 说明 |
|---|---|---|---|
| **整图数组 + generation 计数** | **1.297 ms** | **5.60 us** | 数组只分配一次；每节点存 gen 戳，== 当前查询号才有效；新查询号 +1，O(1) 复位 |
| 每次重新分配并清零 | 1.763 ms | **504.45 us** | 面试版写法；512×512 三个数组约 2.4 MB，复位 O(V) |
| unordered_map | 2.354 ms | 10.17 us | 只存访问过的节点；每次访问要哈希、可能分配 |

> ⚠️ 这是区分“写过 demo”和“做过项目”的点：说出“generation 复位、惰性删除二叉堆、容器保留容量”。gen 是 32 位，**回绕到 0 时整体清零一次**。

### 5.4 其他常数优化

- 邻居偏移预计算 `{1, −1, W, −W, W+1, …}`；
- 地图外围加一圈障碍，省越界判断；
- g 用 int32（512×512 迷宫最长 36968 格 × 1414 ≈ 5200 万）；可走性用位图；parent 可只存 3 比特方向；
- SoA 布局；open 的 vector `clear()` 复用容量。

### 5.5 工程版 GridPathfinder（`demos/astar_engineering.cpp`，与 Dijkstra 对拍 300 次：294 次最短且正确、6 次不可达、0 错误，平均 0.446 ms）

class GridPathfinder {
public:
    explicit GridPathfinder(const Grid& grid)
        : grid_(grid), n_(grid.w * grid.h), g_(n_), parent_(n_), seenGen_(n_, 0), closedGen_(n_, 0) {
        const int W = grid.w;
        const int off[8] = {1, -1, W, -W, W + 1, -W + 1, W - 1, -W - 1};   // 与 DX/DY 顺序一致
        std::copy(off, off + 8, offset_);
        heap_.reserve(4096);
    }

    // 找到返回 true，path 为格子下标序列（含起终点）；maxExpand 限制单次查询的展开数
    bool find(int s, int t, std::vector<int>& path, int maxExpand = INT_MAX) {
        if (++gen_ == 0) {                                   // 40 亿次查询后回绕：整体清零一次
            std::fill(seenGen_.begin(), seenGen_.end(), 0u);
            std::fill(closedGen_.begin(), closedGen_.end(), 0u);
            gen_ = 1;
        }
        heap_.clear();                                       // 保留容量，不重新分配
        path.clear();
        const int W = grid_.w, tx = t % W, ty = t / W;
        auto h = [&](int i) {                                // Octile，直走 1000、斜走 1414
            int dx = std::abs(i % W - tx), dy = std::abs(i / W - ty);
            return 1000 * std::max(dx, dy) + 414 * std::min(dx, dy);
        };
        push(s, 0, -1, h(s));
        int expanded = 0;
        while (!heap_.empty()) {
            std::pop_heap(heap_.begin(), heap_.end(), Cmp{});
            OpenE e = heap_.back(); heap_.pop_back();
            if (closedGen_[e.i] == gen_) continue;           // 惰性删除
            closedGen_[e.i] = gen_;
            if (e.i == t) { build(t, path); return true; }
            if (++expanded > maxExpand) break;
            const int x = e.i % W, y = e.i / W;
            for (int d = 0; d < 8; ++d) {
                if (!canMove(x, y, d)) continue;
                const int j = e.i + offset_[d];
                if (closedGen_[j] == gen_) continue;
                const int ng = g_[e.i] + (d < 4 ? 1000 : 1414);   // int32 足够：最长路径 × 1414 远小于 2^31
                if (seenGen_[j] == gen_ && ng >= g_[j]) continue;
                push(j, ng, e.i, h(j));
            }
        }
        return false;
    }

private:
    struct OpenE { int f, h, i; };
    struct Cmp {   // 全序：f 小 → h 小 → 下标小。任何平台、任何堆实现结果都相同
        bool operator()(const OpenE& a, const OpenE& b) const {
            if (a.f != b.f) return a.f > b.f;
            if (a.h != b.h) return a.h > b.h;
            return a.i > b.i;
        }
    };
    static constexpr int DX[8] = {1, -1, 0, 0, 1, 1, -1, -1};
    static constexpr int DY[8] = {0, 0, 1, -1, 1, -1, 1, -1};
    bool canMove(int x, int y, int d) const {
        if (!grid_.walkable(x + DX[d], y + DY[d])) return false;
        return d < 4 || (grid_.walkable(x + DX[d], y) && grid_.walkable(x, y + DY[d]));   // 禁止切角
    }
    void push(int i, int g, int p, int h) {
        seenGen_[i] = gen_; g_[i] = g; parent_[i] = p;
        heap_.push_back({g + h, h, i});
        std::push_heap(heap_.begin(), heap_.end(), Cmp{});
    }
    void build(int t, std::vector<int>& path) const {
        for (int i = t; i != -1; i = parent_[i]) path.push_back(i);
        std::reverse(path.begin(), path.end());
    }

    const Grid& grid_;
    int n_;
    std::vector<int> g_, parent_;
    std::vector<uint32_t> seenGen_, closedGen_;   // == gen_ 才算本次查询的有效数据
    uint32_t gen_ = 0;
    std::vector<OpenE> heap_;
    int offset_[8];
};
```

### 5.6 多线程寻路

- **每线程一份搜索状态**（g / parent / gen / heap），地图只读共享。Detour 同理：navmesh 共享，`dtNavMeshQuery` 每线程一个。
- **请求队列 + 回调**：下一帧或几帧后拿结果（UE `FindPathAsync`）。
- **地图修改要同步**：读写锁或双缓冲（逻辑帧末交换）。
- **帧同步要小心**：异步结果必须在**确定的逻辑帧**生效（如“请求帧 + 2”），不能“算完就用”。

> 自测：惰性删除会让堆多大？——上限为总入堆次数；格子图上同一节点改进 0～2 次，只比索引堆大一些；担心内存可在堆过大时重建一次。

## 6. 加速与平滑

### 6.1 JPS：跳过对称路径（Harabor & Grastien，2011）

开阔格子图上“先右后下”与“先下后右”等价，A* 会把它们全部入 open。JPS 沿直线 / 对角线一路**跳**，只在必须拐弯处（跳点）停下入堆。

```
① 直线走：只留正前方        ② 强制邻居：X 是跳点          ③ 斜着走：先做两次直线扫描
 剪 剪 剪                    █  ↑强制  .                   ↑扫描 [✓]
 P → X → ✓                   P → X     ✓                   X  ┄┄→扫描
 剪 剪 剪                    .  .      .                 P↗
 其余邻居从 P 出发             P 上方是墙，P 无法斜走到        向右、向上各扫一条直线，
 不经过 X 也同样好              X 上方（禁止切角）→ 必须停下     任一找到跳点则 X 是跳点
```

停下条件只有三种：到达终点、出现强制邻居、斜向扫描时直线方向发现跳点。本书实现“禁止切角”版本。

```

+ o o o o o o o o o o o o o o + + . . .     . . . o . . . . . o . o . . . . . . . .
+ o S o o o o o o o # o o o o o + + . .     . . S . . . . . . o # . . . . . . . . .
+ o o * * * * * * o # o o o o o o + . .     . . . J . . . . J . # . . o + . . . + .
+ o o o # # # # o * # o o o o # # # . .     . . . . # # # # . J # . . . o # # # . .
+ + o o # . . + o * # + o o o o o # . .     . . . . # . . . o . # . . + o . . # . .
. + o o # . . + o * # # # o o o o # . .     . . . . # . . . . o # # # + o . . # . .
. + o o # + + + o * * * * * * o o # . .     . . . . # . + . + J . . . J J . o # . .
. + + o o o o o o # # # # # o * o # G +     . . . o . o . . . # # # # # . . . # G .
. . + + + + + + + . . . . . + + * * * +     . . . . + . + . + . . . . . + . J . J .

（左：* 为路径；右：J 为路径上的跳点，o / + 为展开 / 待展开的跳点，其余格子只被扫描、从未入堆）

```text
JPS(S, G): 与 A* 主循环相同，“邻居”换成“跳点”
    cur = open 中 f 最小的节点
    dirs = prune(cur, 来向)              // 起点取全部 8 个方向
    for d in dirs:
        jp = jump(cur, d)
        if jp 存在: g[jp] = g[cur] + octile(cur, jp)，按 A* 规则放入 open

jump(x, d):
    loop:
        x = x + d
        if x 是障碍: return 无
        if x == G: return x
        if d 是直线 且 x 有强制邻居: return x
        if d 是斜向 且 (jump(x, d 的横向) 或 jump(x, d 的纵向) 有结果): return x
        if d 是斜向 且 两侧直邻格不全可走: return 无     // 禁止切角
```

|---|---|---|---|---|---|---|
| 开阔地 | 228 | 0.029 ms | 3 | **263620** | 0.444 ms | **0.1×（更慢）** |
| 随机障碍 25% | 11758 | 1.385 ms | 6285 | 49138 | 0.919 ms | 1.5× |
| 迷宫 | 79476 | 3.476 ms | 23927 | 85316 | 1.325 ms | 2.6× |
| 房间 | 7822 | 0.953 ms | 564 | 64090 | 0.214 ms | **4.5×** |

- **JPS 不是总能加速**：开阔地上 A* + 正确平局决胜已近乎完美，JPS 每斜走一步都向两侧直线扫描到地图边缘，扫了 26 万格，慢 15 倍。
- **最擅长“大片开阔 + 若干障碍”**：A* 要把陷阱里的对称路径全部入堆，JPS 只扫描不入堆。
- **保证最短**（E6 100% 最优），剪掉的只是等价路径。

> ⚠️ JPS 适用条件：**只适用于均匀代价格子图**（有地形权重不行）；不适用于 navmesh、路点图；**JPS+**（Steve Rabin）预计算每格 8 个方向到跳点 / 墙的距离，扫描变查表，通常快一个数量级以上，适合静态地图。

### 6.2 HPA*：把大图变小（Botea 等，2004）

```
┌────────┬────────┬────────┬────────┐   ① 预处理：切簇 → 公共边上选入口 →
│ S━━━━━━◎━━━━━━━━◎        ◎        │      簇内算入口两两距离 = 抽象图的边
│   ╲    │ ╲    ╱ │╲     ╱ │        │   ② 查询：S、G 临时连到所在簇的入口
├────◎───┼───◎────┼───◎────┼───◎────┤   ③ 抽象图（几十上百个节点）上 A*
│        │        │  ╲     │        │   ④ 细化：相邻入口间簇内小 A*，
│        ◎        ◎   ━━━━━◎━━━━━ G │      可分段做；单位拿到前两段就出发
└────────┴────────┴────────┴────────┘
粗线 = 簇边界，◎ = 入口节点，━ = 抽象图上的路径
```

- 收益：大地图查询快一到两个数量级；细化分段降低首帧延迟。
- 代价：通常比最短路长几个百分点（入口固定），最后要平滑；地图修改要重算受影响的簇。
- navmesh 本身也是一种“分层”；超大世界还会在 tile 之上再建一层图。

### 6.3 双向 A* 与预计算启发

- **双向 A***：两边同时搜。**坑**：第一次相遇的路径不一定最短；正确终止条件是已知最优 μ ≤ 两侧 open 最小 f 的较大者。实现复杂，游戏里少用；价值在于能更快发现终点被困在小区域。
- **ALT**：预选 k 个地标 L，Dijkstra 算出 d(L, ·)；`h(n) = max_L |d(L, G) − d(L, n)|`，三角不等式保证可采纳且一致，比几何距离准，迷宫、绕路多的地图效果明显；内存 k × V。
- **完全预计算**：路点图几百个点时用 Floyd / n 次 Dijkstra 存“下一跳表”，查询 O(路径长度)；内存 O(V²)。

### 6.4 路径平滑：拉绳

std::vector<int> string_pull(const Map& m, const std::vector<int>& path) {
    std::vector<int> out = {path[0]};
    size_t a = 0;
    while (a + 1 < path.size()) {
        size_t b = a + 1;
        while (b + 1 < path.size() && los(m, path[a], path[b + 1])) ++b;   // 能看见就继续往后
        out.push_back(path[b]);
        a = b;
    }
    return out;
}

## 7. 游戏实战

### 7.1 导航网格：Recast/Detour

UE 与 Unity 的内置寻路都是导航网格；UE 直接集成开源的 Recast/Detour（Mikko Mononen）。

```
Recast（离线烘焙 / 运行时按 tile 重建）
  场景三角形 → 体素化（高度场）→ 可走过滤（坡度 / 净高 / 台阶）→ 按 agent radius 收缩
            → 区域划分（分水岭等）→ 轮廓 → 凸多边形（最多 6 边）→ 细节网格（贴合高度）

Detour（运行时一次查询）
  ① findNearestPoly：起终点吸附到最近多边形
  ② findPath：多边形图上的 A* → 多边形走廊
  ③ findStraightPath：漏斗算法 → 拐点序列
  ④ 跟随与避让：DetourCrowd（走廊 + RVO）
  分帧接口：initSlicedFindPath / updateSlicedFindPath(maxIter) / finalizeSlicedFindPath
```

- 多边形 A*：节点是凸多边形，邻居是共边多边形；代价按多边形边上点之间的距离累计；启发 = 欧几里得 × 0.999（`H_SCALE`）。
- 结果“近似最短”：搜索时只用边上固定点估算代价，走廊不一定是真实最短，但一般足够接近。
- agent radius：烘焙时向内收缩一个角色半径，运行时角色当点寻路；不同体型需要不同 navmesh（UE：Supported Agents）。

### 7.2 漏斗算法

A* 给出多边形走廊，相邻多边形公共边是**入口**（portal）。最短路径只在入口端点处拐弯，漏斗算法线性扫描求出：

```
 ┌────────┐┌──────┐┌───────┐┌─────────┐┌───────┐
 │        ││      ││       ││         ││       │
 │        ││      │┃       ┃│         │        G
 │   S━━━━┃┃━━━━━━┃┃━━━━━━━┃┃━━━━━━━━━┃━━━━━━━│    ━ 漏斗结果：只在入口端点拐弯
 └────────┘└──────┘└───────┘└─────────┘└───────┘    ┃ 入口（相邻多边形的公共边）
   （示意：真实结果见电子书图 7-2，路径贴着各入口的内侧端点走）
```

```text
apex = S；left = right = S
for 每个入口 (pl, pr)，最后加退化入口 (G, G):
    // 收紧右边
    if pr 在当前右边的左侧（或重合）:
        if apex == right 或 pr 在左边的右侧: right = pr        // 漏斗没翻转
        else: 输出 left 为拐点；apex = left；从 left 所在入口之后重新扫描
    // 左边对称处理
输出 G
```

每个入口处理常数次，近似 O(n)。拐点通常还要沿法线往里挪一点，避免贴墙角走。

### 7.3 分帧寻路

A* 主循环可暂停：open / g / parent 存在对象里，每帧只展开固定数量节点（demo 的 `Search::step(budget)`）。

| E7：迷宫左上 → 右下（路径 36968 格） | 帧数 | 单帧最大 | 总耗时 |
|---|---|---|---|
| 不分帧 | 1 | **4.312 ms** | 4.312 ms |
| 每帧 20000 节点 | 6 | 0.964 ms | 3.842 ms |
| 每帧 5000 节点 | 21 | 0.248 ms | 3.897 ms |
| 每帧 1000 节点 | 103 | **0.045 ms** | 3.527 ms |

总工作量不变（102253 次展开），峰值从 4.3 ms 降到 0.045 ms。工程上做成**全局寻路请求队列**：每帧总预算（如 2 万节点或 1 ms）；优先级（玩家单位、视野内、距离近）；请求合并 / 作废（连点三次只留最后一次、单位死亡取消）；等待期间先朝直线方向起步或播动作；Detour 有分帧接口和 `dtPathQueue`。

### 7.4 动态障碍与重新规划

| 情况 | 做法 |
|---|---|
| 门开关、桥塌、建筑放下 | 格子改格子并更新连通块；navmesh 按 tile 局部重建（TileCache 圆柱 / 盒子临时障碍） |
| 已规划路径被挡 | 每帧只检查前方几个路点；被挡时从当前位置重新寻路，不要每帧重寻 |
| 其他移动单位 | **不放进寻路图**（一直在动，路径会抖），交给局部避障 |
| 频繁小范围变化 | LPA* / D* Lite 复用上次结果（机器人常用，游戏少用） |

### 7.5 流场：很多单位去同一个地方

### 7.6 全局寻路与局部避障是两层

```
全局寻路   A* / HPA* / navmesh：绕开静态障碍，给出路点或走廊      ← 事件触发，可分帧 / 异步
   ↓
路径跟随   朝下一个拐点前进；到达半径内切下一个；检查前方是否被挡  ← 每帧 O(1)
   ↓
转向       seek / arrive / separation：变成平滑的期望速度         ← 每帧
   ↓
局部避障   RVO / ORCA：根据周围单位速度选一个不相撞的实际速度     ← 每帧，空间划分加速
动态的东西（其他单位）交给下两层，静态的东西（墙、地形）交给最上层
```

> ⚠️ “两个单位窄路卡住怎么办”是局部避障问题：全局不考虑移动单位；局部 RVO/ORCA 让行；死锁时超时、一方等待或后退、临时把对方当障碍重寻。MOBA 小兵通常是“沿兵线路点 + 分离力 / 避让”，而不是每个小兵都跑 A*。

### 7.7 帧同步：寻路必须逐位确定

```
E9 · 两份堆实现（std::priority_queue 与自写 4 叉堆），同一图、同一批 40 次查询
[开阔地]  只比 f：路径不同 40 / 40（代价不同 0）   比 (f, h)：0 / 40   全序 (f, h, 下标)：0 / 40
[房间]    只比 f：路径不同 39 / 40（代价不同 0）   比 (f, h)：0 / 40   全序 (f, h, 下标)：0 / 40
```

只比 f 时代价都最短，但走法几乎全不同。“换堆实现”在真实项目里对应：**Windows 用 MSVC STL，Android/iOS 用 libc++，服务器用 libstdc++**。(f, h) 本批碰巧无差异，但 f、h 都相同的节点仍存在（关于起终点连线对称的格子），只有加上下标的**全序**才从原理上保证一致。

**帧同步寻路检查清单**
1. 代价与启发用**整数 / 定点**，不用 float 和 sqrt（8 方向 10/14 或 1000/1414；欧几里得用整数平方根或定点）。
2. 比较器是**全序** (f, h, 节点编号)。
3. **邻居遍历顺序固定**；navmesh 邻接表顺序来自确定的烘焙数据。
4. **不依赖哈希容器遍历顺序**。
5. **导航数据各端相同**（烘焙产物作为资源，不要各端运行时生成）。
6. **动态障碍按逻辑帧生效**。
7. **异步 / 分帧结果在确定的逻辑帧生效**（如请求帧 + 2）；展开预算用逻辑上的固定节点数，不能按毫秒分帧。
8. **平滑、视线检测同样确定**（整数格子检测）。

> 🎮 **MOBA 里哪些地方用寻路**：摇杆移动本身不需要寻路（碰墙沿墙滑）。寻路常见于 AI 英雄（人机、掉线托管）、召唤物 / 宠物跟随、野怪脱战回出生点、点击小地图自动移动、小兵离开兵线追击。都在逻辑帧里运行，清单全部适用。排查不同步时把每次寻路的输入（起终点、地图版本）与路径哈希写进逻辑日志，第一处不一致往往直接定位问题。

## 9. 40 道面试追问（精简答案）

**基础**
1. **f、g、h？** g 已走真实代价，h 剩余估计，f = g + h；每次展开 f 最小。
2. **与 Dijkstra / BFS / 贪心的关系？** 只差取哪个：BFS 最早入队（等权最短）、Dijkstra g 最小、贪心 h 最小、A* g + h 最小；h ≡ 0 即 Dijkstra。
3. **open / closed？** open 已发现未展开（优先队列）；closed 已展开 g 最优，一致 h 下不再更新。
4. **为何出队时判终点？** 入队时 g 可能不是最优；成为 f 最小时才保证（最优性证明依赖）。
5. **8 方向代价与切角？** 直 1 斜 √2（10/14、1000/1414）；禁止切角使寻路与碰撞一致。
6. **三种寻路图？** 格子（简单、动态好改、节点多）、路点（最少、生硬）、navmesh（3D 主流、生成复杂）。
7. **何时用 BFS / Dijkstra？** 等权图用 BFS；没有单一终点（移动范围、最近目标、距离场 / 流场）用 Dijkstra。
8. **如何得到路径？** 更新 g 时记 parent，取出终点后回溯再反转。

**启发函数**
9. **可采纳 / 一致？** h ≤ h* 保最短；h(n) ≤ c + h(n') 保出队即最优、不重开；一致 ⇒ 可采纳。
10. **4 / 8 / 任意角度？** 曼哈顿 / Octile / 欧几里得；8 方向用曼哈顿高估（最多长 9.8%），欧几里得低估搜得多。
11. **h 高估 / h = 0？** 高估更快不保证最短；h = 0 即 Dijkstra。
12. **地形代价？** 乘最便宜地形单价；引导变弱、变慢。
13. **加权 A*？** f = g + w·h，代价 ≤ w × 最优；随机图 w = 1.2 展开 1/10、长 3%，凹形陷阱无效。
14. **平局决胜？** f 同取 h 小；开阔地 228 对 10772；帧同步要全序 (f, h, id)。
15. **两个 h 组合？** 取 max，仍可采纳且更强（ALT）。
16. **整数代价注意？** 重查可采纳性：1414 < 1000√2，长对角线欧几里得（取整）略高估；Detour 乘 0.999。

**正确性与复杂度**
17. **证明最优性？** 反证：最短路径上有 f ≤ C* 的节点在 open，终点不可能以更大 g 先出队。
18. **一致性为何出队即最优？** 沿边 f 不减 → 按 f 非降序出队 → 能给它更短路径的节点都已出队并松弛过它。
19. **复杂度？** O(E log V) 时间、O(V) 空间；树视角 O(b^d)，完美 h 时 O(d)；瓶颈常是内存。
20. **最优效率？** 同一可采纳 h 且保最短的算法都必须展开 f < C* 的全部节点，A* 只展开这些。
21. **最坏情况与应对？** 不可达（E8：20.5 ms）、凹形误导；连通块编号 O(1)、展开上限、返回最近点、终点吸附。
22. **只可采纳不一致？** 节点可能需重开（最坏指数），或接受次优。

**工程实现**
23. **open 数据结构？** 二叉堆 + 惰性删除（1.30 ms），索引堆 1.39 ms，std::set 2.21 ms。
24. **每次清空整图？** 不要，generation 计数 O(1) 复位（504 对 5.6 us）；gen 回绕时清零一次。
25. **常数优化？** 邻居偏移预计算、外围边框、int32、位图、SoA、容器复用、平局决胜、桶队列。
26. **一帧很多请求？** 全局队列 + 每帧预算 + 优先级 + 合并作废；分帧（峰值 4.3 → 0.045 ms）；异步。
27. **多线程？** 地图只读共享、搜索状态每线程一份；修改用锁 / 双缓冲；帧同步结果确定帧生效。
28. **路径锯齿？** 拉绳（路点少 40%、短 4%、耗时不到 1%）、Theta*、navmesh 漏斗。
29. **常见 bug？** 入队判终点、不检查 closed、更新后不入堆、h 不匹配、斜走代价错、切角、float ==、不处理不可达。

**加速算法**
30. **JPS 原理？** 剪掉对称路径，沿直线 / 对角线跳，只在终点 / 强制邻居处停下入堆；保证最短。
31. **JPS 一定快吗？** 不一定：开阔地慢 25 倍，房间 / 陷阱快 4.8～7.5 倍；只适用均匀代价格子图；JPS+ 预计算。
32. **HPA*？** 切簇、入口、簇内预计算 → 抽象图 A* → 分段细化；快一到两个数量级，近似最短。
33. **双向 A* 的坑？** 第一次相遇不一定最短，需 μ ≤ max(两侧最小 f) 终止。
34. **ALT？** 地标 + 三角不等式 h = max|d(L,G) − d(L,n)|，可采纳一致，内存 k × V。

**游戏场景**
35. **navmesh 流程？** Recast 烘焙（体素化 → 过滤 → 半径收缩 → 区域 → 凸多边形 → 细节）；Detour 吸附 → 多边形 A* → 漏斗 → 跟随避让。
36. **漏斗算法？** 沿入口维护漏斗左右边，越过时端点成拐点，近似 O(n)。
37. **动态障碍？** 格子改格 + 连通块；navmesh tile 重建；只检查前方路点；移动单位交给局部避障。
38. **200 个单位同一目标？** 流场：一次 Dijkstra 得积分场 → 方向场 → 单位 O(1) 查表。
39. **窄路互卡？** 局部避障 RVO / ORCA，死锁超时 / 等待 / 后退 / 临时当障碍重寻。
40. **帧同步寻路？** 整数 / 定点、全序比较、固定邻居顺序、不依赖哈希遍历、导航数据一致、确定帧生效、平滑也整数化（E9：只比 f 40/40 不同，全序后一致）。

## 速记卡（一页纸背完 A*）

- **核心**：f = g + h，展开 open 中 f 最小者；出队时判终点；ng < g 才更新；open 空即不可达。
- **家族**：BFS（等权）、Dijkstra（h = 0）、贪心（只看 h）、加权 A*（≤ w 倍最优）。
- **启发**：可采纳 → 最短；一致 → 出队即最优、不重开。4 向曼哈顿、8 向 Octile、任意角度欧几里得；有地形乘最小单价。
- **证明**：最短路径上总有 f ≤ C* 的节点在 open；A* 展开 f < C* 的全部节点，最优效率。
- **复杂度**：O(E log V) 时间、O(V) 空间；最坏是不可达 → 连通块编号预判。
- **工程**：priority_queue + 惰性删除；generation 复位；f 同取 h 小；整数代价；分帧 + 请求队列；多线程状态各一份。
- **加速**：JPS（均匀格子、开阔 + 障碍）、JPS+、HPA*、ALT、双向（注意终止条件）；拉绳 / Theta* / 漏斗做平滑。
- **游戏**：Recast/Detour = 烘焙 + 多边形 A* + 漏斗；流场管大量单位；全局寻路与局部避障分层；帧同步要整数 + 全序 + 确定帧生效。
