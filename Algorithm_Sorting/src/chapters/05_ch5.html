CHAPTER 05

快速排序：最快的平均，最危险的最坏

面试里被问得最多、追问得最深的排序。要讲清楚三件事：分区怎么写，pivot 怎么选，最坏情况怎么防。

本章目标
  • 能手写 Lomuto 和 Hoare 两种分区，说出它们的差别和各自的坑
  • 理解退化的原因：有序输入、大量重复、递归过深导致栈溢出（本章有实测）
  • 掌握三路快排、递归短边、三数取中 / ninther 这些工程手段
  • 能用快速选择在 O(n) 平均时间内求第 K 大

5.1 核心思想：分区

选一个基准值 pivot，把数组分成两部分：左边都 ≤ pivot，右边都 ≥ pivot，然后递归地处理两边。和归并相反，快排的工作在“分”这一步做完，“合”什么都不用做。分区完成时，左右两部分之间已经有序了。

它的效率完全取决于分得是否均匀。每次都对半分，递归深度是 log₂n，总共 O(n log n)；每次都分成 0 和 n−1，递归深度是 n，总共 O(n²)。

5.2 Lomuto 分区：单指针，好写但有坑

取最后一个元素作 pivot。用 i 标记“小于区”的下一个空位，j 从左往右扫描：遇到比 pivot 小的元素，就和 a[i] 交换，i 加 1。扫完以后，把 pivot 和 a[i] 交换，pivot 就到了它的最终位置。

int partition_lomuto(int* a, int lo, int hi) { // [lo, hi]，返回 pivot 的最终下标 int p = a[hi], i = lo; for (int j = lo; j < hi; ++j) if (a[j] < p) std::swap(a[i++], a[j]); std::swap(a[i], a[hi]); return i; // 递归 [lo, i-1] 和 [i+1, hi]，pivot 本身不再参与 }

Lomuto 有两个缺陷：一是交换次数多，每个比 pivot 小的元素都要换一次；二是遇到大量相等元素会退化。全部相等时 a[j] < p 永远为假，i 一直不动，每次都分成 0 和 n−1，于是变成 O(n²)。

5.3 Hoare 分区：双指针相向而行

Hoare 在 1961 年发明快排时用的就是这种分区：i 从左往右找 ≥ pivot 的元素，j 从右往左找 ≤ pivot 的元素，两边都找到就交换，直到 i、j 相遇。

void quick_sort(int* a, int lo, int hi) { // [lo, hi] if (lo >= hi) return; int p = a[lo + (hi - lo) / 2]; // 取中间位置的值：有序输入不会退化 int i = lo - 1, j = hi + 1; while (i < j) { do ++i; while (a[i] < p); // 严格小于：遇到等于 pivot 的也停下 do --j; while (a[j] > p); if (i < j) std::swap(a[i], a[j]); } quick_sort(a, lo, j); // 用 j 划分 quick_sort(a, j + 1, hi); }
对比项LomutoHoare
指针单向，i 慢 j 快双向，相向而行
交换次数（随机）约 n/2约 n/6，少约 3 倍
全部相等退化 O(n²)每次都停下交换，正好对半分
分区后 pivot在最终位置，不再参与递归不一定在最终位置，两侧都可能包含它
递归区间[lo, i−1] 和 [i+1, hi][lo, j] 和 [j+1, hi]
面试注意：Hoare 的三个经典 bug
  1. 用 <= 代替 <：while (a[i] <= p) 在全等数组上会让 i 一路冲出右边界。
  2. pivot 取 a[hi] 又用 j 划分：比如 [1, 2] 以 2 为 pivot，i 和 j 都停在下标 1，返回 j = 1，于是又递归 [0, 1]，形成死循环。用 j 划分时，pivot 必须取 a[lo] 或向下取整的中点。反过来，如果用 i 划分（[lo, i−1]、[i, hi]），pivot 就不能取 a[lo]。
  3. 把 j 写成 i：两种组合不能混用。最稳妥的做法是背熟上面这一套。

5.4 pivot 怎么选

策略做法弱点谁在用
首 / 尾元素直接取 a[lo] 或 a[hi]有序、逆序输入直接 O(n²)教科书
中间元素a[(lo+hi)/2]可以被构造出最坏输入（如“风琴管”序列）手写模板
随机随机选一个下标期望 O(n log n)；要调随机数，结果不可复现算法课、面试
三数取中lo、mid、hi 三者的中位数仍可被构造攻击（McIlroy 1999），概率极低libstdc++
九数取中（ninther）取三组“三数取中”的中位数更稳，代价是多做几次比较MSVC（区间 > 40）、pdqsort（区间 > 128）
深入一层：确定性的 pivot 总能被攻击

McIlroy 在《A Killer Adversary for Quicksort》里构造了一个“对抗比较器”：它在排序过程中动态决定元素的大小，能让任何确定性选 pivot 的快排都跑出 O(n²)。这在服务器上可能变成拒绝服务攻击。所以工业实现不靠 pivot 选得巧来保证最坏情况，而是监控递归深度，超过阈值就换成堆排序，这就是 introsort（第 8 章）。

每层递归大约占 100 字节栈空间。Windows 主线程默认栈是 1 MB，只要 2 万个有序元素就能把它撑爆。游戏引擎的 Job 线程、协程或纤程的栈通常更小（几十 KB 很常见），几百层就溢出。递归短边的工程版排 100 万个元素，最大深度只有 16。

游戏客户端视角：线上崩溃的一种典型来源

“策划配了一张已经排好序的表，加载时用自己写的快排再排一次，在 Job 线程里栈溢出。”这类问题在开发机上很难复现，因为开发机的数据往往是乱序的，或者跑在主线程上栈更大。结论：不要在引擎代码里手写快排，用 std::sort。真要手写，就必须递归短边并加深度限制。

5.6 递归短边、循环长边：把栈深压到 O(log n)

每次分区后，只对较短的一边递归，较长的一边改成在当前函数里用循环继续处理。每次递归调用处理的区间长度都不超过父区间的一半，所以递归深度 ≤ log₂n，和输入无关。注意，这只保证了栈深，时间复杂度最坏仍然是 O(n²)。

template > void quick_sort_engineered(T* a, int lo, int hi, Less less = {}) { // [lo, hi] while (hi - lo > 16) { int mid = lo + (hi - lo) / 2; // 三数取中：结束后 a[lo] <= a[mid] <= a[hi]，两端还能起到哨兵作用 if (less(a[mid], a[lo])) std::swap(a[mid], a[lo]); if (less(a[hi], a[lo])) std::swap(a[hi], a[lo]); if (less(a[hi], a[mid])) std::swap(a[hi], a[mid]); T p = a[mid]; int i = lo - 1, j = hi + 1; for (;;) { do ++i; while (less(a[i], p)); do --j; while (less(p, a[j])); if (i >= j) break; std::swap(a[i], a[j]); } if (j - lo < hi - j) { quick_sort_engineered(a, lo, j, less); lo = j + 1; } // 递归短边 else { quick_sort_engineered(a, j + 1, hi, less); hi = j; } // 长边留给 while } insertion_sort(a + lo, hi - lo + 1, less); // ≤ 17 个元素：插入排序收尾 }

5.7 三路快排：专治大量重复

游戏数据里重复键非常多：品质只有 5 档、职业只有 6 种、队伍只有 2 个。Dijkstra 的“荷兰国旗”分区把数组分成三段：< p、= p、> p。中间那段已经就位，不再参与递归。重复越多，递归规模缩小得越快。

template > void quick_sort_3way(T* a, int lo, int hi, Less less = {}) { // [lo, hi] if (lo >= hi) return; std::swap(a[lo], a[lo + rand() % (hi - lo + 1)]); // 随机 pivot（示意；工程上用 ） T p = a[lo]; int lt = lo, i = lo + 1, gt = hi; while (i <= gt) { if (less(a[i], p)) std::swap(a[lt++], a[i++]); else if (less(p, a[i])) std::swap(a[i], a[gt--]); // 换过来的元素还没看过，所以 i 不动 else ++i; } quick_sort_3way(a, lo, lt - 1, less); // [lt, gt] 全等于 p，跳过 quick_sort_3way(a, gt + 1, hi, less); }
实测 E5：N = 100 万，三路的长处和代价

大量重复（16 种值）：三路 7.95 ms，工程版 Hoare 16.29 ms，std::sort 9.68 ms。有序：三路 20.84 ms，Hoare 3.94 ms。三路每处理一个元素都要做两次比较、交换也更多，所以没有重复时反而更慢。MSVC 的 std::sort 在分区时会把等于 pivot 的元素聚到中间（_Partition_by_median_guess_unchecked 返回一个相等区间），兼顾了两种情况。

5.8 为什么快排在实践中最快

快排的平均比较次数约为 1.39 n log₂n，比归并的 ~n log₂n 还多。它快在每一步的代价小：

  • 内层循环极简：和放在寄存器里的 pivot 比较，然后指针加 1。
  • 访存顺序：两个指针各自顺序扫描，硬件预取效果好；区间缩小到能放进 L1 以后，后面的操作全部命中缓存。
  • 写得少：E2（n=1000 随机）中，工程版快排写 6730 次，归并写 18686 次，堆写 11585 次。
  • 原地：不需要额外缓冲，没有分配开销。

5.9 快速选择：O(n) 求第 K 大

只想要第 K 小的元素时，分区以后只需要进入包含 K 的那一边，另一边直接丢掉。平均工作量是 n + n/2 + n/4 + … ≈ 2n，即 O(n)。最坏仍是 O(n²)；用中位数的中位数（BFPRT）选 pivot 可以保证最坏 O(n)，但常数太大，工程上很少用。std::nth_element 是 introselect：快速选择 + 深度兜底。

int quick_select(std::vector& a, int k) { // 返回第 k 小（k 从 0 开始），会打乱 a int lo = 0, hi = int(a.size()) - 1; while (lo < hi) { int p = a[lo + (hi - lo) / 2], i = lo - 1, j = hi + 1; while (i < j) { do ++i; while (a[i] < p); do --j; while (a[j] > p); if (i < j) std::swap(a[i], a[j]); } if (k <= j) hi = j; else lo = j + 1; // 只保留包含 k 的那一边 } return a[k]; }

5.10 交互实验：三种快排对比

先选“快排 · Lomuto”，数据切到“已有序”，观察每次分区后右侧都是空的、递归一层只少一个元素；再换成“Hoare + 三数取中”。最后选“大量重复”，对比三路划分。

面试注意：快排高频追问清单
  • 最坏情况什么时候出现？ pivot 总是取到最大或最小值：首 / 尾作 pivot 遇到有序或逆序输入；Lomuto 遇到全相等的输入。
  • 空间复杂度？ 平均 O(log n)，朴素实现最坏 O(n)；递归短边可以保证 O(log n)。不是 O(1)。
  • 稳定吗？ 不稳定，因为分区时有远距离交换。
  • 和堆排比？ 两者平均都是 n log n，但快排缓存友好、写得少，实测更快（E5：47 ms 对 74 ms）；堆排的优势是最坏有保证、O(1) 空间。
  • 怎么避免最坏情况？ 随机 / 三数取中 / ninther 选 pivot 只能降低概率；真正的保证要靠 introsort 的深度限制，切换到堆排。
本章速记
  • Lomuto：好写，pivot 最终归位；交换多，全相等时退化。Hoare：交换少约 3 倍，全相等时对半分；pivot 不一定归位，递归 [lo, j]、[j+1, hi]。
  • 退化实测：有序的 16000 个数，朴素版比较 1.28 亿次、递归 15999 层；1 MB 栈遇到 2 万个有序元素就溢出。
  • 工程四件套：三数取中 / ninther、Hoare、小区间插排、递归短边；再加深度限制 + 堆排兜底，就是 introsort。
  • 三路快排专治重复键（E5：7.95 ms 对 16.29 ms）；快速选择平均 O(n)。
