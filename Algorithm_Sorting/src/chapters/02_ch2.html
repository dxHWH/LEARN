PART TWO

第二部分　O(n²) 三兄弟与希尔排序

冒泡、选择、插入是所有排序的起点。它们在大数据上没有竞争力，但其中的想法（相邻交换、找最值、有序区扩张）在每一个工业排序里都能找到。

CHAPTER 02

冒泡排序与选择排序

一个靠相邻交换让最大值“浮”到末尾，一个每轮直接找出最小值换到前面。两者都是 O(n²)，但性格完全不同。

本章目标
  • 写出带两种优化的冒泡排序（无交换提前退出、记录最后交换位置）
  • 举出选择排序不稳定的反例，说清它“交换次数最少”的意义
  • 理解为什么同样是 O(n²)，实测速度可以差好几倍

2.1 冒泡排序：相邻比较，大的往后沉

从头到尾比较每一对相邻元素，前一个比后一个大就交换。这样一趟下来，当前范围内最大的元素一定会被“推”到最后，就像气泡上浮一样。每趟结束后有序区增加一个元素，n−1 趟后全部有序。

伪代码

bubbleSort(a, n): end = n - 1 while end > 0: last = 0 // 本趟最后一次交换的位置 for j = 0 to end - 1: if a[j] > a[j+1]: // 严格大于才交换 → 稳定 swap(a[j], a[j+1]) last = j end = last // last 之后的部分已经有序；本趟无交换时 last = 0，循环结束

C++ 实现

template > void bubble_sort(T* a, int n, Less less = {}) { int end = n - 1; while (end > 0) { int last = 0; for (int j = 0; j < end; ++j) { if (less(a[j + 1], a[j])) { // 只用 <，保证相等不交换 std::swap(a[j], a[j + 1]); last = j; } } end = last; // 优化 1：没交换就退出；优化 2：[last+1, end] 已有序，下趟不用再扫 } }
深入一层：两种优化各解决什么问题
  • 提前退出：一趟没有交换说明已经有序。它让最好情况（输入有序）从 O(n²) 降到 O(n)。实测 E3 中，有序的 2 万个数只要 0.01 ms，随机的要 75 ms。
  • 记录最后交换位置：如果数组尾部本来就有序，一趟就能把这段整体划进有序区，不用每趟只前进一格。
  • 两种优化都改变不了一个弱点：小元素在末尾时，每趟只能向前挪一格（俗称“乌龟”）。比如 [2,3,4,5,1] 需要 4 趟。鸡尾酒排序（双向冒泡）交替从左往右、从右往左扫，能缓解这个问题，但仍然是 O(n²)。

稳定：只交换相邻元素，而且严格大于才交换，相等的元素不会互相越过。原地：O(1) 额外空间。

2.2 选择排序：每轮找最小，换到最前面

把数组分成左边的有序区和右边的无序区。每一轮在无序区里扫描一遍找出最小值，和无序区的第一个元素交换，有序区就增加一个元素。

它的问题出在“交换”这一步：被换走的那个元素可能一下跳过很远，越过了和它相等的元素。下面这个例子里，5a 和 5b 的键都是 5，排序前 5a 在前面：

template > void selection_sort(T* a, int n, Less less = {}) { for (int i = 0; i < n - 1; ++i) { int m = i; for (int j = i + 1; j < n; ++j) if (less(a[j], a[m])) m = j; // 只记下标，不交换 if (m != i) std::swap(a[i], a[m]); // 每轮最多交换一次 } }

复杂度与性质

  • 比较次数永远是 n(n−1)/2，和输入无关。所以它不是自适应的，有序数组也要跑满 O(n²)。实测 E3 中，有序和随机都约 280 ms。
  • 交换次数 ≤ n−1，这是所有算法里最少的一类（E2：n=1000 随机，只写了 1982 次，而冒泡写了 48 万次）。当“写”远比“读”昂贵时（比如 Flash 存储），它反而有优势。如果要让写次数绝对最少，可以用 Cycle Sort。
  • 不稳定（见图 2-2）。如果非要稳定，可以把“交换”改成“把最小值插到前面、中间整体后移”，代价是每轮 O(n) 次移动；或者在链表上实现。
变体：双向选择

每轮同时找出最小值和最大值，分别放到两端，扫描轮数减半，但比较次数基本不变（每个元素仍要和 min、max 各比一次）。面试里提一下就够了，它不会改变复杂度的量级。

2.3 同样是 O(n²)，为什么实测差好几倍

复杂度只描述增长的趋势，不包含常数。三兄弟的比较次数差不多（选择 n²/2，冒泡约 n²/2，插入约 n²/4），但每次比较附带的工作差别很大：

  • 插入排序：平均只比较 n²/4 次，每次后移只有一次赋值，内层循环遇到不大于 key 的元素就停。所以它在三兄弟里最快。
  • 冒泡排序：一次交换要三次赋值，而且随机数据下 if 分支几乎没法预测。
  • 选择排序：m = j 让下一次比较的 a[m] 依赖上一次的结果。如果编译器把它生成成条件传送（cmov），就会形成一条循环携带的依赖链，CPU 的乱序执行没法把这些比较并行起来。这一点要谨慎看待：同一台机器上另一种写法（demos/sel_test.cpp）只要 38 ms。这说明O(n²) 算法的常数对代码生成非常敏感，比较次数却是固定的。
面试注意

被问“冒泡和插入哪个快”，答“插入更快”，然后给出两个理由：①平均比较次数少一半（n²/4 对 n²/2）；②每次移动只有一次赋值，冒泡的一次交换是三次赋值。如果能补一句“二者的交换 / 移动次数都等于逆序对数”，就说明你理解了本质。

2.4 交互实验

切到“已有序”，看冒泡怎么一趟就结束；切到“逆序”，看选择排序的比较次数为什么和随机数据完全一样。

本章速记
  • 冒泡：相邻交换、稳定；“提前退出”让最好情况变成 O(n)；交换次数 = 逆序对数。
  • 选择：比较次数固定 n²/2，不自适应；交换 ≤ n−1 次；远距离交换导致不稳定。
  • 同为 O(n²)，实测插入 < 冒泡 < 选择，常数差距可达十几倍。
自测：冒泡排序最好情况是 O(n) 吗？

只有加了“一趟没有交换就退出”的优化才是 O(n)。教科书上不带标志位的版本，任何输入都要做 n(n−1)/2 次比较。回答时要说明前提。

自测：选择排序可以做成稳定的吗？

可以。找到最小值后，不和 a[i] 交换，而是把 a[i..m−1] 整体后移一格，再把最小值放到 a[i]。这样相等元素的相对顺序不变，但每轮多了 O(n) 次移动。在链表上做，摘下节点再插入就行，没有移动代价。
