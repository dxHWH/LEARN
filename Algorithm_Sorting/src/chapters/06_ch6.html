CHAPTER 06

堆排序：最坏有保证的原地排序

把数组看成一棵完全二叉树，反复取出堆顶的最大值放到末尾。理论上很完美，实际跑起来却不快。

本章目标
  • 掌握数组和完全二叉树之间的下标映射，能写出 siftDown
  • 理解为什么自底向上建堆是 O(n)，而不是 O(n log n)
  • 说清堆排为什么比快排慢，以及它在哪些地方不可替代

6.1 二叉堆：用数组存一棵完全二叉树

大顶堆：每个节点都不小于它的孩子，所以堆顶 a[0] 是最大值。因为是完全二叉树，节点可以按层序紧密地存在数组里，不需要指针：

6.2 两个阶段：建堆，然后反复取堆顶

  1. 建堆：从最后一个非叶子节点 n/2−1 开始往前，对每个节点做 siftDown（下沉）。全部做完，整个数组就是一个大顶堆。
  2. 排序：把堆顶（最大值）和堆的最后一个元素交换，最大值就到了最终位置；堆的大小减 1，对新的堆顶做 siftDown 恢复堆的性质。重复 n−1 次。
template void sift_down(T* a, int i, int n, Less& less) { // 在 a[0, n) 中让 a[i] 下沉 T v = std::move(a[i]); for (;;) { int c = 2 * i + 1; if (c >= n) break; if (c + 1 < n && less(a[c], a[c + 1])) ++c; // 取较大的孩子 if (!less(v, a[c])) break; // v >= 孩子：找到位置 a[i] = std::move(a[c]); // 孩子上移（“挖坑”法，比反复 swap 少一半赋值） i = c; } a[i] = std::move(v); } template > void heap_sort(T* a, int n, Less less = {}) { for (int i = n / 2 - 1; i >= 0; --i) sift_down(a, i, n, less); // 建堆：O(n) for (int end = n - 1; end > 0; --end) { std::swap(a[0], a[end]); // 最大值归位 sift_down(a, 0, end, less); // O(log n) } } // 等价的 STL 写法：std::make_heap(b, e); std::sort_heap(b, e);

6.3 为什么建堆是 O(n)

直觉上，n/2 个节点各下沉 O(log n)，应该是 O(n log n)。但大多数节点都在底层，下沉不了几层：高度为 h 的节点最多有 n/2h+1 个，每个最多下沉 h 层，所以总代价是

Σh≥0 (n / 2h+1) · h = n · Σ h/2h+1 = n · 1 = O(n)

一半的节点是叶子，根本不用动；四分之一的节点只下沉 1 层……真正下沉 log n 层的只有根节点一个。反过来，如果一个个 push 进去建堆（上浮），就是 O(n log n)，因为多数节点在底部，要上浮很多层。这是一个常见的追问点。

6.4 复杂度与性质

性质结论
时间最好、平均、最坏都是 O(n log n)；比较次数约 2n log₂n（E2：n=1000 随机，16840 次，约为归并的 1.8 倍）
空间O(1)，迭代实现，没有递归，这是它最大的优点
稳定✘：堆顶和堆尾的交换跨度非常大（E1 逆序对 2916，所有算法里最多）
自适应✘：输入有序也一样要建堆、拆堆（E5：有序 35.90 ms，快排 3.94 ms）

6.5 为什么堆排在实践中慢

  • 缓存不友好：下沉时从 i 跳到 2i+1，越往下跨度越大。100 万个 int 是 4 MB，下层节点之间相隔几十 KB 甚至几 MB，几乎每次访问都会缓存未命中。快排的两个指针都是顺序扫描。
  • 比较次数多：每下沉一层要比较两次（先比较两个孩子，再和孩子比较），总数约 2n log n。
  • 分支难预测：“左孩子大还是右孩子大”基本是随机的。
  • 拆堆阶段反复把小元素换到堆顶，它几乎一定会一路沉到底，做了很多无用的比较。
深入一层：两种改进

Floyd 的自底向上堆排（bottom-up heapsort）：既然换上来的元素多半会沉到底，那就先沿着“较大孩子”的路径直接走到叶子（每层只比较一次），再从叶子往上找它真正的位置。比较次数能降到约 n log₂n。d 叉堆（如 4 叉堆）：树高变成 log₄n，一个节点的孩子在内存里相邻，缓存表现更好，优先队列常用这种结构。

6.6 不可替代的场合

introsort 的兜底

快排递归深度超过 2⌊log₂n⌋ 时，std::sort 对当前区间改用堆排，从而保证最坏 O(n log n)，而且不需要额外内存。

内核和嵌入式

Linux 内核的 lib/sort.c 是堆排：没有递归，不会撑爆很小的内核栈；O(1) 内存；最坏情况可预测。

Top-K / partial_sort

维护大小为 K 的堆，扫描一遍是 O(n log K)。E9：100 万个积分取前 100，小顶堆 0.41 ms，全量排序 58.61 ms。

游戏里的优先队列

技能 / Buff 定时器（按到期时间的小顶堆）、A* 的 open list、事件调度、k 路归并，本质上都是堆。

6.7 交互实验

注意看两个阶段：前半段在建堆，柱子没有明显规律；后半段每轮都把当前最高的柱子换到右侧，变绿就位。

面试注意
  • 建堆 O(n) 要会证明，至少要能说出“大多数节点在底层，下沉不了几层”。
  • 升序排序用大顶堆（每轮把最大值放到末尾）。很多人会下意识地说“小顶堆”，那样得到的是降序。
  • std::priority_queue 默认是大顶堆；要小顶堆得写 std::priority_queue<int, std::vector<int>, std::greater<int>>。
本章速记
  • 数组下标：父 (i−1)/2，孩子 2i+1、2i+2；升序用大顶堆。
  • 自底向上建堆 O(n)；排序阶段 n−1 次下沉，每次 O(log n)。
  • 最坏 O(n log n)、O(1) 空间、不稳定、不自适应；缓存不友好，实测比快排慢约 56%。
  • 用途：introsort 兜底、内核排序、Top-K、优先队列、定时器。
