第四部分　非比较排序：绕开 n log n

不再问“谁大谁小”，而是直接利用键的数值结构：用键做数组下标，或者按数位逐位分配。代价是对键有要求，并且要额外的内存。

CHAPTER 07

计数排序、基数排序、桶排序

三者都是“分配式”排序。计数排序是基础，基数排序是多轮计数排序，桶排序是按值域粗分以后再细排。

本章目标
  • 写出稳定的计数排序，理解前缀和与“倒序回填”各自的作用
  • 理解 LSD 基数排序为什么要求每一趟都稳定，并能对负数、浮点数排序
  • 知道桶排序在什么分布下有效、什么情况下会退化
  • 明白它们在游戏里的典型用途：渲染 sort key、分组、直方图

7.1 计数排序：直接把值当下标

如果键是 [0, k) 范围内的整数，可以开一个大小为 k 的计数数组，数一下每个值出现了几次，再按值从小到大输出。只要统计和输出两遍扫描，时间 O(n + k)。

只输出“值”时直接按计数展开就行。但如果要排的是带着其他字段的记录，并且要求稳定，就需要“前缀和 + 倒序回填”。下例中 a/b/c 用来区分键相同的记录：

// key(x) 返回 [0, k) 的整数 template void counting_sort(std::vector& a, int k, Key key) { std::vector cnt(k + 1, 0); for (const T& x : a) ++cnt[key(x) + 1]; // 存到 cnt[v+1] for (int v = 0; v < k; ++v) cnt[v + 1] += cnt[v]; // 前缀和：cnt[v] 变成 v 段的起始位置 std::vector out(a.size()); for (const T& x : a) out[cnt[key(x)]++] = x; // 正序扫描 + 从起始位置往后填，同样稳定 a.swap(out); }

图 7-1 用的是“结束位置 + 倒序扫描”（教材常见写法），代码用的是“起始位置 + 正序扫描”，两者等价，都是稳定的。不能混用：结束位置配正序扫描，同键记录会被反过来。

性质结论
时间O(n + k)，和输入顺序无关
空间O(n + k)：输出数组 + 计数数组
稳定✔（按上面的写法）
适用k 和 n 同一量级或更小。k 远大于 n 时（比如对 100 个 32 位整数排序）就得不偿失
游戏客户端视角：计数排序到处都是，只是不叫这个名字
  • 背包按品质（白 / 绿 / 蓝 / 紫 / 橙，k=5）分组；英雄列表按职业分组。
  • 粒子按发射器分组、实例按网格 ID 分批，都是“先计数，再前缀和得到偏移，再回填”。GPU 上用 compute shader 做的直方图 + prefix sum 完全是同一套思路。
  • 空间哈希网格：每个格子统计一下物体数，做前缀和，就得到一个紧凑的“格子 → 物体列表”数组，比给每个格子开一个 std::vector 对缓存友好得多。

7.2 基数排序：按位多轮计数

键的值域太大（比如 32 位整数）时，直接计数需要 40 亿个计数器。基数排序把键拆成若干“位”（比如每 8 比特一位，共 4 位），从最低位开始，每一位做一次稳定的计数排序，这叫 LSD（Least Significant Digit first）基数排序。

为什么每一趟都必须稳定？以 170 和 75 为例：按十位排时，两者十位都是 7，平局。它们的个位顺序（0 < 5）是上一趟排好的，只有稳定排序才能把这个顺序保留下来。如果这一趟不稳定，75 就可能跑到 170 前面，结果错误。这正是第 1 章说的多关键字排序：先按次要键排，再用稳定排序按主要键排。

// 对 uint64_t 键做 LSD 基数排序；tmp 是调用方提供的、和 a 等长的缓冲（可每帧复用） template void radix_sort_u64(T* a, T* tmp, size_t n, KeyFn key) { T* src = a; T* dst = tmp; for (int pass = 0; pass < 8; ++pass) { const int shift = pass * 8; uint32_t cnt[257] = {}; for (size_t i = 0; i < n; ++i) ++cnt[((key(src[i]) >> shift) & 0xFF) + 1]; if (std::find(cnt + 1, cnt + 257, uint32_t(n)) != cnt + 257) continue; // 这一字节全部相同：跳过 for (int b = 0; b < 256; ++b) cnt[b + 1] += cnt[b]; for (size_t i = 0; i < n; ++i) dst[cnt[(key(src[i]) >> shift) & 0xFF]++] = src[i]; std::swap(src, dst); // 乒乓缓冲 } if (src != a) std::memcpy(a, src, n * sizeof(T)); // 示意；非平凡类型请用 std::move }

复杂度：O(d · (n + b))

d 是趟数，b 是每一位的取值个数（基数）。32 位整数用 8 比特一位，d = 4、b = 256，复杂度就是 O(4 · (n + 256))，对大 n 而言是线性的。基数选得越大，趟数越少，但计数数组越大：256 个计数器正好能放进 L1；如果选 16 比特一位（65536 个计数器），计数数组会超出 L1，反而变慢。

实测 E5：N = 100 万个随机 int

基数排序 4.31 ms，std::sort 51.38 ms，快了约 12 倍。但它不是自适应的：输入有序时基数排序要 5.97 ms，std::sort 只要 3.91 ms。小数据量时优势也不明显，E8 中 N=2000 时二者分别是 0.016 ms 和 0.023 ms，基本持平。

负数和浮点数

LSD 基数排序是按无符号整数的二进制位排序的，所以要先把键映射成一个保持大小顺序的无符号整数：

inline uint32_t key_of(int32_t x) { return uint32_t(x) ^ 0x80000000u; // 翻转符号位：负数变到 [0, 2^31)，正数变到 [2^31, 2^32) } inline uint32_t key_of(float f) { uint32_t u; std::memcpy(&u, &f, 4); // 别用 *(uint32_t*)&f：违反严格别名规则 return (u & 0x80000000u) ? ~u // 负数：全部取反（负得越多，原始位模式越大） : u | 0x80000000u; // 正数：只翻转符号位 } // 渲染里的深度一般非负，可以直接把 float 位模式当键；NaN 要提前处理掉

LSD 和 MSD

LSD（从低位开始）MSD（从高位开始）
做法每一趟处理整个数组按最高位分桶，再在每个桶内递归处理下一位
要求每一趟必须稳定桶内递归，不要求稳定
适合定长键：整数、64 位 sort key变长键：字符串；可以提前结束（桶里只剩 1 个元素）
实现简单，无递归，适合 GPU递归；小桶要转插入排序

7.3 桶排序：按值域均匀分桶

假设数据在 [0, 1) 内均匀分布。开 n 个桶，第 i 个桶装 [i/n, (i+1)/n) 范围的数，平均每个桶只有 1 个元素；对每个桶做插入排序，再按桶的顺序拼起来。

  • 期望时间 O(n)：要求数据均匀分布。最坏 O(n²)：所有数据挤进同一个桶，退化成一次插入排序。
  • 是否稳定取决于桶内用的算法：桶内用插入排序就是稳定的。
  • 工程上不要给每个桶开一个 std::vector，每个桶都要分配内存，非常慢。本书 demo 先计数、再前缀和、再回填到一个扁平数组，最后在每段内做插入排序。实测 E5：100 万个均匀分布的 float，桶排序 9.68 ms，std::sort 63.61 ms。
游戏客户端视角：透明物体的“深度分桶”

透明物体需要从远到近绘制。如果数量很多（比如成千上万个粒子），可以把视锥的深度范围分成 k 个桶，只按桶的顺序绘制，桶内不再排序。这是一个用少量误差换取速度的近似排序。GPU 粒子系统常在 compute shader 里做双调排序（bitonic sort）或基数排序，原因是它们的数据访问模式是固定的，适合并行。

7.4 交互实验

计数排序那一栏显示的是输出数组的填充过程：注意它是从右往左（倒序扫描输入）填的。基数排序用的是 3 位十进制数，观察每趟之后“低几位”逐渐有序。

面试注意
  • “基数排序 O(n)，所以总比快排快”——不对。它有前提：键是定长整数或可以映射成定长整数，数据量足够大，有 O(n) 的额外内存。数据量小或基本有序时它可能更慢（E5 有序：5.97 ms 对 3.91 ms）。
  • 被问“基数排序为什么从低位开始”：因为从低位开始时，每一趟都处理整个数组，只要求每趟稳定，不需要递归；从高位开始就要在每个桶内递归。
  • 被问“1 亿个 0~100 岁的年龄怎么排”：计数排序，k = 101，一遍计数一遍展开，O(n)，计数数组只有 101 个 int。
本章速记
  • 计数排序：O(n + k)，稳定的关键是前缀和 + 回填方向配对（起始位置 + 正序，或结束位置 + 倒序）。
  • LSD 基数排序：O(d(n + b))，每一趟必须稳定；8 比特一趟，256 个计数器正好放进 L1。
  • 负整数翻转符号位，浮点数“负数全取反、正数翻符号位”，就能按无符号整数排序。
  • 桶排序：均匀分布时期望 O(n)，最坏 O(n²)；用扁平数组实现。
