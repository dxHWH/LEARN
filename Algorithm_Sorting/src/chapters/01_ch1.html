CHAPTER 01

排序的六个维度与 n log n 下界

先把评价标准讲清楚，后面每讲一种算法，都从这几个维度去打分。

本章目标

  • 能用决策树证明比较排序的下界 Ω(n log n)

1.1 六个评价维度

维度含义为什么在游戏客户端里要关心
时间复杂度最好 / 平均 / 最坏三种情况分开看每帧的预算只有 16.6 ms（60 FPS），偶发的最坏情况就是一次卡顿
额外空间原地（O(1) 或 O(log n) 栈）还是要 O(n) 缓冲移动端内存紧；每帧临时分配会带来碎片和分配开销
稳定性键相等的元素，排序后是否保持原来的相对顺序UI 同层节点的先后、多关键字排序、帧同步的确定性
自适应性输入越接近有序，是否跑得越快渲染队列、碰撞检测的端点，帧与帧之间几乎不变
比较 / 非比较只靠 a < b 判断，还是利用键本身的结构（数位、值域）64 位 sort key 可以用基数排序，突破 n log n
访存模式顺序访问还是大跨度跳跃；交换的是小键还是大结构体缓存未命中往往比比较次数更决定实际耗时
深入一层：“原地”的两种口径

严格说，原地（in-place）指额外空间 O(1)。但多数教材和面试默认把“只用 O(log n) 递归栈”的快排也算作原地。回答时可以主动区分：“快排是原地的，但递归栈平均 O(log n)、最坏 O(n)；堆排序才是真正的 O(1)。”这样说既严谨，又显得基础扎实。

1.2 稳定性：最常被追问的概念

稳定指：如果 a[i] 和 a[j] 的键相等，并且排序前 i < j，那么排序后 a[i] 仍然排在 a[j] 前面。只对整数本身排序时稳定性看不出来，它只在“按某个字段给记录排序”时才有意义。

稳定性有什么用？最典型的是多关键字排序：要“先按段位、段位相同再按胜率”排序，可以先按胜率排一次，再用稳定排序按段位排一次。第二次排序不会打乱段位相同的玩家已有的胜率顺序。基数排序就是靠这个原理工作的：从低位到高位，每一趟都必须稳定。

判断一个算法是否稳定，有一个简单的经验：只做相邻交换，或者遇到相等就停下来不越过，就是稳定的；只要有“远距离交换”，通常就不稳定。选择排序、堆排序、快排都会把元素一次换出很远，所以都不稳定。

实测 E1：5000 条记录、键只有 50 种，排序后统计“相邻同键但 id 逆序”的对数

冒泡 / 插入 / 归并 / 计数 / 基数 / stable_sort 都是 0；选择 1607，希尔 2503，工程快排 2498，三路快排 2454，堆 2916，std::sort 2509。

1.3 逆序对：冒泡和插入的真实工作量

如果 i < j 且 a[i] > a[j]，就称 (i, j) 是一个逆序对。比如 [3, 1, 2] 有 (3,1)、(3,2) 两个逆序对。逆序对数记作 I，有几个很有用的性质：

  • 有序数组 I = 0；逆序数组 I = n(n−1)/2，这是最大值；随机排列的期望 I = n(n−1)/4。
  • 交换一对相邻的逆序元素，I 恰好减 1。所以冒泡排序的交换次数、插入排序的移动次数都正好等于 I。
  • 由此可以得出：任何“只交换相邻元素”的排序，平均都要 Ω(n²) 步。想突破 n²，就必须做远距离交换，比如希尔、快排、堆排。
实测 E2：N=1000 的随机数据

冒泡写入 483422 次，等于交换 241711 次，也就是 I；插入比较 242702 次，约等于 I + n。两者都接近理论期望 n(n−1)/4 = 249750。数组逆序时，冒泡和插入的比较次数都是 499500 = n(n−1)/2。

1.4 比较排序的下界：为什么快不过 n log n

只能通过 a < b ? 获取信息的排序算法，可以抽象成一棵决策树：每个内部节点是一次比较，每个叶子是一种最终排列。n 个元素有 n! 种可能的排列，算法必须能区分所有排列，所以叶子至少有 n! 个。

高度为 h 的二叉树最多有 2h 个叶子，所以 2h ≥ n!，即 h ≥ log₂(n!)。由斯特林公式，log₂(n!) = n log₂n − n log₂e + O(log n) ≈ n log₂n − 1.44n。所以任何比较排序在最坏情况下都至少需要 Ω(n log n) 次比较。这个结论对平均情况同样成立：叶子的平均深度也至少是 log₂(n!)。

面试速答版

“比较排序可以看成一棵决策树。它要区分 n! 种排列，所以至少有 n! 个叶子，树高就至少是 log(n!)，也就是 n log n 级别。计数排序、基数排序不在这个模型里，因为它们不靠比较，而是直接把键当下标用，所以能做到线性。”

1.5 增长曲线：n² 和 n log n 差多少

小 n 的时候常数因子更重要。n = 16 时，n²/4 = 64，n log₂n = 64，两者已经持平；再加上插入排序没有递归、访存是顺序的，所以“小区间用插入排序”是所有工业排序的共识。libstdc++ 的阈值是 16，MSVC 是 32。

1.6 选型决策树

本章速记
  • 六个维度：时间（最好 / 平均 / 最坏）、空间、稳定、自适应、比较与否、访存模式。
  • 稳定的经验判断：只做相邻交换、遇到相等就停 → 稳定；有远距离交换 → 一般不稳定。
  • 冒泡的交换次数、插入的移动次数都等于逆序对数；只做相邻交换的排序平均 Ω(n²)。
  • 比较排序下界：决策树至少有 n! 个叶子，树高 ≥ log₂ n! ≈ n log₂ n − 1.44n。
自测：为什么说“只做相邻交换的排序平均是 Ω(n²)”？

一次相邻交换最多消除 1 个逆序对，而随机排列的期望逆序对数是 n(n−1)/4，所以至少需要这么多次交换。希尔排序就是为了打破这个限制，用大步长让一次交换消除多个逆序对。

自测：计数排序是 O(n)，和 Ω(n log n) 下界矛盾吗？

不矛盾。下界只针对“仅通过比较获取信息”的算法。计数排序直接用键做数组下标，一步就拿到 log k 比特的信息，不在决策树模型里。代价是它要求键是小值域的整数。
