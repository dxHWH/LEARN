8.1 introsort：快排做主体，堆排兜底，插排收尾

introsort（内省排序）由 David Musser 在 1997 年提出。它解决的问题是：快排平均最快，但最坏 O(n²)。办法是一边快排一边数递归深度，深度超过阈值，说明 pivot 一直选得不好，就对当前子区间改用堆排序。C++11 起，标准要求 std::sort 的复杂度为 O(n log n)（以前只要求平均），这实际上就要求实现采用 introsort 一类的做法。

实现小区间阈值pivot深度预算插排时机
libstdc++（GCC）16三数取中（取 first+1、mid、last−1，放到 first）2⌊log₂n⌋递归时跳过 ≤ 16 的区间，最后对整个数组做一遍插入排序：前 16 个有边界检查，之后无边界检查
MSVC STL32（_ISORT_MAX）区间 > 40 用 ninther，否则三数取中每次分区 _Ideal = _Ideal/2 + _Ideal/4每个小区间就地插入排序
libc++（LLVM）按类型调整三数 / 九数取中较新版本加入了深度限制对算术类型使用无分支的块分区（BlockQuicksort 思路）
深入一层：MSVC 分区返回的是一个“相等区间”

MSVC 的 _Partition_by_median_guess_unchecked 返回一对迭代器 [mid_first, mid_last)，表示所有等于 pivot 的元素已经聚到中间，下一步只需要递归两侧。这相当于内置了三路划分，所以 E5 里大量重复（16 种值）的数据，std::sort 只要 9.68 ms，比本书的 Hoare 工程版（16.29 ms）快很多。

实测 E5：qsort 为什么比 std::sort 慢 66%

100 万个随机 int：qsort 85.29 ms，std::sort 51.38 ms。qsort 的比较器通过函数指针、以 const void* 参数调用，没法内联，每次比较都是一次间接调用；std::sort 的比较器是模板参数，lambda 会被直接内联成一条 cmp 指令。这也是“C++ 模板比 C 回调更快”的经典例证。

Top-K：为什么 partial_sort 比 nth_element 还快

直觉上 nth_element 是 O(n)，partial_sort 是 O(n log K)，前者应该更快。但实测反过来了，因为 K = 100 远小于 n：堆里装着当前前 100 名，绝大多数新元素都比堆顶小，只比较一次就被丢掉，只有极少数需要入堆调整。实际工作量接近 n 次比较。nth_element 则要做好几轮完整的分区，每轮都有大量交换。K 很小用堆，K 和 n 同量级用 nth_element。

8.3 严格弱序：比较器必须遵守的契约

标准要求比较器 comp 是严格弱序（strict weak ordering），即满足：

性质要求写成 <= 会怎样
非自反comp(a, a) 必须为 false违反：a <= a 为 true
非对称comp(a, b) 为 true，则 comp(b, a) 为 false违反：a == b 时两个方向都为 true
传递comp(a, b) 且 comp(b, c)，则 comp(a, c)成立
不可比的传递性a~b 且 b~c，则 a~c（~ 表示“谁也不小于谁”）—

违反这个契约是未定义行为。具体后果取决于实现，下面是实测结果：

E7 · 比较器写成 <=（64 个全相等的元素，数组左边是别人的内存 [0,9,9,9,9,9,9,9]）
(a) libstdc++ 式无哨兵插排 + <=：越界读 336 次；排序后数组里出现了 7 个从未出现过的 9
    左侧内存被改成 [0,5,5,5,5,5,5,5]
    同一段代码改用 < ：越界读 0 次，左侧内存未被改写
(b) MSVC std::sort + <=（2000 个相等元素，Release）：比较 14635 次，访问哨兵区 0 次
    同样数据用 < ：比较 4006 次
    （MSVC Debug 版会通过 _DEBUG_LT_PRED 断言 "invalid comparator"）

原理：libstdc++ 的收尾插入排序在前 16 个元素之后不检查边界，它假设“前 16 个里一定有一个不大于 key 的元素能挡住它”。用 <= 时，相等也算“小于”，key 会一直往左走，越过数组开头，读到别人的内存；后移操作又把别人的数据挪了进来、把 5 写了出去。这就是“比较器写错导致崩溃，而且崩溃点离 sort 很远”的来源。MSVC 的实现在这个例子里没有越界，但比较次数多了 3.6 倍；Debug 版会直接断言。不同实现表现不同，正说明这是 UB，不能依赖。

常见的比较器错误

struct Hero { int rank; float winRate; int id; }; // ✘ 1：用 <= 或 >= auto bad1 = [](const Hero& a, const Hero& b) { return a.rank <= b.rank; }; // ✘ 2：多字段写成“或”：a=(1,9) b=(2,1) 时 bad2(a,b) 和 bad2(b,a) 都为 true auto bad2 = [](const Hero& a, const Hero& b) { return a.rank < b.rank || a.winRate < b.winRate; }; // ✘ 3：浮点里有 NaN：NaN 与任何数比较都为 false，破坏了“不可比”的传递性 // ✘ 4：比较器依赖会变化的外部状态（排序过程中修改了 winRate、读了随机数、读了实时时间） // ✔ 字典序：用 std::tie 最不容易写错 auto good = [](const Hero& a, const Hero& b) { return std::tie(a.rank, a.winRate, a.id) < std::tie(b.rank, b.winRate, b.id); }; // ✔ 降序就交换 a、b，或者用 >：两者都是严格弱序 auto desc = [](const Hero& a, const Hero& b) { return a.rank > b.rank; }; // ✔ C++20：默认生成 <=>，直接 std::sort(v.begin(), v.end()) // struct Hero { ...; auto operator<=>(const Hero&) const = default; };
游戏客户端视角：Lua 和 C# 里也有同样的坑
  • Lua table.sort：快排实现，不稳定。比较函数写成 a.lv <= b.lv 时会报 invalid order function for sorting，或者在数组边界外读到 nil 而报错；数据不同，有时报错有时不报，线上很难排查。
  • C# List<T>.Sort / Array.Sort（Unity 常用）：introsort，不稳定。比较器不一致时，.NET 可能抛出 “IComparer.Compare() method returns inconsistent results”。要稳定排序用 LINQ 的 OrderBy（稳定，但会分配内存）。

8.4 现代排序：pdqsort 和 TimSort

pdqsort（Orson Peters，2016）

Pattern-defeating quicksort，introsort 的改进版：

· 检测到分区很不平衡时，打乱几个元素来破坏对手构造的模式

· 分区时没有发生交换，就尝试有上限的插入排序，有序输入接近 O(n)

· 块分区（BlockQuicksort）：先把比较结果存进偏移数组，再批量交换，消除分支预测失败

Go 1.19 的 sort、Boost 的 pdqsort 都采用了它；Rust 的 sort_unstable 也长期基于 pdqsort。

TimSort（Tim Peters，2002）

稳定的归并 + 插入混合排序，针对真实数据中常见的“有序段”：

· 扫描找出天然的升序段或降序段（降序段直接翻转），短段用二分插入补齐到 minrun（32～64）

· 用栈维护各段长度的不变式，决定何时合并

· galloping 模式：一边连续获胜时，用指数搜索成块拷贝

Python 的 sorted、Java 的对象数组排序、Android 都使用它。有序输入 O(n)，最坏 O(n log n)。

另外，Java 对基本类型数组用的是 Dual-Pivot Quicksort（Yaroslavskiy，2009）：用两个 pivot 把数组分成三段，减少了内存访问次数。

面试注意
  • 回答“std::sort 是怎么实现的”，至少要说出：introsort；快排主体 + 三数取中；深度超过约 2 log n 转堆排；小区间（16/32）用插入排序；不稳定；C++11 起要求最坏 O(n log n)。
  • 被问“std::sort 需要随机访问迭代器吗”：需要。所以 std::list 不能用 std::sort，只能用成员函数 list::sort。
  • stable_sort 会尝试分配 O(n) 的临时内存，在每帧都要执行的代码里要注意。
本章速记
  • introsort = 快排 + 堆排兜底 + 插排收尾；阈值 libstdc++ 16 / MSVC 32；深度预算约 2 log₂n。
  • qsort 慢在比较器无法内联（E5：85 ms 对 51 ms）。
  • K 很小时 partial_sort / 堆最快（E9：0.22 ms），K 较大时用 nth_element。
  • 严格弱序：非自反、非对称、传递、不可比传递；写成 <= 是 UB，可能越界写（E7）。用 std::tie 写多字段比较。
