CHAPTER 00

导读：知识地图、阅读路线与事实等级

网络同步只回答三个问题：谁说了算、网上传什么、什么时候往前走。帧同步和状态同步是这三个问题的两组不同答案，其余的技术都是在补各自的短板。

本章目标
  • 记住网络同步的“三问”，用它给任何一种方案定位。
  • 看懂全书知识地图：HOK 帧同步一条线、Unreal 状态同步一条线、两条线在“预测 + 回滚”处汇合。
  • 知道书里每个结论的来源：HOK 文档、UE 源码 / 官方文档、公开资料、本书实测、推断。

30 秒说明：这本书怎么用

你给的《HOK 帧同步机制详解》已经把王者荣耀的帧同步讲得很完整：服务器定帧汇总 + 三层冗余抗丢包 + 900 帧滑动窗口定序 + 本地确定性模拟 + 逻辑与表现彻底解耦。这本书做三件事：

  1. 补原理：为什么这么设计？不这么设计会怎样？每个设计点都用一个可运行的 C++ 模型量化（例如“一包带 3 帧冗余能挡住多少丢包”“严格 Lockstep 下一个人断流全场卡多久”）。
  2. 补另一半：状态同步（尤其是 Unreal）——快照插值、客户端预测与和解、延迟补偿、Actor 复制管线、属性复制与 RPC、CharacterMovementComponent、GAS 预测、Iris / Mover / 网络物理。
  3. 补面试：每章都有 30 秒答案、面试注意、坑位清单和自测；第 15 章汇总 50 道追问。

0.1 网络同步的三问

问题帧同步（Lockstep 家族）状态同步（权威服务器家族）
谁说了算（权威在哪）没有“权威状态”：每个客户端都跑完整逻辑，大家算得一样就是真相；服务器只定序服务器的状态就是真相；客户端只是“播放器”，最多做预测
传什么输入（第 N 帧谁按了什么键）状态（位置、血量、技能状态）+ 事件（RPC）
何时推进拿到第 N 帧的全部输入才推进（或先猜着推进，错了回滚）服务器按自己的 tick 推进；客户端按收到的快照插值，按本地输入预测
最难的事确定性、抗丢包、断线追帧带宽、手感（延迟）、命中判定公平

标签含义可信度

实测 Ex本书 demos/ 下 C++ 模型的输出（数字由构建脚本从 JSON 读入，书和 md 同源）模型结论；参数是假设的，趋势与量级可信，绝对值不代表线上

本章速记
  • 三问：谁说了算 / 传什么 / 何时推进。帧同步 = 无权威状态 + 传输入 + 拿到输入才推进；状态同步 = 服务器权威 + 传状态 + 服务器自己推进。
  • 两条线的汇合点：预测 + 回滚重算（GGPO 的回滚 = UE CMC 的“纠正后重放 SavedMoves”）。
  • 每个结论看标签：实测 给趋势和量级，UE / 公开资料 给事实。
