CHAPTER 04

确定性工程：让十台设备算出同一个比特

帧同步最危险的故障不是卡，而是“静默分叉”：某一帧某个浮点数末位不同，之后每一帧都在放大，最后变成“我明明打中了却没伤害”。

本章目标
  • 说清浮点“不确定”的真正来源：不是 IEEE 754 本身，而是编译器、指令集、数学库和运算顺序。
  • 亲眼看到：同一份源码、同一台机器，只换编译选项，600 帧群体模拟的 hash 就不同；定点版三份完全一致。
  • 会写 Q16.16 定点数的乘除、开方、正弦，知道精度和溢出的代价。
  • 掌握随机、容器顺序、时间累加等其他确定性陷阱，以及 desync 的检测和定位方法。
30 秒面试版答案

帧同步要求相同输入得到逐位相同的结果。IEEE 754 的加减乘除开方本身是确定的，问题出在编译器重排和 FMA 收缩（/fp:fast）、不同指令集、各平台数学库的 sin/cos 实现、并行归约顺序，所以跨平台帧同步一般用定点数（如 Q16.16 / Q32.32，整数运算处处一致）。其他陷阱：随机数要用同步种子的确定性生成器，且表现层不能偷用逻辑随机；不能依赖 unordered_map / 指针地址的遍历顺序；逻辑不能读墙钟、不能用浮点累加时间；逻辑层单线程；不用引擎物理。出了 desync 靠周期性上报帧 hash发现，靠分层 hash、逐帧日志 diff 和录像重放定位。HOK 把战斗逻辑整体放进独立的 C++ GameCore，物理上隔绝了引擎的浮点、时钟、随机和容器。

4.2 浮点为什么会“不一样”

先澄清一个常见误解：IEEE 754 规定加、减、乘、除、开方必须正确舍入，同样的指令、同样的操作数，在任何符合标准的硬件上结果都一样。不一样来自“指令序列不一样”：

  • 结合律：浮点加法不满足结合律，(a+b)+c ≠ a+(b+c)。编译器在 /fp:fast / -ffast-math 下会重排、向量化求和。
  • FMA 收缩：a*b+c 被融合成一条指令，只舍入一次，结果和分两步不同；是否生成取决于编译选项和目标指令集（AVX2 / ARMv8 都有 FMA）。
  • 中间精度：老的 32 位 x87 用 80 位寄存器保存中间结果，何时溢出到内存（截断成 32 / 64 位）取决于寄存器分配。
  • 超越函数：sin / cos / exp / pow 不要求正确舍入，各平台、各版本的数学库实现不同。

4.3 定点数：用整数表示小数

Q16.16：用 32 位有符号整数 $v$ 表示实数 $v / 2^{16}$，整数部分 16 位（约 ±32768）、小数精度 $1/65536 \approx 1.5\times10^{-5}$。加减就是整数加减；乘除要借 64 位中间结果：

$$a \cdot b \;\to\; \frac{a_{\text{raw}} \cdot b_{\text{raw}}}{2^{16}},\qquad \frac{a}{b} \;\to\; \frac{a_{\text{raw}} \cdot 2^{16}}{b_{\text{raw}}}$$ typedef int32_t fx; // 实数 = raw / 65536 const fx ONE = 1 << 16; inline fx fmul(fx a, fx b) { return (fx)(((int64_t)a * b) >> 16); } // 64 位中间结果防溢出 inline fx fdiv(fx a, fx b) { return (fx)(((int64_t)a << 16) / b); } uint32_t isqrt64(uint64_t v) { // 逐位开方：结果向下取整，处处一致 uint64_t r = 0, bit = 1ULL << 62; while (bit > v) bit >>= 2; while (bit) { if (v >= r + bit) { v -= r + bit; r = (r >> 1) + bit; } else r >>= 1; bit >>= 2; } return (uint32_t)r; } inline fx fsqrt(fx a) { return a <= 0 ? 0 : (fx)isqrt64((uint64_t)a << 16); } const fx PI = 205887, TWO_PI = 411775, HALF_PI = 102944; fx fsin(fx x) { // 区间规约到 [-π/2, π/2] + 7 次泰勒多项式 x %= TWO_PI; if (x > PI) x -= TWO_PI; if (x < -PI) x += TWO_PI; if (x > HALF_PI) x = PI - x; if (x < -HALF_PI) x = -PI - x; fx x2 = fmul(x, x), x3 = fmul(x2, x), x5 = fmul(x3, x2), x7 = fmul(x5, x2); return x - x3 / 6 + x5 / 120 - x7 / 5040; }

精度实测：fsin 最大误差 [[det.precise.D7.sin|.2e]]，fsqrt 最大误差 [[det.precise.D7.sqrt|.2e]]（约 1 个最低位）实测 D7。定点数的代价：

代价说明常见处理
范围 vs 精度Q16.16 若以厘米为单位只有 ±327 m；距离平方会溢出 32 位平方、点积用 int64；大地图用 Q32.32（int64）或分块局部坐标
除法精度小数除以大数会被截断成 0调整运算顺序（先乘后除）；必要时临时提高精度
三角 / 开方不能用 CRT查表（表必须是常量，不能运行时用 std::sin 生成）或纯整数多项式
生态物理、寻路、动画曲线都要定点版逻辑层自研：简单几何碰撞、格子寻路；动画只用于表现
不用定点数行不行？

可以，但条件苛刻：所有端同一编译器、同一版本、同一指令集、禁止 fast-math 和 FMA 收缩、自带超越函数。单平台（比如同一主机平台）或全 PC 的项目有人这么做；跨 iOS / Android / PC 的移动 MOBA 基本都选定点数。另一个折中是软件模拟浮点（soft float），确定但慢一个数量级。

4.4 随机数：同一个种子，同样的调用次数

struct LogicRng { // 只给逻辑层用；种子由服务器下发（HOK 文档：随帧下发） uint64_t s; explicit LogicRng(uint64_t seed) : s(seed * 0x9E3779B97F4A7C15ULL + 1) {} uint64_t Next() { s ^= s >> 12; s ^= s << 25; s ^= s >> 27; return s * 2685821657736338717ULL; } int32_t Range(int32_t lo, int32_t hi) { return lo + (int32_t)(Next() % (uint64_t)(hi - lo)); } };

种子一致只是必要条件。更隐蔽的 bug 是调用次数不一致：例如某个特效、UI 或“只在本地玩家执行”的逻辑也调了逻辑随机，于是本地端比别人多消耗一次随机数，从此所有随机结果都错位。规则是：表现层永远不碰逻辑随机源，需要随机就用自己的；凡是“只对本地玩家执行”的代码都不能改逻辑状态。HOK 把帧随机放在 C++ 逻辑层，种子随帧 hash 一起上报校验 HOK 文档。

4.7 HOK 的工程约束：把不确定的东西关在门外

HOK 的战斗逻辑整体放在不依赖 Unity 的 C++ GameCore 里 HOK 文档：定点数、可播种同步随机源、逻辑层单线程、禁用墙钟、倍速用有理数（分子 / 分母）、避免依赖不稳定遍历顺序。这些约束之所以能被严格执行，是因为逻辑层在物理上就访问不到引擎的浮点时间、随机数和容器——比代码规范和 Code Review 可靠得多。顺带的收益是同一份逻辑既能跑在手机上也能跑在服务器上（CS 模式，第 8 章）。

面试注意

“帧同步为什么要用定点数”是必考题。答题要点：① IEEE 754 基本运算本身确定，不确定来自编译器 / 指令集 / 数学库 / 运算顺序；② 跨平台无法锁死这些，所以用整数模拟小数；③ 定点数的代价（范围、精度、生态）以及怎么处理。能补一句“随机数调用次数也必须一致、表现层不能用逻辑随机”，说明你真踩过坑。

自测 1：同一台 PC 上，Debug 和 Release 版本的浮点结果会不同吗？取决于浮点模型选项而不是优化级别本身。实测 /Od /fp:strict 与 /O2 /fp:precise 逐帧一致；但如果 Release 开了 /fp:fast 或启用了 AVX2 并允许收缩，就可能不同。x86 32 位用 x87 时，寄存器分配不同也会导致差异。
自测 2：Q16.16 下计算两点距离，有什么坑？dx² + dy² 会溢出 32 位（dx 超过 181 就溢出 raw 值 2³¹），要用 int64 累加；开方后再转回 Q16.16。另外距离很小时精度只有 1/65536，比较“是否相等”要用阈值。
自测 3：发现线上有 0.1% 的对局 desync，怎么定位？先看 hash 分歧的帧号与上报的分层 hash，确定是哪个子系统；拿到该局的录像（输入序列）在多平台重放，二分找到第一个分歧帧；在该帧打开详细追踪，diff 两端的逐变量日志；常见根因是表现层改了逻辑状态、随机调用次数不一致、容器遍历顺序、未初始化变量。
