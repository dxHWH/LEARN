CHAPTER 00

阅读指南：一条主线串起传输层

先说清楚这本书在讲什么、按什么顺序讲、遇到哪种标记该怎么读。

一条主线：可靠性是一组机制，而不是一个开关

传输层的知识点乍看很散：端口、校验和、序号、三次握手、滑动窗口、拥塞控制、TIME_WAIT、KCP、QUIC……面试时也常被拆成一道道独立的题来问。但它们其实都在回答同一个问题：

🧭 全书主线

IP 网络只承诺"尽力而为"：包会丢、会乱序、会重复、会出错、会因为拥塞而变慢。要想在它上面提供"可靠"的服务，就要拿出一组机制去对付这些问题，而每个机制都有代价（延迟、带宽、内存、复杂度）。

UDP 几乎什么机制都不加，把选择权交给应用；TCP 把一整套机制固化在操作系统内核里，给所有应用同一种"可靠有序字节流"；可靠 UDP（KCP、QUIC、游戏引擎的网络层）则在用户态按需挑选、重新调参这些机制。

读的时候遇到新知识点，可以先问自己两句：它是在对付哪一种网络问题？它付出了什么代价？能答上这两句，这个知识点就不再是孤立的一道题，而是知识网里的一个节点。

关于配套程序

配套源码在本书同目录的 demos/ 下，全部用 MSVC 14.44（VS2022）、/std:c++20 /O2 编译，在 Windows 11 x64 上实际运行，书中的输出均为原样粘贴。双击 demos/build_and_run.bat 就能在你自己的机器上复现。

程序证明什么所在章节
d1_tcp_udp_behaviors真实 socket 实测：UDP 保留消息边界 / TCP 粘包；UDP 发往空端口"成功"但收到 ICMP；TCP 连空端口被 RST 拒绝（Windows 耗时约 2 s）；四次挥手中 CLOSE_WAIT / FIN_WAIT_2 / TIME_WAIT 的出现时机；半关闭；SO_LINGER 发 RST第 2、3、5、6 章
d2_rudp_sim虚拟时钟仿真（RTT 60 ms、可调丢包）：停等 / GBN / SR / 快速重传 / 类 TCP / 类 KCP / 冗余发送 在批量传输与 100 Hz 实时流两种场景下的完成时间、重传占比和时延分布第 8、9、11 章
⚠️ 关于仿真数据

d2 是协议逻辑真实、网络是模型的仿真：本机回环几乎不丢包也没有延迟，用真实 socket 看不出协议差异。仿真里的"类 TCP"是教学用简化版（没有 TLP、RACK、PRR、BBR 等现代 Linux 优化），绝对数值偏悲观，请看趋势和相对大小，不要把绝对值当作真实 TCP 的性能。书中引用时会再次说明。
