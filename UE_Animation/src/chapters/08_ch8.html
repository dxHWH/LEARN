CHAPTER 08

IK 与程序化动画：让动画适应世界

动画是按平地、按标准体型做的。真实场景里有台阶、斜坡、不同长度的武器、要去够的门把手——这些靠 IK 和各种“Warping”在运行时修正。

本章目标
  • 推导两骨骼 IK 的解析解，理解 Pole（Joint Target）的作用
  • 知道 FABRIK / CCD 这类迭代解法的收敛特性和代价
  • 讲清脚步 IK 的完整流程，以及射线检测该放在哪个线程
  • 了解 UE5 的 Control Rig、IK Rig、距离匹配、步幅 / 朝向调整、Motion Warping 和 Motion Matching

8.1 FK 与 IK

FK（正向运动学）：给每节骨骼的局部旋转，算出末端在哪——动画序列就是 FK 数据。IK（逆向运动学）：给末端的目标位置，反求每节骨骼该怎么转。游戏里常见的 IK：

脚步 IK

台阶、斜坡上脚贴地，骨盆随之下沉。

手部 IK

左手始终握住枪的护木（不同武器握点不同），双手搬箱子。

Look At / Aim

头和眼睛看向目标；枪口精确指向准星。

交互

伸手去按按钮、开门、攀爬时手扶边缘。

8.2 两骨骼 IK：解析解

void TwoBoneIK(FVector A, float L1, float L2, FVector Target, FVector Pole, FVector& Elbow, FVector& End) { const FVector ToT = Target - A; const float Dist = ToT.Size(); const FVector Dir = ToT / Dist; const float D = FMath::Clamp(Dist, FMath::Abs(L1 - L2) + 1e-3f, L1 + L2 - 1e-4f); const float CosA = (L1 * L1 + D * D - L2 * L2) / (2.f * L1 * D); const float SinA = FMath::Sqrt(FMath::Max(0.f, 1.f - CosA * CosA)); const FVector Bend = (Pole - Dir * FVector::DotProduct(Pole, Dir)).GetSafeNormal(); // Pole 去掉沿 Dir 的分量 Elbow = A + Dir * (L1 * CosA) + Bend * (L1 * SinA); End = A + Dir * D; // 够不着时停在伸直的位置 }
实测 E8：上臂 30、前臂 28，2 万个随机目标
  • 可达 16330 个：末端误差最大 0.0000；不可达 3670 个：手臂伸直指向目标；骨长误差 0；肘部全部落在 Pole 一侧。
  • 耗时 13.9 ns/次——解析解几乎是免费的，所以手脚 IK 全都用它。

UE 的 Two Bone IK 节点参数：IK Bone（末端骨骼，例如 hand_l / foot_r，向上两级自动确定链）、Effector Location 与其空间（组件、世界、某骨骼空间）、Joint Target Location（即 Pole）、Allow Stretching（够不着时允许拉长，可设起始比例和最大比例）、Take Rotation from Effector Space / Maintain Effector Relative Rotation（末端旋转怎么处理）。

面试注意：两骨骼 IK 的三个坑
  • 手臂伸直时 Pole 失效、肘部翻转：A、B、T 共线时弯曲平面不确定，Pole 的微小变化会让肘部翻到另一边。办法：让目标略在最大长度之内（clamp 时留余量），Pole 放在合理方向并随身体旋转。
  • 空间搞错：Effector 用世界坐标却按组件空间解释，角色一转身手就飞了。用骨骼空间（如“相对右手”）给左手 IK 目标最稳。
  • IK 要在混合之后、最后阶段做：IK 是对最终姿势的修正，放在混合之前会被后续混合冲掉。

8.3 多骨骼：FABRIK、CCD 与全身 IK

链条超过两节时，没有唯一的解析解，用迭代：

  • FABRIK（Forward And Backward Reaching IK）：先把末端放到目标、从末端往根逐节拉回骨长（Backward）；再把根放回原位、从根往末端逐节拉回（Forward）；重复到误差小于容差。只做点和长度运算，不算角度，很快。
  • CCD（Cyclic Coordinate Descent）：从末端前一节开始，每节旋转使“这节到末端”的方向对准“这节到目标”，循环往复。实现简单，但容易让靠近末端的关节转得过多。
  • 全身 IK（Full Body IK）：同时考虑多个末端（双手双脚）和关节限制，UE5 在 Control Rig / IK Rig 里提供 Full Body IK 解算器。

8.4 脚步 IK 的完整流程

  1. 射线检测（游戏线程）：在角色或 EventGraph 里，从每只脚的骨骼位置向下做 Line / Sphere Trace，得到地面高度和法线。物理查询不能在动画工作线程里随意做。
  2. 算偏移：每只脚的高度差 = 地面高度 − 动画里脚的高度；骨盆下沉量 = 两脚中下沉最多的那个（否则低的那只脚够不着地）。
  3. 平滑：偏移和脚的旋转都做插值（例如 15~20/s 的指数插值），避免走台阶时一帧一跳。
  4. AnimGraph：转到组件空间 → 调整 pelvis 高度 → 两只脚各一个 Two Bone IK（目标 = 原位置 + 偏移，Pole 在膝盖前方）→ 按地面法线旋转脚掌 → 转回局部空间。
  5. 开关：空中、播放特定蒙太奇时关闭（用曲线或变量控制 Alpha）；远处角色在 LOD 中跳过。
游戏客户端实战：为什么用“IK 骨骼”（ik_foot_l 等）

Mannequin 里有一组不参与蒙皮的骨骼：ik_foot_root / ik_foot_l / ik_foot_r / ik_hand_root / ik_hand_gun / ik_hand_l / ik_hand_r。动画导出时把脚、手的位置烘焙到这些骨骼上。运行时 IK 目标直接取这些骨骼的位置，即使上游混合改变了腿的姿势，也能知道“这条动画原本想让脚放在哪”；左手 IK 也可以取 ik_hand_l 相对 ik_hand_gun 的位置，自动适配不同武器。

8.5 UE5 的程序化动画工具

工具做什么要点
Control Rig节点化的绑定与程序化动画系统可在 AnimGraph 里作为节点运行（Forward Solve），做 IK、程序化修正；也用于 Sequencer 里手 K 动画
IK Rig / IK Retargeter定义 IK 目标与解算器栈；不同骨架之间按“骨骼链”重定向取代 UE4 只能同骨架重定向的限制；支持运行时重定向
距离匹配（Distance Matching）起步、急停、转身动画按“离停止点还有多远”选择播放位置，而不是按时间动画里带距离曲线；角色按代码物理减速，动画刚好在停下时播到最后一帧，不滑步
步幅调整（Stride Warping）按实际速度 / 动画速度的比例拉长或缩短腿的步幅少量动画覆盖连续的速度范围
朝向调整（Orientation Warping）把下半身扭向实际移动方向，上半身保持朝前只需 4 个基本方向动画就能覆盖任意方向
Motion Warping在蒙太奇的指定时间窗内，把 Root Motion 的位移 / 旋转调整到某个目标点翻越、处决、攻击吸附：动画落点精确对准目标
Motion Matching（Pose Search）不用状态机，每帧在动画数据库里搜索“与当前姿势和期望轨迹最匹配”的那一帧接着播UE 5.4 起随 Game Animation Sample 推广；需要大量动作捕捉数据、搜索有 CPU 开销
物理动画布娃娃、受击物理、次级运动Physics Asset；AnimGraph 的 RigidBody 节点（辫子、披风）、AnimDynamics；Physical Animation Component 用马达驱动刚体跟随动画
深入：Motion Matching 的代价函数

每一帧（或每隔几帧）计算一个查询向量：当前若干骨骼的位置和速度（如双脚、骨盆）+ 未来若干时刻的期望轨迹（位置、朝向，来自玩家输入和移动预测）。数据库里每一帧都预先算好同样格式的特征向量，搜索加权距离最小的那一帧，如果它和当前播放位置足够不同就跳过去，并用惯性化平滑切换。工程难点在于特征的归一化和权重、搜索加速（KD 树 / 聚类）、数据覆盖率，以及与玩法需要的“确定性响应”之间的平衡。

本章速记
  • 两骨骼 IK：clamp 距离 → 余弦定理求角 → Pole 定平面；E8：误差 0、13.9 ns/次。伸直时 Pole 失效会翻肘。
  • 多骨骼用 FABRIK / CCD / Full Body IK；FABRIK 平均几次迭代就收敛，但有长尾（E8：容差 0.01 时 50 次不收敛 25/20000）。
  • 脚步 IK：游戏线程射线 → 骨盆下沉取最大值 → 平滑 → 组件空间两骨骼 IK + 脚掌对齐法线。
  • UE5：Control Rig、IK Rig 重定向、距离匹配、步幅 / 朝向调整、Motion Warping、Motion Matching。
自测：为什么脚步 IK 时骨盆要往下沉，而不是只把一只脚往上抬？

站在台阶边缘时，一只脚踩在高处、另一只在低处。动画里两只脚是在同一高度的，如果骨盆不动，只能把低处那只脚往下“伸”——而动画里腿通常已经接近伸直，伸不下去，脚就悬空。先把骨盆下沉到“低的那只脚刚好能踩到”的高度，再用 IK 把高处那只脚抬上去（弯膝盖总是可行的）。

自测：Motion Warping 和 Root Motion Source 有什么区别？

Motion Warping 修改的是蒙太奇自带的 Root Motion：动画本来位移 2 米，目标在 2.5 米外，就在指定窗口内把位移拉伸到 2.5 米，姿势仍来自动画。Root Motion Source 是代码直接生成的位移（恒定速度、跳到某点、径向力），不依赖动画。两者都通过角色移动组件执行，可参与网络预测。
