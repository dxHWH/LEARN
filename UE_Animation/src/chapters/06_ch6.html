6.1 动画蓝图编译后是什么

动画蓝图编译生成一个 UAnimInstance 的子类（UAnimBlueprintGeneratedClass）。AnimGraph 里的每个节点变成这个类里的一个 FAnimNode_* 结构体成员（如 FAnimNode_SequencePlayer、FAnimNode_LayeredBoneBlend），节点之间用 FPoseLink 连起来；EventGraph 和函数编译成普通蓝图字节码。

EventGraphAnimGraph
做什么读角色 / 移动组件的状态，算出变量（速度、方向、是否在空中、瞄准角）用这些变量驱动节点树，输出最终姿势
入口Event Blueprint Update Animation（C++：NativeUpdateAnimation）Output Pose 节点向下拉取
线程游戏线程开启多线程更新后在工作线程
能否访问 UObject可以（Cast、调函数）不能随意访问，只能读 Proxy 里的数据或线程安全的属性
UE5 推荐写法

把 EventGraph 里的逻辑搬到 Blueprint Thread Safe Update Animation（C++：NativeThreadSafeUpdateAnimation）里，在工作线程执行；需要读角色数据时用 Property Access（属性访问）节点，它由引擎在安全的时机把数据拷贝过来。Lyra 的动画蓝图几乎没有 EventGraph 逻辑，就是这么做的。

6.2 一帧的调用链

深入：Root Motion 让调用顺序变了

角色播放带 Root Motion 的蒙太奇时，UCharacterMovementComponent 需要在移动之前就知道这一帧动画位移了多少。所以它会在自己的 Tick 里主动调用 TickCharacterPose，先推进动画时间并提取 Root Motion，再用这段位移执行移动；之后 SkeletalMeshComponent 的 Tick 不会再重复推进时间。这也是“Root Motion 角色的动画和移动是强耦合的”的含义（第 7 章）。

6.3 为什么要有 Proxy

工作线程计算姿势时，游戏线程可能正在改 Actor 的属性、销毁对象、跑 GC。如果动画节点直接读 Character->GetVelocity()，就是数据竞争。UE 的解法是 FAnimInstanceProxy：

  • 动画实例里真正参与计算的状态（节点树、同步组、蒙太奇评估数据、要读的变量）放在 Proxy 里。
  • 游戏线程在 PreUpdateAnimation 阶段把需要的数据拷贝进 Proxy；工作线程只读写 Proxy。
  • 收尾阶段再把结果（Notify 队列、曲线值等）交还游戏线程。
UCLASS() class UMyAnimInstance : public UAnimInstance { GENERATED_BODY() protected: UPROPERTY(BlueprintReadOnly) float GroundSpeed = 0.f; UPROPERTY(BlueprintReadOnly) float Direction = 0.f; UPROPERTY(BlueprintReadOnly) bool bIsInAir = false; UPROPERTY(Transient) TObjectPtr OwnerCharacter; // 只缓存一次，不要每帧 Cast virtual void NativeInitializeAnimation() override { OwnerCharacter = Cast(TryGetPawnOwner()); } // 游戏线程：只做“读取 + 拷贝”，不做重计算 virtual void NativeUpdateAnimation(float DeltaSeconds) override { if (!OwnerCharacter) return; Velocity = OwnerCharacter->GetVelocity(); ActorRot = OwnerCharacter->GetActorRotation(); bIsInAir = OwnerCharacter->GetCharacterMovement()->IsFalling(); } // 工作线程：只用上面拷好的值算派生量 virtual void NativeThreadSafeUpdateAnimation(float DeltaSeconds) override { GroundSpeed = FVector(Velocity.X, Velocity.Y, 0.f).Size(); Direction = UKismetAnimationLibrary::CalculateDirection(Velocity, ActorRot); } private: FVector Velocity = FVector::ZeroVector; FRotator ActorRot = FRotator::ZeroRotator; };
面试注意：EventGraph 里的性能坑
  • 每帧 Cast：Try Get Pawn Owner → Cast To Character 放在 Update 事件里，每帧每个角色都做一次。应在 Initialize 时缓存。
  • 蓝图 VM 开销：EventGraph 里的每个节点都走蓝图虚拟机，几十个角色乘起来就是游戏线程的大头。能挪到线程安全函数或 C++ 的就挪。
  • 在动画蓝图里做射线检测、生成 Actor：这些属于游戏逻辑，应该在角色或组件里做，动画蓝图只读结果。

6.4 Fast Path、Property Access 与线程安全函数

机制解决什么怎么用
Fast PathAnimGraph 节点引脚的值如果来自蓝图逻辑，每次 Update 都要跑一段蓝图字节码引脚直接连成员变量（或只做 Break Struct、取反 Bool 等简单操作），编译器把它变成直接内存拷贝，节点右上角出现闪电图标；否则编译时给出性能警告
Property Access工作线程里需要读游戏线程对象的属性用属性访问节点 / 绑定写路径（如 TryGetPawnOwner.CharacterMovement.Velocity），引擎在安全时机批量拷贝
Thread Safe 函数自定义计算放到工作线程函数标记为 Thread Safe，编译器检查里面不调用非线程安全的东西；可在 Blueprint Thread Safe Update Animation 或 Anim Node Functions 里调用
Anim Node Functions节点级的初始化 / 更新逻辑节点的 On Initial Update / On Become Relevant / On Update 绑定线程安全函数，例如进入状态时重置播放时间

6.5 一个动画节点的一生

USTRUCT(BlueprintInternalUseOnly) struct FAnimNode_SpineLean : public FAnimNode_Base { GENERATED_BODY() UPROPERTY(EditAnywhere, Category = Links) FPoseLink Source; // 输入姿势 UPROPERTY(EditAnywhere, Category = Settings) FBoneReference SpineBone; // 按名字引用骨骼，运行时解析成 Compact 下标 UPROPERTY(EditAnywhere, Category = Settings, meta = (PinShownByDefault)) float LeanDegrees = 0.f; // 暴露成引脚，最好用 Fast Path 绑定变量 virtual void Initialize_AnyThread(const FAnimationInitializeContext& Context) override { FAnimNode_Base::Initialize_AnyThread(Context); Source.Initialize(Context); } virtual void CacheBones_AnyThread(const FAnimationCacheBonesContext& Context) override { Source.CacheBones(Context); SpineBone.Initialize(Context.AnimInstanceProxy->GetRequiredBones()); // LOD 变化时会重新调用 } virtual void Update_AnyThread(const FAnimationUpdateContext& Context) override { GetEvaluateGraphExposedInputs().Execute(Context); // 刷新引脚绑定的值 Source.Update(Context); // 继续往下传 } virtual void Evaluate_AnyThread(FPoseContext& Output) override { Source.Evaluate(Output); // 先拿到输入姿势 const FCompactPoseBoneIndex Idx = SpineBone.GetCompactPoseIndex(Output.Pose.GetBoneContainer()); if (Idx.IsValid()) // 当前 LOD 可能没有这根骨骼 { FTransform& T = Output.Pose[Idx]; const FQuat Lean(FVector::ForwardVector, FMath::DegreesToRadians(LeanDegrees)); T.SetRotation((Lean * T.GetRotation()).GetNormalized()); } } }; // 编辑器里还需要一个 UAnimGraphNode_SpineLean（放在 Editor 模块）提供节点外观和标题
面试注意：自定义节点的三条铁律
  1. 函数名带 _AnyThread 的都可能在工作线程跑：不能访问 UObject 的可变状态、不能 Spawn、不能调非线程安全的引擎函数。
  2. 必须把调用往下传：Initialize / CacheBones / Update / Evaluate 都要调用输入 FPoseLink 的对应函数，否则子图不会运行。
  3. 骨骼下标只能用 Compact Pose Index，并在 CacheBones 里重新解析（第 1 章）。

6.6 拆分动画蓝图：Linked Anim Graph 与 Anim Layer

一个角色要支持十几种武器时，把所有逻辑塞进一个动画蓝图会变得不可维护。UE 提供两种拆分方式：

  • Linked Anim Graph：在 AnimGraph 里放一个节点，运行另一个动画蓝图的 AnimGraph，像调用子函数一样。
  • Anim Layer + Anim Layer Interface：主动画蓝图只定义“接口”（例如 FullBody_Idle、UpperBody_Aim 这些层），具体实现放在各个武器的动画蓝图里，运行时用 LinkAnimClassLayers 切换。Lyra 的“每种武器一个动画层蓝图”就是这么做的。
  • Animation Blueprint Template：不绑定具体 Skeleton 的模板，可以被不同角色复用，具体的动画资产作为变量传入。
游戏客户端实战：切换武器层时的注意点

链接新的动画层会让新子图“重新变得相关”，序列时间和状态机状态都会重置，可能出现一帧的姿势跳变。通常在切换时配合一次惯性化（Inertialization）请求，并且把运动同步组放在主蓝图里，让新层的循环动画接上原来的脚步相位。

本章速记
  • 动画蓝图 = UAnimInstance 子类；EventGraph 在游戏线程读状态写变量，AnimGraph 可在工作线程更新与求值。
  • 调用链：TickComponent → TickAnimation（UpdateAnimation，NativeUpdate）→ RefreshBoneTransforms 派发 → 工作线程 Update + Evaluate + 组件空间 → Complete（派发 Notify、通知渲染）。
  • Proxy 隔离数据；UE5 用 Property Access + Thread Safe Update 取代 EventGraph；Fast Path 让引脚绑定免跑蓝图 VM。
  • 节点四件套：Initialize / CacheBones（解析骨骼）/ Update（时间、权重，自顶向下）/ Evaluate（姿势，自底向上）；记得往下传。
  • 大型角色用 Linked Anim Graph / Anim Layer 拆分，切层时注意状态重置。
自测：关闭“多线程动画更新”后，动画还会在工作线程上算吗？

Update（包括 AnimGraph 节点的 Update_AnyThread）会回到游戏线程执行；但 Evaluate 通常仍可以并行（由 a.ParallelAnimEvaluation 等控制），因为求值只依赖 Update 之后的节点数据。两者是分开的开关。调试时常把并行关掉，以便在游戏线程上断点和复现问题。

自测：为什么普通 Notify 不在工作线程直接触发？

Notify 的回调通常会做游戏逻辑：播声音、生成特效、修改 Actor 状态、调用蓝图函数，这些都必须在游戏线程执行。所以求值阶段只记录“本帧扫过了哪些 Notify”，Complete 阶段在游戏线程统一派发。代价是触发时间比姿势晚一点；需要精确时机的用蒙太奇的 Branching Point。
