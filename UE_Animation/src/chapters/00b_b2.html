BASICS · B2

位置、旋转、缩放与坐标空间

“这根骨头在哪”这个问题，答案取决于“相对谁”。弄清变换和空间，FK、蒙皮矩阵、IK 都只是同一件事的不同用法。

本章目标
  • 知道一个变换（Transform）由哪三部分组成，作用到点上的先后顺序
  • 分清局部空间、组件空间、世界空间，会用“手在哪”的例子解释
  • 手算一遍两节手臂的 FK，理解“父子级联”
  • 知道矩阵是什么、乘法顺序为什么有两种约定，UE 里 FTransform 和 FQuat 的顺序为什么相反
  • 用一个数值例子讲清“参考姿势的逆”在蒙皮里做了什么

B2.1 一个变换 = 缩放 + 旋转 + 平移

描述一根骨头“怎么摆”，需要回答三个问题：多大（缩放 Scale）、朝哪（旋转 Rotation）、在哪（平移 Translation）。合起来常简称 TRS。UE 的 FTransform 就是这三样：FVector Scale3D、FQuat Rotation、FVector Translation。

把变换作用到一个点上，顺序是先缩放、再旋转、最后平移（FTransform::TransformPosition）。顺序不能随便换：

点 (1, 0, 0)第一步第二步结果
先绕 Z 转 90°，再平移 (10, 0, 0)转完：(0, 1, 0)平移：(10, 1, 0)(10, 1, 0)
先平移 (10, 0, 0)，再绕 Z 转 90°平移完：(11, 0, 0)转完：(0, 11, 0)(0, 11, 0)

直观理解：先平移再旋转，旋转是绕原点转的，点已经被推远了，于是转出一个大圈。骨骼的变换总是“先在自己的位置上转好，再放到该放的地方”，所以是先旋转后平移。

B2.2 坐标空间：同一只手，三种说法

问“你的右手在哪？”，可以有三种回答，都对，只是参照物不同：

空间参照物为什么需要它
局部空间（Local / Bone Space）父骨骼动画数据存这个：同一条“挥手”动画，角色站哪都能用；混合大多在这里做
组件空间（Component / Mesh Space）角色自己的原点（SkeletalMeshComponent）“手离地多高”“头朝哪”这类问题要在这里回答：IK、瞄准、蒙皮矩阵
世界空间（World Space）整个关卡的原点和别的物体打交道：武器挂点、射线检测、脚下的地面高度

B2.3 父子级联：FK 手算一遍

两节手臂：肩膀转 30°，上臂长 30；肘部在此基础上再转 45°，前臂长 28。手在哪？（二维、单位 cm，数字来自实测 E11(g)）

三维里道理一样，只是“角度相加”变成了“旋转相乘”（三维旋转不能简单地把角度加起来，B3 会讲为什么），“沿朝向走 L”变成了“用父亲的旋转转一下自己的偏移，再加上父亲的位置”。这正是第 1 章那一行代码：

for (int32 i = 1; i < NumBones; ++i) ComponentSpace[i] = LocalSpace[i] * ComponentSpace[Parent[i]]; // 展开看：位置 = 父旋转(父缩放 × 自己的局部位置) + 父位置；旋转 = 父旋转 · 自己的局部旋转

B2.4 矩阵是什么，乘法顺序为什么有两种写法

矩阵就是一张数字表。一个 4×4 矩阵能把“缩放 + 旋转 + 平移”打包在一起，拿一个点去乘它，三件事一次做完；两个矩阵相乘，就是把两次变换合成一次。GPU 喜欢矩阵，因为“乘一个矩阵”是它最擅长的运算。

麻烦在于写法约定：同样是“先做 A 再做 B”，

约定“先 A 后 B”写作谁在用
行向量（点写在左边：v · M）A * BUE 的 FMatrix、FTransform，DirectX 传统写法
列向量（点写在右边：M · v）B · A大多数数学课本、OpenGL / GLM、本书 demo 里的 3×3 矩阵
UE 的 FQuatB * A四元数按数学惯例，和 FTransform 正好相反（B3.7）
面试注意：手写变换公式前，先说约定

“蒙皮矩阵是 InvBind × Current 还是 Current × InvBind？”两种写法在各自的约定下都对。面试时先说一句“按 UE 的 FTransform 约定，A*B 表示先 A 后 B”，再写公式，就不会被追问绕晕。最常见的翻车是在 UE 里混用 FTransform 和 FQuat 的乘法：前者先左后右，后者先右后左。

B2.5 逆变换，以及“参考姿势的逆”在做什么

逆变换就是“撤销”：一个变换把点从 A 处搬到 B 处，它的逆就把点从 B 搬回 A。最常见的两个用法：

  • 组件空间 → 局部空间：IK 改完了手在组件空间的位置，要转回“相对前臂”的局部数据，就乘一次父骨骼组件变换的逆。
  • 蒙皮里的“参考姿势的逆”（也叫逆绑定矩阵）：见下图。

把②③合成一个矩阵，就是第 1 章的蒙皮矩阵：SkinMatrix = InvRefPose × CurrentComponent（UE 约定，先逆绑定再当前）。CPU 每帧为每根骨头算一个，上传给显卡；显卡对每个顶点按权重把几根骨头的结果加起来（B1-1 里肘部 0.5/0.5 的顶点就是两个结果各取一半）。

本章速记
  • 变换 = 缩放 + 旋转 + 平移；作用到点上：先缩放、再旋转、后平移，顺序换了结果就变。
  • 局部 = 相对父骨骼（动画存这个）；组件 = 相对角色根（IK、蒙皮）；世界 = 相对地图（挂件、射线）。
  • FK：从根往下逐层累积；手算例子：肩 30°、肘 +45° → 手在 (33.23, 42.05)。
  • 矩阵 = 打包的变换，相乘 = 合成；UE：FTransform 的 A*B 先 A 后 B，FQuat 的 A*B 先 B 后 A。
  • 逆 = 撤销；参考姿势的逆把顶点变成“相对骨头的位置”，再乘当前变换放回去 = 蒙皮矩阵。
自测：角色整体向前跑了 10 米，局部空间、组件空间、世界空间里手的坐标分别变不变？

局部空间和组件空间都不变（相对父骨骼、相对角色根都没变），只有世界空间的坐标变了。这也是为什么动画数据存局部空间、蒙皮在组件空间做：角色在世界里怎么移动都不影响动画计算，最后乘一个“组件到世界”的变换就行。

自测：为什么不直接用顶点的绝对坐标乘以骨头的当前变换，还要先乘参考姿势的逆？

因为骨头的当前变换描述的是“骨头从它的原点出发怎么摆”，它只能正确地搬动“相对骨头”的坐标。顶点的绝对坐标是相对模型原点的，直接乘会把顶点绕模型原点转、再额外平移一次，模型会被甩飞。先乘参考姿势的逆，把顶点换成相对骨头的坐标，再乘当前变换，才是“粘在骨头上一起动”。
